# RimWorld 完整地图生成步骤（含 RimExodus 注入点）

本文档记录 RimWorld 地图生成的完整 genStep 执行顺序，并标注 RimExodus 在哪里插入了什么。
目的是让后续开发快速恢复"原版做了什么、我们在哪一步介入"的上下文。

> **排序规则**（`MapGenerator.cs:MapGeneratorPostInit`）：`orderby def.order, def.index`。
> genStep 按 `GenStepDef.order` 升序执行，order 相同时按 `Def.index`（加载顺序）决胜。
> **MapGeneratorDef 里 XML `<li>` 列表顺序不影响执行顺序**——只决定包含哪些 GenStepDef。

## 注入目标

RimExodus 通过 `1.6/Patches/MapGeneration.xml` 的 `PatchOperationAdd`，把四个自定义 GenStepDef
追加到三个 `MapGeneratorDef` 的 `genSteps` 列表：

- **`Base_Player`** — 玩家家园（锚点 A）+ 邻接地块地图（B/C）复用此链。
- **`Base_Faction`** — 派系基地。
- **`Encounter`** — 遭遇/任务地点。

三者都继承自 `MapCommonBase`（抽象父类），共用大部分 genStep。

## 关键时序约束

1. **snapshot 备份在 391（2026-08 反转旧"必须在 1400"结论）**：备份须在全部**基础地形**写入步骤（Terrain 210 / Coast 220 / CoastalEdgeFill 230 / Roads 390）之后——这是 391 下限的硬约束。order 400+ 的地板写入（Settlement BaseGen `SymbolResolver_FloorFill` / Harbor 桥 / ArcheanTrees）已被选址 patch（ScatterEdgeMargin=20 / ClearRectMargin=10）拦在接缝带之外，快照的游戏逻辑消费面仅剩 void 侧外条带（`SeamStripData.CaptureAndStore`），B∪T 读活数据非快照；残余缺口（贴附矩形/降落平台/Harbor 桥溢出）处行为有变化，记观察项（见下节）。Plants(900)/Animals(1200)/Snow(1150) 不写 topGrid。
2. **void 铺设在 391 的原因（勿回退到 1400）**：让 Settlement(400) 及之后全部步骤在最终地形上工作——Plants 的 fertility 门（FertilityGrid 实时算，void=0）、Animals(1200)/威胁步骤(1600) 的 Standable 门天然跳过 void 格。**前提**：铺 void 直写 topGrid 后必须即调 `map.pathing.RecalculateAllPerceivedPathCosts()`——Walkable/Standable 读 PathGrid 缓存数组而非 terrainGrid（GenGrid.Walkable → pathGrid.WalkableFast），不刷新则动物照落 void（2026-08 实测历史 bug：旧序 1400 直写后等 FinalizeInit 才重算，`EvacuatePawnsOnCells` 的 FindNearestWalkable 读旧缓存 + 径向首候选即自身格 → 撤离原地空转）。
3. **SeamOverride 必须在 void(391) 之后、Settlement(400) 与 Fog(1500) 之前**：读两端数据 + 写覆写后的地形；混合同样直写 topGrid，结束后同样刷新 pathGrid（否则带格混出水后 Standable 仍判可走，pawn/植物落水上）。Fog 基于最终地形揭雾。
4. **道路 patch 在 390 靠多边形几何算锚点**：传送点 1490 才铺设（原为整条 genStep 链之后的 onComplete），390 时不能查 `SeamlessEdgeCells`，仍用纯多边形几何。
5. **传送点必须在 Fog(1500) 之前铺（EnterSpots=1490，勿回退到 onComplete）**：Fog 的 `UnfogMapFromEdge` fallback 与选址兜底依赖 `CanReachMapEdge`/`TryFindRandomEdgeCellWith` 的接缝语义 patch，patch 以 `HasSeamEdge`（listerThings 传送点实况）为门——点在 onComplete 才铺时这些判定在生成期走原版方形边缘语义，裁切图上恒不可达 → 零揭雾整图全雾（2026-08 偶发全雾成因之一）。铺在 1490 而非更早（392）：400-1490 期间保持与旧序一致（patch 未生效）零回归，且 Plants/Animals 生成时传送圈格上无 thing 干扰。
6. **PlayerStartSpot 是进程级 static，跨图生成必须重置**：`IncrementalMapGenerator.Start` 已补 `PlayerStartSpot = Invalid; rootsToUnfog.Clear()`（对齐原版 `MapGenerator.GenerateMap` 开头，`ClearWorkingData` 本身不动这两个字段）——不重置则上一张图的坐标残留，850 的"已设跳过"守卫跳过本图选址、Fog 用他图坐标揭雾（落 MakeFog 建筑时零揭雾，2026-08 偶发全雾成因之二）。392 末的预设（已裁切 + 未设守卫）另消除选址 fallback 的每图红字。
7. **MutatorFinal(1600) 对地形的影响**：多数 mutator 不写 topGrid，但 AncientUplink/InsectMegahive 的 `GeneratePostFog` 会 `SetTerrain`——这些任务地块上 392 的覆写可能被 1600 覆盖（已知小瑕疵，罕见场景）。void 格上的此类写入被 `Patches_TerrainGrid` 守卫拦截（391 提前后该守卫在生成期实际生效）。

## 2026-08 反转：把 SeamlessTile/SeamOverride 从 1400/1410 提前到 391/392

曾否决过提前到 391-399（旧否决理由：①391 备份 snapshot 会漏掉 400+ 的 BaseGen 地板/Harbor 桥写入，卷积用旧地形；②SeamOverride 在 392-399 跑，之后 Settlement(400) 的 FloorFill 会盖掉卷积结果、SyncRockBuilding 岩石 spawn 干扰选址）。**2026-08 反转，动因与重新评估**：

- **动因**：实测动物站 void——旧序下 Animals(1200) 先在将来 void 格上合法生成、靠撤离兜底，而撤离被"直写 topGrid → pathGrid 过期"击败（见约束 2）。根治 = 让动物生成时 void 已在且可通行性缓存正确。
- **旧否决理由①重评**：快照消费面经查只有 void 侧外条带（B∪T 读活数据）；选址 patch（margin 20/10）今天已把地板写入拦在带外——旧否决写下时选址 patch 体系尚未成型。残余：贴附矩形/降落平台/Harbor 桥若溢出到带/外条带，行为有变化（旧序：写入进快照/被混合覆盖；新序：不进快照/覆盖混合），频率窄，观察项。
- **旧否决理由②重评**：FloorFill 盖混合只发生在残余缺口处（正常选址不进带）；岩石 spawn 干扰选址不成立（锚点 margin 20 >> 带深 ~10）。void 格上的地板写入转而被 `Patches_TerrainGrid` 守卫拦截（预期收益）。
- **新增观察项**：①污染地块(890) 的污染变体现在发生在混合之后，带格与对端可能不一致（旧序为相反方向的不一致）；②`completelyIgnoreFertility` 植物不受肥力门约束、可能漏进 void 格（旧序靠 1400 事后清理兜住，新序无此清理）；③MapPreview 预览链的 order 变化回归。
