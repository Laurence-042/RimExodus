# RimWorld 完整地图生成步骤（含 RimExodus 注入点）

本文档记录 RimWorld 地图生成的完整 genStep 执行顺序，并标注 RimExodus 在哪里插入了什么。
目的是让后续开发快速恢复"原版做了什么、我们在哪一步介入"的上下文。

> **排序规则**（`MapGenerator.cs:MapGeneratorPostInit`）：`orderby def.order, def.index`。
> genStep 按 `GenStepDef.order` 升序执行，order 相同时按 `Def.index`（加载顺序）决胜。
> **MapGeneratorDef 里 XML `<li>` 列表顺序不影响执行顺序**——只决定包含哪些 GenStepDef。

## 注入目标

RimExodus 通过 `1.6/Patches/MapGeneration.xml` 的 `PatchOperationAdd`，把四个自定义 GenStepDef
追加到**全部表面层 `MapGeneratorDef`** 的 `genSteps` 列表（2026-08 通配化，原为点名
`Base_Player`/`Base_Faction`/`Encounter` 三个；通配覆盖 EscapeShip/Archonexus 周期/AncientStockpile/
InsectLair 等显式设置名单外 mapGenerator 的 def，以及 mod 自定义 MapGeneratorDef——Patch 在全部
mod Defs 加载后跑，后加载者同样被注入）。核心命中：

- **`Base_Player`** — 玩家家园（锚点 A）+ 邻接地块地图（B/C）复用此链。
- **`Base_Faction`** — 派系基地。
- **`Encounter`** — 遭遇/任务地点（绝大多数 Site def 不设 mapGenerator，`MapParent.MapGeneratorDef`
  回落默认此链）。

三者都继承自 `MapCommonBase`（抽象父类），共用大部分 genStep。

**通配排除谓词（勿删）**：① xpath 带 `[defName]` 存在性——`MapCommonBase` 是无 defName 的 Abstract
基类但有 genSteps 节点，通配命中它会使注入经 XML 继承（Patch 先于继承解析跑）传播给全部子类，
Base_Player/Encounter 等会**双份注入**（389/392 重复跑）；② 空间层家族显式排除
（Space/Asteroid/AsteroidBasic/OrbitalItemStash/OrbitalRelay/Mechhive/SettlementPlatform——后三者同
`ParentName="SpaceMapGenerator"`）：genStep 内部 `GetMapWorldTile` 守卫对空间层/口袋图返回 -1 早退，
注入本无害，但语义上空间图不属于表面无缝网格。无 `<genSteps>` 子节点的 def（如 SpacePocket 纯继承）
不被 xpath 命中、天然跳过。

## 关键时序约束

1. **snapshot 备份在 389（2026-08 反转旧"必须在 1400"结论；2026-08-30 从 391 再提前到 Roads 前）**：备份须在全部**基础地形**写入步骤（Terrain 210 / Coast 220 / CoastalEdgeFill 230）之后——这是 389 下限的硬约束；Roads(390) 虽在其后，但道路写不进 void 格（TerrainGrid 守卫）、外条带快照只覆盖 void 侧格，不受影响。order 400+ 的地板写入（Settlement BaseGen `SymbolResolver_FloorFill` / Harbor 桥 / ArcheanTrees）已被选址 patch（ScatterEdgeMargin=20 / ClearRectMargin=10）拦在接缝带之外，快照的游戏逻辑消费面仅剩 void 侧外条带（`SeamStripData.CaptureAndStore`），B∪T 读活数据非快照；残余缺口（贴附矩形/降落平台/Harbor 桥溢出）处行为有变化，记观察项（见下节）。Plants(900)/Animals(1200)/Snow(1150) 不写 topGrid。
2. **void 铺设在 389 的原因（勿回退到 1400）**：让 Settlement(400) 及之后全部步骤在最终地形上工作——Plants 的 fertility 门（FertilityGrid 实时算，void=0）、Animals(1200)/威胁步骤(1600) 的 Standable 门天然跳过 void 格。**前提**：铺 void 直写 topGrid 后必须即调 `map.pathing.RecalculateAllPerceivedPathCosts()`——Walkable/Standable 读 PathGrid 缓存数组而非 terrainGrid（GenGrid.Walkable → pathGrid.WalkableFast），不刷新则动物照落 void（2026-08 实测历史 bug：旧序 1400 直写后等 FinalizeInit 才重算，`EvacuatePawnsOnCells` 的 FindNearestWalkable 读旧缓存 + 径向首候选即自身格 → 撤离原地空转）。
3. **SeamOverride 必须在 void(389) 之后、Settlement(400) 与 Fog(1500) 之前**：读两端数据 + 写覆写后的地形；混合同样直写 topGrid，结束后同样刷新 pathGrid（否则带格混出水后 Standable 仍判可走，pawn/植物落水上）。Fog 基于最终地形揭雾。
4. **道路 patch 在 390 靠多边形几何算锚点**：传送点 1490 才铺设（原为整条 genStep 链之后的 onComplete），390 时不能查 `SeamlessEdgeCells`，仍用纯多边形几何。
5. **传送点必须在 Fog(1500) 之前铺（EnterSpots=1490，勿回退到 onComplete）**：Fog 的 `UnfogMapFromEdge` fallback 与选址兜底依赖 `CanReachMapEdge`/`TryFindRandomEdgeCellWith` 的接缝语义 patch，patch 以 `HasSeamEdge`（listerThings 传送点实况）为门——点在 onComplete 才铺时这些判定在生成期走原版方形边缘语义，裁切图上恒不可达 → 零揭雾整图全雾（2026-08 偶发全雾成因之一）。铺在 1490 而非更早（392）：400-1490 期间保持与旧序一致（patch 未生效）零回归，且 Plants/Animals 生成时传送圈格上无 thing 干扰。
6. **PlayerStartSpot 是进程级 static，跨图生成必须重置**：`IncrementalMapGenerator.Start` 已补 `PlayerStartSpot = Invalid; rootsToUnfog.Clear()`（对齐原版 `MapGenerator.GenerateMap` 开头，`ClearWorkingData` 本身不动这两个字段）——不重置则上一张图的坐标残留，850 的"已设跳过"守卫跳过本图选址、Fog 用他图坐标揭雾（落 MakeFog 建筑时零揭雾，2026-08 偶发全雾成因之二）。392 末的预设（已裁切 + 未设守卫）另消除选址 fallback 的每图红字。
7. **MutatorFinal(1600) 对地形的影响**：多数 mutator 不写 topGrid，但 AncientUplink/InsectMegahive 的 `GeneratePostFog` 会 `SetTerrain`——这些任务地块上 392 的覆写可能被 1600 覆盖（已知小瑕疵，罕见场景）。void 格上的此类写入被 `Patches_TerrainGrid` 守卫拦截（389 提前后该守卫在生成期实际生效）。
8. **读档后快照缺失的精简重生成（2026-08-31，`SeamlessSnapshotRegenerator`）**：读档后（旧档或 `serializeBaseSnapshots` 关闭）源图内存无基础三层快照 → `GenerateTileMap` 入口（三分支之前，POI 原生/同步逃生/分帧增量统一覆盖）调 `EnsureSourceSnapshot`：在一张**临时 Map**（同步段内临时加入 `Find.Maps`——`Thing.SpawnSetup` 的存在性检查是无条件 `IndexOf < 0`，非登记图上 RocksFromGrid 的 GenSpawn 必失败；加/移都在同一次 tick 回调内，不会被 tick/渲染/存档看见，销毁 = `DisposeTempMap` 照抄 MapPreview 的 DisposeMap 卫生——全局注册表摘除[RemoveAllFromMap / sustainer.EndAllInMap，防 mod 的 <389 步骤 spawn 的带 tick 物进入全局 tick 表] + GlowGrid 静态光照池等共享资源归还 + 纯 `Find.Maps.Remove`；mapDrawer 跳过（临时图从不跑 mesh 重建，sections 恒 null 且私有判不了——`DeinitAndRemoveMap` 对其 NRE 即此，且会把临时图借用的源图 parent 误通知））上同步重跑 order < 389 的 genStep 子集（= 基础快照在 389 备份时点的地形/岩体/屋顶状态），提取三层回填源图 + `SeamStripData.CaptureAndStore` 重建条带快照（幂等覆盖：B∪T 取当前实况、外条带取重生成原生值）。种子/RockNoises/GL shim/per-step Rand+ProgramState 全复刻 `IncrementalMapGenerator`——种子 = HashCombine(世界种子, tile)，per-step seedPart 计数只依赖前序步（子集只删 ≥389 的后续步），地形与原图确定性一致。互斥：全程持有 `MapGenerator.mapBeingGenerated`；已有分帧增量/预览在飞则本次跳过（邻图生成本身照常，该方向混合退回既有静默跳过，下次触发生成再补）。设置 `regenerateMissingSnapshots`（默认开）总门控。mapGeneratorDef 取源图 `generatorDef`（生成时记录，缺失回落 Base_Player）——地形/岩体步骤 biome 驱动跨 def 一致，def 差异步骤均在 389 之后被排除。
