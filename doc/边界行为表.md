# 边界行为表（传送点 / 接缝带行为规范）

本文档定义 RimExodus 中"pawn 与接缝传送点交互"的完整行为规范：什么主体、在什么移动状态下、踩到/走到传送点格或边界带时应该发生什么。目的：①统一实现判据；②区分"原版原生行为"与"mod patch 强加行为"，控制 patch 数量。

**状态：草案（填值为讨论结论 + 合理估计，待用户在表上直接修改定稿）。** 原版机制结论均经反编译源码核查（`references/RimWorldDecompiled`），附路径:行号。

## 一、原版机制事实（已核查）

### 1.1 `exitMapOnArrival` 的全部设置点（全库仅 5 处赋值）

| # | 设置点 | 触发条件 | 来源 |
|---|---|---|---|
| 1 | `FloatMenuOptionProvider_DraftedMove.PawnGotoAction` | **玩家征召**右键/拖框 goto，且原始点击格（`clickCell`，非 gotoLoc）是 exit cell 时设为 `!pawn.IsColonyMech`（殖民地机械族例外） | `RimWorld/FloatMenuOptionProvider_DraftedMove.cs:106-110` |
| 2 | `JobGiver_ExitMap.TryGiveJob` | 所有"撤离 duty"的统一出口：构造 `Goto` + `exitMapOnArrival=true` + `failIfCantJoinOrCreateCaravan` | `Verse.AI/JobGiver_ExitMap.cs:79-84` |
| 3 | `JobGiver_PrisonerEscape` | 囚犯越狱：区域毗邻地图边缘（或 25 区域 BFS 内经自由通行的门可达边缘） | `RimWorld/JobGiver_PrisonerEscape.cs:15-22,26-57` |
| 4 | `GenGuest.GuestRelease` | 俘虏/访客被释放后离场 | `RimWorld/GenGuest.cs:41-79`（赋值 :77） |
| 5 | `Pawn_MindState.StartFleeingBecauseOfPawnAction` | **无阵营野生动物**恐慌逃跑、方向背离地图中心、50% 概率：`Flee` + flag | `Verse.AI/Pawn_MindState.cs:810-830`（赋值 :828） |

除上述外全库无其他赋值点（已 grep 全量核实）。

### 1.2 检查点（谁在消费这个 flag）

- `JobDriver_Goto`：pre-tick `exitMapOnArrival && IsExitCell(pos)` → `TryExitMap()`；到达时额外有 `OnEdge(map)` 兜底 → `pawn.ExitMap(allowedToJoinOrCreateCaravan: true, ...)`（`Verse.AI/JobDriver_Goto.cs:22-27,58,69-81`）。
- `JobDriver_Flee`：同构检查（`RimWorld/JobDriver_Flee.cs:33-48,54-57`），无条件组队/入队。
- `JobDriver_TakeAndExitMap`：**不读 flag**，tickAction 查 pawn 所在格 `IsExitCell`、到达时 `OnEdge || IsExitCell` 即 `ExitMap(allowedToJoinOrCreateCaravan:true)`（TargetB 只是引导目标；`RimWorld/JobDriver_TakeAndExitMap.cs:29-46`）。
- 组队链：`Pawn.ExitMap` → `CaravanExitMapUtility.CanExitMapAndJoinOrCreateCaravanNow`（前置：Spawned 且 `MapUsesExitGrid`；殖民者直接 true；非殖民者只能**加入现有**远行队，`CaravanExitMapUtility.cs:157-170`）→ `ExitMapAndJoinOrCreateCaravan`（加入或建队，建队时 `autoJoinable=true` 并仅唤醒可入队、未倒地、未征召的 pawn `CheckForJobOverride`，`:106-140`）。

### 1.5 RimExodus 现状几何事实（mod 侧核查）

- **传送点带 = 整条接缝带**：接缝带 = 距最近 void 格切比雪夫距离 ∈ {1..2} 的非 void 格（`ComputeVoidBand(map, SeamOverlap=2)`），每个格都铺一个 `RimExodus_SeamlessEnterSpot`（`SeamlessEnterSpotPlacer.cs:62-101`，仅 `wt<0` 擦边格例外）。因此"接缝带内非传送点格"基本不存在。
- **exit cell = 整条传送点带**：`Patches_ExitMapGrid.cs:36-82` 跳过原版 Rebuild、只把传送点格标为 exit cell——因传送点铺满接缝带，实际等价于整条接缝带都是出口格。
- **预加载边界带是另一条更宽的带**：宽 15（`borderPreloadDistance`，`RimWorld RimExodusSettings.cs:14`），包含接缝带 + 向内 13 格；"边界带内、传送点带外"（距 void 3-15 格）的格真实存在。速查表由同源 `ComputeVoidBand(map, 15)` 构建（`SeamlessBorderLookup.cs:113-139`），故现状 goto 到**传送点格也会触发预加载**（带宽 15 包含带宽 2 的全部格）——这正是待办②要排除的。

### 1.3 关键否定性事实（决定行为表结构）

- **原版不存在"未征召玩家 goto"**：`FloatMenuOptionProvider_DraftedMove` 是唯一构造玩家 Goto 菜单的 provider，且 `Undrafted => false`（`:14-15`）；`MultiPawnGotoController` 拖框也转调它（`RimWorld/MultiPawnGotoController.cs:155`）。因此"未征召殖民者踩传送点"只可能来自闲逛/工作/逃跑/跟随等 AI job——全部不带 flag。
- **玩家指令 job 统一带 `playerForced`**：`PawnGotoAction` 构造 job 时不显式设置，但 `Pawn_JobTracker.TryTakeOrderedJob` 入口统一 `job.playerForced = true`（`Verse.AI/Pawn_JobTracker.cs:897`）——征召 goto / 未征召玩家命令 / 拖框全部覆盖。RimExodus 现有预加载分支（`Patch_Pawn_JobTracker_StartJob` 查 playerForced）因此对玩家 goto 全量生效。
- **闲逛 job 是 `GotoWander` 且无 flag**：`JobGiver_Wander.cs:74-93`；目标格筛选（`RCellFinder.RandomWanderDestFor`，`RimWorld/RCellFinder.cs:255-300`）**不排除边缘/出口格**——动物和未征召 pawn 闲逛可以停在传送点格上，但原版不会因此离图。
- **跟随 job 无 flag**：`JobDriver_Follow`/`JobDriver_FollowClose` 均不含 flag。

### 1.4 各主体的离场路径（全部经 JobGiver_ExitMap 族）

撤离 duty 经 `LordToil_ExitMap`（`ExitDuty => DutyDefOf.ExitMapBest`）分配，最终都变成 `exitMapOnArrival=true` 的 Goto：

| 主体 | 离场路径 | 来源 |
|---|---|---|
| 敌方袭击者撤退 | `LordJob_AssaultColony` 等 → `LordToil_ExitMap` | `Verse.AI.Group/LordJob_AssaultColony.cs` |
| 盟友增援撤退 | ImmediateAttackFriendly → 非敌对路径 `LordJob_AssistColony`（图含两个 `LordToil_ExitMap`，已核实） | `RimWorld/RaidStrategyWorker_ImmediateAttack.cs:9-22`、`RimWorld/LordJob_AssistColony.cs:30-33` |
| 访客离场 | `LordJob_VisitColony` → `LordJob_TravelAndExit` → `LordToil_ExitMap` | `RimWorld/LordJob_VisitColony.cs` |
| 路过旅行者穿图 | `IncidentWorker_TravelerGroup` → `LordJob_TravelAndExit`（先走到穿图终点再撤离） | `RimWorld/IncidentWorker_TravelerGroup.cs:44-46`、`Verse.AI.Group/LordJob_TravelAndExit.cs:17-27` |
| 派系商队离场 | `LordJob_TradeWithColony` → `LordToil_ExitMapAndEscortCarriers` / `LordToil_ExitMap` | `RimWorld/LordJob_TradeWithColony.cs` |
| 敌方 mech 撤退 | 同袭击者（`LordJob_MechanoidsDefend`、GameEnding 转换） | `Verse.AI.Group/LordJob_MechanoidsDefend.cs` |

| 野性动物逃跑 | `Pawn_MindState`（50% 概率 Flee+flag） | 见 1.1#5 |
| **定居点 NPC** | **不离图**（`LordJob_DefendBase` 无 ExitMap toil） | `RimWorld/LordJob_DefendBase.cs` |

不经 flag 的直接 `ExitMap`（均 `allowedToJoinOrCreateCaravan:false`）：远行队出发按钮（`CaravanFormingUtility.ExitMapAndCreateCaravan` 流程）、Farskip、穿梭机/运输舱——与边界行走无关。

## 二、行为表

原则：

- 预加载原则上只能由玩家操作触发
- 在NPC在原版中会尝试从边缘撤离的场景中，如果对端地图未加载，NPC会正常撤离，如果对端地图已加载，NPC会进入对端地图后继续撤离

列说明：
- **flag** = 该移动场景下 job 的 `exitMapOnArrival` 预期值（注明原生来源）。
- **跨图登记** = RimExodus 桥接标记（`SeamlessCrossMapPendingDestinations` / 计划中的传送许可标记）。
- **踩点(已加载)** = 对端地图已加载（`hasArrival==true`）时 pawn 踩到传送点格的行为。
- **踩点(未生成)** = 对端未生成/生成中时 pawn 到达传送点格的行为。
- **预加载** = 该指令是否应触发邻居地图预加载。
- **原版行为** = 无 RimExodus 时此场景的结果（exit cell 为原版方形边缘带）。
- **patch 依赖**：`无需`（原版即如此）/`现有`（依赖现有 patch）/`收紧`（现状会偏离，需改）/`新增`。

## 三、传送判定优先级（实现判据）

`TryTriggerTransfer` 对"pawn 踩到传送点格"的判定顺序：

1. `job.exitMapOnArrival == true` → 放行原生 ExitMap（撤离/远行队：征召 goto 传送点、撤离 duty、囚犯越狱、野性恐慌逃跑）。**不变。**
2. pawn 持有跨图登记（桥接传送许可标记）→ **传送** + 续程（跨图 goto）。
3. `pawn.IsAnimal`（野生+驯养）→ **传送**（无续程）。
4. 其余（所有人形的闲逛/工作/逃跑/战斗移动）→ **无事**。

即：传送资格 = 跨图登记 ∨ 动物；撤离资格 = 原生 flag。与移动目标格是否为传送点无关（只看"踩上"+资格）。

## 四、与现状的差异 / 实现待办（表定稿后执行）

1. **传送资格收紧**（影响所有人形非撤离移动场景）：现状 `TryTriggerTransfer` 对任何无 flag pawn 传送（`SeamlessMapTransferTrigger.cs:87` 之后无资格检查）。需增加"跨图登记 ∨ 动物"判定。
2. **预加载排除传送点格**（征召 goto 传送点场景）：`SeamlessBorderPreloader.CheckPawnGoto` 的边界带判定需排除传送点格本身——征召 goto 传送点 = 撤离意图，不应触发对端生成（生成也用不上）。
3. **桥接传送许可标记**（跨图 goto 场景）：`SeamlessCrossMapOrders.TryBridgeJob` 下发的 Goto（`SeamlessCrossMapOrders.cs:80`）与普通 AI Goto 无区分，收紧后会被误拦。桥接时给 pawn 登记 transit 标记（可复用/伴随 `SeamlessCrossMapPendingDestinations`，传送消费时清除）。
