# 边界行为表（传送点 / 接缝带行为规范）

本文档定义 RimExodus 中"pawn 与接缝传送点交互"的完整行为规范：什么主体、在什么移动状态下、踩到/走到传送点格或边界带时应该发生什么。目的：①统一实现判据；②区分"原版原生行为"与"mod patch 强加行为"，控制 patch 数量。

**状态：定稿（2026-08，行为值经用户逐项确认；行为表由 `doc/gen_边界行为表.py` 生成）。** 原版机制结论均经反编译源码核查（`references/RimWorldDecompiled`），附路径:行号。

## 一、原版机制事实（已核查）

### 1.2 检查点（谁在消费这个 flag）

- `JobDriver_Goto`：pre-tick `exitMapOnArrival && IsExitCell(pos)` → `TryExitMap()`；到达时额外有 `OnEdge(map)` 兜底 → `pawn.ExitMap(allowedToJoinOrCreateCaravan: true, ...)`（`Verse.AI/JobDriver_Goto.cs:22-27,58,69-81`）。
- `JobDriver_Flee`：同构检查（`RimWorld/JobDriver_Flee.cs:33-48,54-57`），无条件组队/入队。
- `JobDriver_TakeAndExitMap`：**不读 flag**，tickAction 查 pawn 所在格 `IsExitCell`、到达时 `OnEdge || IsExitCell` 即 `ExitMap(allowedToJoinOrCreateCaravan:true)`（TargetB 只是引导目标；`RimWorld/JobDriver_TakeAndExitMap.cs:29-46`）。
- 组队链：`Pawn.ExitMap` → `CaravanExitMapUtility.CanExitMapAndJoinOrCreateCaravanNow`（前置：Spawned 且 `MapUsesExitGrid`；殖民者直接 true；非殖民者只能**加入现有**远行队，`CaravanExitMapUtility.cs:157-170`）→ `ExitMapAndJoinOrCreateCaravan`（加入或建队，建队时 `autoJoinable=true` 并仅唤醒可入队、未倒地、未征召的 pawn `CheckForJobOverride`，`:106-140`）。

### 1.5 RimExodus 现状几何事实（mod 侧核查；2026-08 接缝带重构后口径）

- **传送点铺在传送圈 = 离散边圈 ∪ 带外圈**（`BuildSeamBand` 纯几何、无任何可通行性过滤；`SeamlessEnterSpotPlacer.PlaceEnterSpotsAllNeighbors` 每格一个 `RimExodus_SeamlessEnterSpot`）。**带内圈（核心侧一圈）无传送点**——"接缝带内非传送点格"真实存在（与旧口径"spot 铺满整条接缝带（距 void 切比雪夫 ∈{1..2}）"不同，旧口径已废）。权威定义见 [接缝带定义](接缝带定义.md)。
- **exit cell = 接缝带 Band 全三圈 ∪ 传送点格兜底**：`Patches_ExitMapGrid` 仅在地图已有 RimExodus 传送点时跳过原版 Rebuild，按本图接缝几何标记出口格；无传送点时仍是原版方形网格。现有门控与无点时的几何选点兜底可能形成不一致，见五.5.1 的待验证分叉。
- **边缘选点候选池 = 传送圈，无传送点时回落几何（2026-09）**：`Patches_CellFinder` 三处根原语的门 = `GetMapWorldTile(map) >= 0`，池经 `SeamlessEdgeCells.GetSeamEdgeCellsWithBandFallback`——有 spot 用点位（稳态语义不变，spot 池继续承载步行敌人邻图入场/袭击朝向等机制）；无 spot（生成期 389-1490，传送点 1490 才铺）回落 `BuildSeamBand().TransportRing` 几何（与稳态 spot 铺设范围恒等）。背景：边缘入场类开局 ScenPart（VEF `ScenPart_ArriveAtEdge`）在 genStep 875 调 `TryFindRandomPawnEntryCell`，原门放行原版 → 方形边缘全 void → 选点失败被 VEF 忽略 → `DropThingGroupsNear` 对无效中心逐组静默跳过 = pawn 不生成且无报错。配套根因修复：`CanReachColony` 生成期以 `PlayerStartSpot` 为 OnCell 目的地、目的地无 region 即全图恒 false（原版可达性目的地侧无兜底、起点侧才有 8 邻兜底）——旧版 392 曾预设出生点，被 500 序结构盖墙后 850 跳过重选即触发；预设已删（详见 [地图生成步骤](地图生成步骤.md) 850 行）。
- **预加载距离从接缝带的核心侧起算**：默认宽 15（`borderPreloadDistance`），紧邻 Band 的核心区第一圈算 1，0 在两种撤离模式下均关闭。距离大于 0 时，撤离开启则排除本图接缝带 Band/传送点格，关闭则允许接缝带也触发预加载。普通移动和 PS 统一由 `SeamlessBorderLookup.TryGetPreloadTarget` 判定，不在消费方重复排除；几何始终使用本图 tile，返回的邻居 worldTile 仅用于邻图查询、唤醒和生成。距离与开关刷新规则见 [接缝带定义](接缝带定义.md#7-消费方总览)。

- **Perspective Shift 预加载**：第一人称步行与驾驶共用 `TryPreloadAt`，按角色当前所在格调用上述资格查询；关闭撤离时站在接缝带内移动也可触发预加载/唤醒。普通移动按指令目标格查询，不沿途中逐格补触发。

### 1.3 关键否定性事实（决定行为表结构）

- **原版不存在"未征召玩家 goto"**：`FloatMenuOptionProvider_DraftedMove` 是唯一构造玩家 Goto 菜单的 provider，且 `Undrafted => false`（`:14-15`）；`MultiPawnGotoController` 拖框也转调它（`RimWorld/MultiPawnGotoController.cs:155`）。因此"未征召殖民者踩传送点"只可能来自闲逛/工作/逃跑/跟随等 AI job——全部不带 flag。
- **玩家指令 job 统一带 `playerForced`**：`PawnGotoAction` 构造 job 时不显式设置，但 `Pawn_JobTracker.TryTakeOrderedJob` 入口统一 `job.playerForced = true`（`Verse.AI/Pawn_JobTracker.cs:897`）——征召 goto / 未征召玩家命令 / 拖框全部覆盖。RimExodus 现有预加载分支（`Patch_Pawn_JobTracker_StartJob` 查 playerForced）因此对玩家 goto 全量生效。
- **闲逛 job 是 `GotoWander` 且无 flag**：`JobGiver_Wander.cs:74-93`；目标格筛选（`RCellFinder.RandomWanderDestFor`，`RimWorld/RCellFinder.cs:255-300`）**不排除边缘/出口格**——动物和未征召 pawn 闲逛可以停在传送点格上，但原版不会因此离图。
- **跟随 job 无 flag**：`JobDriver_Follow`/`JobDriver_FollowClose` 均不含 flag。

### 1.6 离图目的：普通撤离与必须入队

`exitMapOnArrival` 只表示到出口后离图，不能据此把所有非玩家强制任务当成 NPC 撤离。离图任务在 `Patches_Job` 的 StartJob 入口按原版契约分流：

| 任务意图 | 判据（均在 `exitMapOnArrival` 为 true 时） | 接缝行为 |
|---|---|---|
| 玩家直接下令离图 | `playerForced` | 保留原生离场/组队，对侧已加载也可离图 |
| 必须加入远行队 | `failIfCantJoinOrCreateCaravan` | 不登记 Evacuation，保留原版入队资格检查；队伍不可加入时任务失败取消，不跨图续跑 |
| 普通撤离 | 上述两项均为 false | 登记 Evacuation；对侧活跃则跨图续链，未加载/休眠则交还原生离场 |

护卫机械族的 `JobGiver_ExitMapFollowOverseer` 与公共 `JoinAutoJoinableCaravan` 子树都声明“必须入队”。分流不检查物种、阵营、具体 giver/lord 类型，也不以当前能否找到远行队替代任务意图。清除旧许可仍先于分流，避免新入队任务继承上一项任务的跨图许可。原版负责选择可加入的队伍、校验护卫机械族的 overseer 是否在队中，以及队伍移动后的失败取消。

此处是机械师已经成为世界远行队成员后的自动入队；下表机械族 Escort 的 Follow/FollowClose 行描述的是主人仍在地图上时的跨缝跟随。

### 1.7 普通撤离的方向与出口选择

一次撤离在跨图后延续同一方向。首次任务登记时记录 pawn 起点，在首次实际跨缝时以“起点 → 实际出口”确定方向；后续地图只平移坐标系，方向向量直接沿用。零行程时以实际跨图的两图中心投影方向初始化。游荡 NPC 转撤离没有原始撤离任务，先使用来图方向；来图不可用时按路径成本选首出口，再由该出口确定方向。

`TryFindEvacuationExit` 对本图出口执行一次代价场查询，按以下顺序选择，并以原生/VF 可达性复核：

1. 未访问且沿撤离方向有正向进展的出口，最大化“前进距离 / 路径成本”；同效率优先推进更远。
2. 无可达前向出口时，选择成本最小的未访问侧向/后退出口。
3. 只剩已访问出口时，选择成本最小的出口并 `ForceExit`，保留防循环兜底。

方向点积无需归一化，同次选择共享方向长度；脚下格不参与候选，因为它无法再次触发 `nextCell` 踩点。加载状态不参与排序，只在到达出口时决定跨图续行或原生离场。当地形确实使沿边路线更有效时仍可沿边，不承诺整个已加载区域的全局最短逃生路线。

段内仍使用原版 Goto 与原版寻路。选点代价场沿用主体的地面/飞行/水面/VF 成本源；撤离额外传入原任务的破门、破栅栏权限，复用 `PathUtility.GetBuildingCost`，并把相同权限传给续程 Goto。挡路 pawn、avoid/allowed 网格等仍不进入估价，实际执行由原生寻路处理。方向、起点与权限只存于运行时许可，随任务替换失效，不新增存档字段。

离线排序回归：`pwsh -File tests/EvacuationRouting.Tests.ps1`；游戏内验证项见 `doc/TODO.md`。

## 二、行为表

原则：

- 预加载原则上只能由玩家操作触发
- 在NPC在原版中会尝试从边缘撤离的场景中，如果对端地图未加载，NPC会正常撤离，如果对端地图已加载，NPC会进入对端地图后继续撤离

列说明：
- **flag** = 该移动场景下 job 的 `exitMapOnArrival` 预期值（注明原生来源）。
- **传送资格** = 该场景是否可获传送许可（Bridge/Evacuation/Pursue/Follow 四类 Grant，`SeamlessTransferGrants`；桥接自标识 = `job.dutyTag` TransitTag，无许可不传）。
- **踩点(已加载)** = 对端地图已加载（`hasArrival==true`）时 pawn 踩到传送点格的行为。
- **踩点(未生成)** = 对端未生成/生成中时 pawn 到达传送点格的行为。
- **预加载** = 该指令是否应触发邻居地图预加载。
- **原版行为** = 无 RimExodus 时此场景的结果（exit cell 为原版方形边缘带）。
- **patch 依赖**：`无需`（原版即如此）/`现有`（依赖现有 patch）/`已实现`（阶段5 传送许可登记制落地，注明实现锚点）。

## 三、传送点激活判据（实现判据，定稿）

`TryTriggerTransfer` 对"pawn 踩到传送点格"按序判定：

1. **flag 且为玩家强制撤离或必须入队的任务**（见 1.6）→ 不登记 Evacuation，保留原生 ExitMap/组队及入队失败取消。殖民地机械族的玩家征召 goto 保留原版 `!IsColonyMech` 例外（无 flag，站住）。
2. **flag 且属普通撤离场景**（非玩家强制、非必须入队；撤离 duty：袭击撤退/盟友·访客·商队·旅行者离场、囚犯越狱、野性恐慌逃跑）：
   - 对端已加载（`hasArrival`）→ **传送** + 对端续发撤离 job（继续跑，出口选择远离来向接缝，直到到达没有加载对端的撤离点 → 原生撤离，视为跑出视野）。
   - 对端未生成 → 放行原生撤离。
3. **跨图登记**（玩家跨图 goto：殖民者/殖民地机械族/被征召驯养动物）→ **传送** + 续程 Goto。
4. **敌方主体战斗移动**（追击/走位——Pursue 许可：追击扫描 `MarkPursuers` / 战斗踩点 `TryRegisterCombatStepTransfer`，见第五节）→ **传送**（跨图追击，防玩家靠跨图甩掉追兵）。
5. **驯养动物跟随主人**（Follow/FollowClose job）→ **传送**（无续程）。
6. 其余（所有人形/动物的闲逛、工作、无 flag 逃跑）→ **无事**。

原则：传送资格 = flag∧普通撤离 ∨ 跨图登记 ∨ 敌方战斗 ∨ 跟随；原生离场 = 玩家直接撤离、必须入队，或普通撤离对端未加载（具体入队资格由原版判定）。目标格非传送点的移动不因路径经过传送点而激活（闲逛/工作/逃跑的目标恒为图内格）。

预加载原则：**只能由玩家操作触发**（征召 goto 或 PS 步行/驾驶）；撤离开启时排除接缝带/传送点格，关闭时允许接缝带触发，距离 0 始终关闭。下方及行为矩阵的撤离/预加载结果以撤离开启的默认模式为准。

> **2026-08 状态**：下列待办①-⑦ 已全部实现（映射与实现锚点见第五节"实现落地记录"）；⑧ 保持已排除结论。本节保留作"定稿时与当时现状的差分"历史记录。

### 五.5.1 2026-10-30 商队撤离循环：证据与待验证分叉

2026-10-31 同格补触发（待游戏内回归）：`Pawn_JobTracker.StartJob` 对已登记传送许可且目标为脚下传送点的 Goto，在原版立即完成移动 toil 前调用与踩点相同的传送分派。跨图或离场成功时不安装旧图 job；对侧未加载时仍走原版离场。对侧已加载但落点不可用、缓存失效等实际传送失败会限频显示 Keyed 警告；普通撤离的同格 Goto 会标脏 ExitMapGrid，再交还 `JobDriver_Goto` 到站离场检查；无离场 flag 的续程 Goto 则直接走既有原生离场入口。下文 2026-09-06 所述“恰好已站在 spot 上仅原地离场”的历史边界由此替代。该补触发不证明先前实例的传送失败原因，诊断日志仍保留用于确认。

1.6 用户日志 `tmp/gistfile1.txt` 中，Zee 等 NPC 同 tick 多次启动 `JobGiver_ExitMapBest` 给出的 Goto，Zee 的目标固定为 map 0 的 `(226, 0, 59)`；没有这些 pawn 的 `Pawn.ExitMap` 记录。一只驮兽在同局从 map 0 `(234, 0, 71)` 成功跨图。这说明 Zee 的目标不是 map 0 的矩形最外沿，但日志没有他的**当前位置**、此目标上的物品、选点分支、传送点数、出口网格状态或寻路结果。“到目标马上完成”和“寻路马上失败”均可产生高频重发；仅凭玩家描述“卡在边缘”不能排除后者。

2026-10-31 用户对另一名卡住的 NPC “Родоторф” 现场核实：Goto 目标 `(68, 0, 254)` 与 pawn 所站位置完全相同，该格物品列表确有 `seamless tile entrance`，地图也确实已裁成六边形。这把该案例的“目标不可达”“没有传送点”“旧方形地图”三条分叉排除；Zee 原日志没有同样的现场坐标，不能把这三条排除直接外推给 Zee。更准确的现象是**已站在传送点上仍不断收到指向脚下的撤离 Goto**，尚未证明是传送执行器本身拒绝传送。

`JobGiver_ExitMapBest` 本身不等于不可挖掘。原版 `JobGiver_ExitMap.TryGiveJob` 在 `forceCanDig`、`duty.canDig && !CanReachMapEdge()` 等条件下把 `canDig` 传给同一个 `JobGiver_ExitMapBest.TryFindGoodExitDest`，后者改用 `TraverseMode.PassAllDestroyableThings`。`RCellFinder.TryFindBestExitSpot` 在该模式且普通路径到不了地图边缘时，改走 `TryFindRandomPawnEntryCell`；RimExodus 对这个入口的无传送点兜底可以选到矩形内部的几何传送圈。因而“目标不在矩形边缘 ⇒ 必有传送点”不成立。Zee 日志里的 lord 为 `LordJob_TravelAndExit`，其原版退出 toil 默认 `canDig=false`；原版贸易商 lord 则有因无法抵达地图边缘而切入 `canDig=true` 的退出 toil。现有日志没有 Zee 的 `duty.canDig` 值、先前 lord/toil 历史，也没有选点时的有效 `TraverseMode`，不能从“商队一员”推断 Zee 已走或未走挖掘分支。即使先前走过挖掘分支，**每次重新下发 ExitMapBest 都会重新选点**；若后来真切回普通模式且仍无传送点，原版通常只会给矩形边缘目标。这与固定的内部目标矛盾，需要 `canDig`、选点来源和传送点现场一起解释。

对“Родоторф”的当前主疑点是传送点格没有被原生离场判定识别：跨图触发器只在 `Pawn_PathFollower.TryEnterNextPathCell` 即将**进入**传送点时运行，已经站在点上的同格 Goto 不会再触发传送。原版 `Toils_Goto.GotoCell` 在起点等于目标时直接进入下一 toil；`JobDriver_Goto` 的到站检查若 `exitMapOnArrival` 且矩形 `OnEdge` 或 `ExitMapGrid.IsExitCell` 为真，就应调用 `TryExitMap`。`JobGiver_ExitMap` 原版会给该 Goto 设置 `exitMapOnArrival=true`；RimExodus 的撤离推迟 patch 在 pawn 已站在传送点时会放行。因此若这个 flag 仍为真且没有离场内部条件拦截，循环指向 `IsExitCell=false`。这可能是网格在铺点前惰性重建后未被标脏，但尚无该实例的原始网格值；传送点是 Ethereal，不会经原版 Building 的 LOS blocker 通知使 ExitMapGrid 失效。先前按 `worldTile>=0` 无条件重建几何网格的改法已撤回，不能只凭当前位置与点位就重新定案。

旧存档中途加入 RimExodus 是必须单列的混合状态：已生成的原生家园图读档时不会重跑 389 裁切和 1490 铺点，初始仍是方形地形、无传送点；之后预加载邻图的接线可在这张旧图上补铺六边形传送点，却不补做裁切。此时“方形可行地形 + 六边形传送点”并存，单凭合法表面 `worldTile` 无法推断地图已被裁切。旧家园未铺点时 `MapUsesExitGrid` 仍按原版为假，非家园图则可能为真；普通方形边缘撤离、挖掘分支的内部几何候选、补铺点后的重定向会得到不同结果。这是独立的兼容性风险，**不是已核实的“Родоторф”案例地图状态**。

诊断方案：只在 `[caravan-exit]` 开启时记录本次 `TryFindBestExitSpot` 选点来源、有效 `TraverseMode` 和 `canBash`；撤离 Goto 首次登记记录 lord、duty、`duty.canDig`、位置、目标及 `exitMapOnArrival`/入队失败标志。同 tick 第三次重发时额外记录 pawn 位置/目标、能否抵达边缘及目标、移动器状态、传送点数、两格的传送点与接缝圈归属、`MapUsesExitGrid`、**未触发重建的原始网格值和 dirty 状态**、两格地形和最多 12 个物品，以及地图四角地形以辨认旧方形图。实际进入传送点的一步会记录许可、对端缓存和加载状态；`TryExitMap` 的允许/推迟入口另留限频记录。每名 pawn 的常态摘要与现场最多每 600 ticks 一组，状态切换另记，避免原日志刷屏。下一份带诊断的复现日志可区分踩点从未发生/许可缺失、网格未识别出口、离场内部阻断，以及旧日志中的其他分叉。
