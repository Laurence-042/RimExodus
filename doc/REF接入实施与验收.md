这不是把 RE 世界政策搬进 REF，也没有把地表 MapParent 改成口袋图。REF 模式跳过 RE 的原版战斗补丁和 CE 注册，评估窗口转调 REF；legacy 代码保留。只有消费方启用战斗模块时才安装 REF 战斗补丁；Delta-V 不调用该入口。与 RE 同装时，共享方法仍有 Harmony 分派及逐图早退成本，关闭地图没有邻图战斗扫描或调度改速。

## 操作与回退

1. 启用 Harmony、RimExodus Framework、RimExodus，确认实际加载的是本次构建 DLL。
2. 默认先走 legacy。设置 → 地图生成 → “使用 REF 地图底层（重启生效）”，勾选后完整重启。
3. 日志应有 `[REF] FrameworkMod instantiated`、`[RimExodus] Map backend: REF`，以及 `RimExodus.Maps`、`RimExodus.Maps.Combat` 的 `GetPatchedMethods` 报告。CE 还应有逐项绑定行。legacy 不应出现 REF 战斗模块绑定报告。
4. 回退时取消勾选并完整重启，确认日志为 `Map backend: legacy`。独立 REF 前置仍需启用。

用同一份测试存档副本分别比较两种模式。旧前哨键与 Def 身份未删除；新档也保留 legacy 记录。Comp 状态的回退边界以 [地图滚动休眠](地图滚动休眠.md) 为准，开关不会补回 legacy 从未保存过的数据。

## 已执行验证与阻挡

- `just build 1.6`：REF 1.6 与 RE 1.6 均通过标准 Release 构建，0 警告、0 错误。
- REF `just test-services`：生产调度算法与生成协调器的 2,135 项检查通过；引擎对象用最小占位实现，不覆盖 Harmony、GPU、Scribe 和实际 tick 注册表。
- 尝试原有 1.6 PatchAll 离线验证器：原配置的 `RimWorldWin64_Data/Managed/Assembly-CSharp.dll` 已不存在，出现程序集加载失败。本轮没有可用绑定结果，不能沿用历史 146/25 数字作为新结果。
- `just build`：REF 1.7 与 RE 1.7 均通过 SDK 10.0.403 的标准 Release 构建，0 警告、0 错误；运行时 REF 与 RE 编译引用的 SHA-256 一致。流程与 Delta-V 一致：先构建 REF，复制对应版本的编译引用，再构建 RE；REF 失败立即停止，不使用备用编译路径。
- 本机 SDK 写入失败已定位并修复：Delta-V 本地 SDK 的 `dotnet.exe` 与 Roslyn 的 `csc.exe`、`vbc.exe`、`VBCSCompiler.exe` 带有继承的 Low 完整性标签，启动后的进程无法写入普通用户目录。仅将这四个程序的标签恢复为 Medium，并重启该 SDK 的编译器服务，原构建链即通过；未放宽用户目录 ACL。先前直接调用编译器生成的 DLL 已由标准构建覆盖；备用构建脚本已删除。
- 用户启动日志暴露公共补丁扫描误收 `MapPreviewGenerationPatch`，导致无目标方法而初始化失败。已限制自动安装为显式 HarmonyPatch 类型，保留 MapPreview 的延迟手动注册。`just test-ref` 的 180 项检查通过，其中新增 5 项直接执行生产安装循环，在实际 1.7 程序集上成功绑定 29 个方法，并检查未提前安装手动 MapPreview 或战斗补丁。其余覆盖调度、坐标、绑定签名、渲染门禁组合及原生绘制捕获/提交。
- 修复后仍需游戏实例化成功行、游戏内 GetPatchedMethods 报告及功能实测；离线绑定未启动游戏，不代替这些验收。当前是可供测试的双后端接入，不能视为最终切换完成。

## 高兼容性原版邻图渲染

设置 → 地图生成 → **高兼容性原版邻图渲染**，默认关闭，下一帧切换，不需重启；与 REF/legacy 模拟底层独立。两种底层均调用 REF 公共渲染服务。旧的 `SeamlessTileRenderer` 自绘制保留，切换时互斥并释放旧绘制缓冲；没有邻居的 Surface 聚焦图在 1.6 仍清色，口袋图/空间层不登记。生成中的半成品邻图排除，已有图在增量生成期间仍可绘制。

RE 只提供可见图、`SeamlessViewProjection` 投影和凸多边形。REF 包裹原版每帧本来就有的一次 MapUpdate，在作用域内覆盖 CurrentMap 查询和局部视区，让原版地图绘制、动态物、Fleck、组件 Update 内绘制自然进入；邻图追加一次组件 Draw。没有二次 tick、没有额外组件 Update，也没有重放相机更新或设置真实聚焦图。聚焦图的常规 shader 更新保留，邻图窗口退出时恢复参数。具体 API、版本路径及资源生命周期见同级 REF 的 `doc/地图模块.md`。

天色仍由 RE 按原有三层规则合成：聚焦图的光照层负责自身方形，邻图的原生光照网格保留 glow/屋顶顶点数据，但在邻图 `SkyManagerUpdate` 后把共享 `LightOverlay` 的天色 alpha 设为 0；全部 `MapUpdate` 完成且 REF 绘制作用域退出后，再用现有矩形并集算法给邻图方形在聚焦图方形之外的区域染一次聚焦图天色。不能只依赖 REF 的大面积平面遮罩裁切：普通 `SectionLayer_LightingOverlay` 网格跨度不足半张地图，不会被该裁切器处理，重叠区会重复染色。此修复已通过双版本构建；昼夜场景继续纳入游戏回归。

这不是任意 Mod 的等价保证。通用机制没有 Surveillance Shift / IsoRim 专用识别；普通地图组件迷雾可进入绘制，但不会替 Mod 生成跨图视野。私有相机缓存、第一人称墙体规则、shader 自定义世界坐标采样、全屏效果、shader 数组/关键字/独立 uniform block、GPU 间接缓冲、绕开提交入口的批量或持久命令、异步线程绘制仍可能不一致。大面积平面网格裁切不等于任意 3D 遮罩。新路径分配与绘制量更高，尚无实机性能结论。

本轮离线验证：1.6/1.7 REF 与 RE 编译零警告、零错误；REF 回归共 526 项，其中 76 项检查参数冻结/异常恢复、队列/pass/layer、坐标与真实 CPU 网格裁切/UV 插值/版本失效，以及加厚包围盒、未使用离面顶点和实际非平面网格；生产安装循环在实际 1.7 游戏程序集绑定 34 个方法。RE 兼容回归为 legacy 24 项、REF 26 项、签名漂移 10 项。1.6 历史 PatchAll 验证器已尝试，仍缺少其指定的 Assembly-CSharp，不能给出绑定成功结论。离线检查不启动游戏，不覆盖 GPU 最终画面。

游戏验收请先确认加载本次配套 DLL，再核对 `[REF] FrameworkMod instantiated` 和 GetPatchedMethods 报告。分别在两个底层检查：

1. 暂停和运行时反复开关、聚焦图互换、世界图返回、换档；无双画、残影、清屏污染。
2. 邻图水面/水深、昼夜/不同天气、Fleck/Mote、灯光、阴影、第三方层；直接聚焦前后对照。
3. Surveillance Shift 明暗区、Pawn 隐藏、接缝处矩形雾角、视野变更；通用矩形越界修复已由用户验证。新加入的跨图视野按 [专用验收](SurveillanceShift跨图视野.md) 检查，不等同于通用渲染能力。
4. IsoRim 普通视角/倾斜/第一人称逐项记录；相机与私有墙体缓存是已知边界，不能以普通网格显示成功推断全面支持。
5. 休眠/唤醒/删图、零邻居、增量生成期间平移缩放；观察帧耗时与内存，不借此改变 tick 或休眠政策。

跨图查询 API、坐标契约和 SS 背景遮片修正见同级 REF `doc/跨图空间查询.md`。SS 新视野回归使用原样链接的参考算法与宿主夹具，共 23 项；REF 当前总计 526 项检查，包含 235 项空间/背景契约和 33 项视区顺序/剔除兼容回归。兼容绑定回归为 legacy 24、REF 26、MapPreview 漂移 10 项。SS 跨图视野已由用户确认验证完成；背景遮片修正的离线检查不替代各消费方的背景实测。

IsoRim 随镜头缺块修复分两层：REF 局部视区以末优先级覆盖通常优先级的相机 Postfix；独立 IsoRim 兼容层在私有可见性判定前转换包围盒/模型矩阵。实际参考 DLL 的两个入口可绑定，日志相机夹具中原先拒绝的邻图块经投影后通过；这不等同于 GPU/实机结果。重启后在正常显示全部地图的模式下验证平移、缩放、旋转及聚焦切换，同时核对实例化/绑定日志。矩形土层长条和首次显示私有层重建仍是独立边界，详见 [调查与实现](IsoRim邻图渲染调查.md)。

用户已实测确认本轮 IsoRim 灰色缺块与移动锯齿边界修复有效；其余专用机制仍按上述边界处理。
