状态：已完成核心闭环，游戏内已验证；五边形地块与 offset 凑整对称性仍待补验证。

## 阶段目标

把第二阶段的"矩形地块 + 刚性重叠带"换成"用可重叠正方形承载世界地块多边形"的完整几何。每个地块地图是一张正方形 `Map`（边长 S），但其上**只有对应世界地块的多边形内部是可活动区域**，多边形之外铺透明虚空地形（void），Pawn 既不能站也不能看过去。相邻地块的多边形在正方形地图上相互交叠，两端的非 void 区域在接缝处重叠，视觉上拼成无缝大地图。

本阶段只负责"几何裁切 + void 铺设 + 接缝传送点铺设"，不处理接缝两侧地形是否连续（那是第四阶段）。RimWorld 星球表面由大量六边形加 12 个五边形平面拼成，因此多边形边数 N 统一为 5 或 6，所有算法遍历 N 个顶点，不区分边数。

## 三态几何模型（核心，务必先读）

每个地块地图上的格子分为三态，**完全由它自己的六边形决定，不看任何邻居**：

- **六边形内部**（不含边）：非 void，**无传送点**。
- **六边形的边**（多边形边线经过的格）：非 void，**有传送点**（仅当该边对应的真实世界邻居地块已加载时，传送点才绑定对端）。
- **六边形外部**：void，不可通行、透明、不生植物、不可建造。

两张相邻地图**各自独立**铺自己的 void。地图 A 六边形之外的 void 区域，在地图 B 上恰好是 B 六边形的内部或边（非 void）——这就是"void 完全被 B 覆盖"的含义：它只对 A 视角成立，从 B 视角看那一块是 B 的活动区。**绝对不要**在 A 地图上把"被 B 覆盖的区域"判成非 void；A 上那块就是 void，由 B 在视觉上盖住它。

两端传送点通过邻居 offset 对齐到同一世界坐标：A 北边格与 B 南边格经 offset 平移后重合，各自地图上那条边都是非 void（边格），所以两端都可站立。这是无缝转移的几何前提。

## 等边顶点模型（2026-08，自"内切圆模型"修正）

多边形顶点位置用"等边模型"确定（**2026-08 用户定夺，勿回退为外接圆半径恒 0.5S**）——世界测地网格上五-五/五-六/六-六边球面等长，边长恒定才是忠实投影：

> 目标边长 = 0.5S；半径 = 0.5S / 相邻顶点方向平均弦长；顶点 = 地图中心 + 半径 × 顶点方向单位向量

即顶点落在正方形地图的内切圆附近（半径 = 0.5S）上，S 是地图边长。正六边形平均弦长 = 1，半径精确回落 0.5S（与旧模型逐位一致，六边形零回归）；正五边形平均弦长 = 2sin36° ≈ 1.176，半径 ≈ 0.4253S——边长与六边形相等。旧"半径恒定"模型下五边形边长 2·0.5S·sin36° ≈ 0.588S，比六边形长 ~17.6%（2026-08 游戏内实测观察确认），且五-六共享边两图投影不等长，offset 中点对齐后向边端线性发散 ~11 格 @S=250，超 3 圈接缝带吸收能力、远端照抄混合静默失效。顶点方向不是硬编码的东南西北，而是从世界地块的真实顶点投影而来（`WorldTileGeometry.PopulateVertexDirections`）：取 `WorldGrid.GetTileVertices` 拿到该 tile 的世界顶点，用 `WorldRendererUtility.GetTangentsToPlanet` 把它们连同 tile 中心投影到以 tile 中心为原点的切平面，再做归一化。这样多边形忠实于该 tile 在星球上的真实朝向——无论是 flat-top 还是 pointy-top、是否经过极区旋转，都不需要特判。

> 旧档注意：已按旧几何生成过的五边形图（含其邻居的条带快照）与等边模型错位，每星球仅 12 个五边形 tile，建议用"删除此图" gizmo 令其走生成链重建。

邻居 offset 也从这套顶点算出（见下节）。每张地块保留自己的切平面基，相邻 tile 的中心不同导致切平面基之间有微小旋转——这就是投影扭曲，本阶段不消除它，而是在接缝处用 2 格重叠带吸收（见"接缝带"一节）。

## 数据模型：NeighborLink

地块之间的邻接关系由直接邻居表维护。`MapParent_SeamlessTile.neighbors` 是 `List<NeighborLink>`，每条含三个字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `worldTile` | `int` | 该邻居在世界地图上的 tile id，作为主键查询（稳定、无角度歧义） |
| `neighbor` | `MapParent` | 邻居地块的 `MapParent` 引用（锚点家园或另一个 `MapParent_SeamlessTile`） |
| `offset` | `IntVec3` | 邻居本地坐标 → 本地块坐标的平移（`cellNeighbor + offset = cellMy`） |

**没有 `direction` 或 `edgeAngle` 字段**——方向完全由 `offset` 隐式编码。早期版本曾用 0-5 固定编号或 `edgeAngle` 弧度显式标方向，全面重构后已全部移除：offset 本身就是方向的唯一载体，渲染器、归属判定、边界带、传送点缓存都直接读 `offset`，不需要再查一次方向表。`NeighborLink` 实现 `IExposable`，随存档深序列化。

锚点家园地图（普通 `Map`，不是 `MapParent_SeamlessTile`）的邻居表由 `SeamlessTileManager` MapComponent 持有；地块的邻居表存在自己的 `MapParent_SeamlessTile.neighbors`。`SeamlessTileGraph` 提供统一查询入口（`GetAllNeighbors` / `TryGetNeighborLinkByWorldTile`），屏蔽存储位置差异。

## 虚空地形 RimExodus_Void

void 是独立顶级 `TerrainDef`（`1.6/Defs/TerrainDefs/VoidTerrain.xml`），不继承 `NaturalTerrainBase`，避免太空边框贴图等无关默认值污染。参考了 VMF `VMF_ImpassableFloor` 与官方 `Space`。它的"完全不可通行 + 完全透明"由一组 Def 字段共同保证，经源码调研确认不需要额外 Harmony patch：

- `passability=Impassable`：`PathGrid.CalculatedCostAt` 返回 10000，寻路、Region 划分、`JumpUtility.ValidJumpTarget` 全部拒绝。
- **不设** `forcePassableByFlyingPawns`（保持默认 false）：Flying PathGrid 也判为不可通行，堵住飞行漏洞。
- `fertility=0`：`WildPlantSpawner` 不在此生植物。
- 空 `affordances`：任何需要地形承载面的建筑都无法放置。
- `changeable=false` + `layerable=false`：玩家无法用铺地板或地形改造覆盖。
- `avoidWander=true`：wander AI 不会选此格（额外保险）。
- `dontRender=true`：主地形层不绘制，使用 ShadowMask 材质（透明/暗影）。

`dontRender=true` 使 void 格在地形层上不写不透明颜色，多边形外的区域自然透明，露出下方聚焦地图的地形——这是"void 完全被对方地图视觉覆盖"的渲染基础。移动相机时若上一帧正常地形的像素残留在颜色缓冲里会叠加压暗，这一现象已在 `SeamlessTileRenderer` 的 CommandBuffer 开头加 `ClearRenderTarget(clearColor=true)` 解决，与 TerrainDef 无关。

## void 铺设：格角检测消除孤岛

void 铺设的归一入口是 `SeamlessTerrainFill.BackupSnapshotAndApplyVoid(map, worldTile)`。它先备份裁切前的完整矩形 `topGrid`（供第四阶段接缝覆写卷积混合读取，存储位置随载体类型自动选择——地块存 `MapParent_SeamlessTile.baseTerrainSnapshot`，锚点存 `SeamlessTileManager.anchorBaseTerrainSnapshot`），再调用 `ApplyPolygonTerrain` 实际裁切。锚点家园 A 与邻接地块 B 走完全相同的 genStep 链（三个 RimExodus genStep 通过 XML PatchOperation 注入到所有玩家可进入的 `MapGeneratorDef`），不再有两份重复的"备份 + 铺 void"逻辑。

`ApplyPolygonTerrain` 的核心判定是**格角检测**：

> 格中心在多边形内，**或** 格的 4 个角中任一在多边形内 → 非 void；否则 → void。

凸性保证了正确性：多边形外部的格 4 个角都不在内，内部的格（含边附近）至少一个角在内。这一判定消除了所有"void 孤岛"问题——早期版本混用 `ContainsPoint` 叉积判定和 `Bresenham` 整数圆整划线，两套口径在边附近错开 ±1 格，切出孤立 void 格切断 Region，导致 `numDistrict=0`、寻路失效、动物生成失败。格角检测是唯一判定，不再有任何边格补丁。

判定完分类后，`ApplyPolygonTerrain` 先清除 void 格上的实体（建筑、岩石、植物、物品，`Destroy(Vanish)`；对 `destroyable=false` 的如 SteamGeyser 改 `DeSpawn`），再批量写 `topGrid`（直接赋值公开数组、只标 mesh dirty、跳过 `SetTerrain` 的重计算副作用，21000 格从 5.7 秒降到毫秒级），最后把误生在 void 格上的 Pawn 径向移到最近可通行格（找不到则销毁非人类 Pawn）。

## 接缝带：ComputeVoidBand

"距 void 边界 N 格"这一语义在本系统里被三处消费：传送点铺设（接缝带）、接缝地形混合（SeamOverride 混合带）、边界预加载检测（BorderLookup 边界带）。这三者曾经各写一份几何（浮点多边形边距离、自建平移法掩码、Bresenham 划线），口径彼此错配，是游戏内"传送点缺失""SeamOverride 泥土带漏出""最外圈擦边格漏带"等一连串症状的共同根因。

归一后的唯一实现是 `SeamlessPolygonGeometry.ComputeVoidBand(map, bandWidth, neighborWorldTiles, result)`：

> 带 = 到最近 void 格的切比雪夫距离 ∈ {1..bandWidth} 的非 void 格。

算法是多轮膨胀：以 void 格为种子（距离 0），每轮把已标记层的 8-邻域内、尚未标记的非 void 格标为"上一轮值 + 1"，共 `bandWidth` 轮，等价于"void 向外膨胀 bandWidth 格"。复杂度 O(N²·bandWidth)，远优于"对每个 void 格扫 (2r+1)² 邻域"的平移法。带内每个格再调 `FindClosestEdgeIndex`（到 6 条多边形边的浮点距离取最小）映射到它最近那条边对应的世界邻居 tile。

**几何同源是关键**：`ComputeVoidBand` 直接读 `TerrainGrid.topGrid` 判定 void，而 `topGrid` 的 void 是 `ApplyPolygonTerrain` 用格角检测铺的——所以"带"和"void 边界"用的是同一套边界表示，不存在两套口径错配的可能。调用时机约束：必须在 `ApplyPolygonTerrain` 之后调用（genStep 顺序保证）。

传送点铺设（`SeamlessEnterSpotPlacer.PlaceEnterSpotsAllNeighbors`）就是调 `ComputeVoidBand(map, SeamOverlap=2, ...)` 拿到 2 格宽的接缝带，在每个带内格放一个单端传送点 Thing（Ethereal 载体，不可攻击/拆除/占领、不进 edificeGrid、`drawerType=None` 不绘制），其 `CompSeamlessTileEnterSpot.targetWorldTile` 设为该格最近边对应的世界邻居。预铺时 `hasArrival=false`；邻居地块加载、邻居关系登记完成后，`RefreshEnterSpotArrivals` 用 offset 算出对端坐标并缓存到 `cachedArrivalCell`，废弃了早期的"两端 spot 互引互绑"模式（投影扭曲使精确坐标互绑不可靠）。

## 接缝重叠带与投影扭曲

邻居 offset 由 `SeamlessNeighborRegistry.ComputeNeighborOffset` 计算：

> offset = round( 2 × (边中点 − 中心) − SeamOverlap × 方向单位向量 )

边中点取自源地块多边形顶点，`SeamOverlap = 2` 是常量。沿 offset 方向收缩 2 格的效果是：邻居多边形相对源地块多叠 2 格，这 2 格在两端都落在各自多边形内（非 void、可站立）。

为什么要主动多叠 2 格？因为投影必然扭曲：相邻 tile 各自用自己地块中心的切平面基投影多边形顶点，中心不同导致切平面基之间有旋转，世界网格上的同一条共享边在两端局部坐标系里的 2D 方向不同（赤道到北极累积约 30°）。如果两端各自精确铺一条单线传送点，投影旋转会让两端 spot 错开，精确坐标互绑失败。改成 2 格宽的带后，两端各有 2 格宽的 spot 带，经 offset 重叠时实际接缝落在两端带的中线上——即使投影旋转让两端 spot 错开 ≤2 格，落点仍落在对端带内，被吸收。所有 offset 消费者（渲染、归属判定、边界带、void、传送点缓存）都读同一个 `NeighborLink.offset`，offset 一改全部自动跟随。

## 已解决的弹跳根因

阶段后期游戏内出现一个连发症状：`numDistrict=0`（六边形内可通行区被切碎）、`RandomAnimalSpawnCell_MapGen failed`、`BindUnboundSpotsBetween` 绑定数偏低。定位到同一个架构债——**void 绘制与传送点放置用的是两套不一致的几何口径**。

旧路径里，void 判定用 `ContainsPoint` 叉积或 `ScanlineFill` 浮点离散化，传送点放置用 `EnumerateEdgeCells` 的 `RoundToInt(浮点顶点) → Bresenham 划线`，混合带和边界带又各自用浮点多边形边距离。这些判定在多边形边附近彼此错开 ±1 格：某些最外圈格 Bresenham 线没经过（无传送点），某些次外圈格反而被经过（有传送点）；void 边界和带边界对不齐，切出孤立 void 格切断 Region。

修复不是"再调一次参数对齐"，而是**消除多套几何**：void 铺设改为格角检测（唯一判定），所有"距 void 边界 N 格"语义统一走 `ComputeVoidBand`（直接读已铺好的 `topGrid` 判 void，与 void 铺设同源）。从此 void 边界、传送点带、混合带、边界带共用同一套边界表示，错配从结构上不可能再发生。废弃的旧方法（`EnumerateEdgeCells` / `BresenhamLine` / `ComputeEdgeBand` / `InsetPolygon` / `ScanlineFill` 等）已作为死代码删除。

## 待办

- **offset 凑整对称性多跳验证**：A→B 与 B→A 各自从自己的多边形边中点算 offset，理论上互为相反数，但 `RoundToInt` 可能引入 ±1 误差。单跳场景已验证可用，多跳（A→B→C）场景的累积误差仍需游戏内确认。
- **五边形地块**：12 个特殊 tile 是五边形，算法已统一遍历 N 个顶点不区分边数。2026-08 游戏内观察确认旧模型下五边形边明显更长（+17.6%），随等边模型修正（见"等边顶点模型"节）；修正后的五边形图（边长/五-六缝混合）待游戏内回归。
- **边界带不可建造约束**（第四阶段前置）：需 patch `GenConstruct.CanPlaceBlueprintAt`，禁止玩家在多边形边内侧 `SeamOverlap+1`（=3）格内建造。传送点只在对侧可达时才被 goto 激活，但玩家可用建筑改变寻路打破此前提、把 pawn 困在 void 一侧。这是"卡 void 不会发生"论证的前提，详细设计见主文档第四阶段。
- 连续地形（接缝两侧高度/地形/水域一致）依赖本阶段稳定的多边形边界几何，是第四阶段的工作。

## 关键源码清单

本阶段涉及的核心源码（均在 `Source/`）：

- `SeamlessPolygonGeometry.cs` — 多边形几何工具。`BuildPolygonVertices`（等边顶点，进程级缓存）、`IsCellInPolygon`（格角检测）、`ContainsPoint`/`ContainsPointAt`（叉积判定）、`ComputeVoidBand`（"距 void 边界 N 格"唯一实现，多轮膨胀）、`FindClosestEdgeIndex`、`DistanceToEdge`。
- `SeamlessTerrainFill.cs` — 多边形地形铺设。`ApplyPolygonTerrain`（格角检测铺 void + 清实体 + 清 Pawn）、`BackupSnapshotAndApplyVoid`（归一入口：备份 snapshot + 调 ApplyPolygonTerrain）。
- `WorldTileGeometry.cs` — 世界地块真实几何读取。`PopulateVertexDirections`（世界顶点投影到切平面归一化）、`FindNeighborIndex`（邻居序号反查）。

- `CompSeamlessTileEnterSpot.cs` — 传送点组件。`targetWorldTile`（持久化匹配标记）、`cachedArrivalCell`/`hasArrival`（运行期缓存，不序列化）、`ComputeAndCacheArrival`。
- `GenStep_SeamlessTile.cs` — genStep，调 `BackupSnapshotAndApplyVoid`。
- `1.6/Defs/TerrainDefs/VoidTerrain.xml` — `RimExodus_Void` 虚空地形 Def。
