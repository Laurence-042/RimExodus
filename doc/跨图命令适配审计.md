## 一、为什么移动/射击可用而挖矿不行（结构性差异）

跨图交互架构（点击重放 + 公共函数层）下，命令能否跨图取决于**原版选项的判定来源**：

- **直接 job 型（移动/射击/装备/搬运/驯服等）**：选项判定只看目标本身——CanReach（公共函数，
  下令语境给真实答案 CanBridgeTo）、CanHitTarget（跨图射击线）。选项 action 直接
  `TryTakeOrderedJob`，job 目标在邻图时由 StartPath 包装桥接。**点击重放 + 公共层天然覆盖**。
- **designation 前置型（挖矿族）**：选项判定读的是 **`pawn.Map` 的全局状态**（designationManager
  的标记列表）——`MineAIUtility.PotentialMineables`（MineAIUtility.cs:23-24）枚举 pawn 所在图的
  Mine 标记生成"可下令矿石清单"，点击的矿石不在清单里 → **选项根本不出现**。pawn 没动（点击重放
  只换 context，不换 pawn），虚拟传送只在我们显式括号包裹时生效。

挖矿还伴生两个独立子系统边界：

1. **标记创建**：采矿设计器全链以 `Find.CurrentMap` 为轴——`Designator_Mine.CanDesignateCell`
   （L33 查 CurrentMap 界内）、`AddDesignation` 进 CurrentMap 的 designationManager。点击重放只
   重放右键浮菜单，不经手左键设计器 → 玩家没有任何手段在邻图渲染带上打标记。
2. **标记渲染**：`DesignationManager.DrawDesignations`（DesignationManager.cs:119-157）只被
   `Map.MapUpdate` 在 `Find.CurrentMap == this` 时调用（Map.cs:1162-1180）——邻图上已存在的
   标记结构性不画（Cell 型走 instanced 批量路径 L128-147，逐条路径的视区裁剪/绘制见 L149-155）。

## 二、job 类型适配矩阵（全 52 provider 审计）

判定轴：选项判定读 `context.map`/`t.Map`/`sleeper.MapHeld`（目标侧）= 可用；读 `pawn.Map`
（下令者侧）= 断裂。

### A1. 直接目标型（~35 个 provider，天然可用）

判定只看目标属性（CanReach/CanHitTarget/载重/敌对），或 targetB 搜索在被点击者图上（FindBedFor
的 `sleeper.MapHeld` 模式，RestUtility.cs:282/311 是库内现成的正确范式）。代表：
DraftedMove(Goto)/DraftedAttack(AttackStatic,AttackMelee)/Equip/Wear/Strip(drafted)/PickUpItem/
Ingest/DraftedRepair/DraftedTend/Arrest/Capture/Rescue（床搜索走 sleeper.MapHeld ✓）/
CarryPawn/CarryingPawn 全族（targetB 均 clicked 侧）/CarryMechToCharger/Trade/Mechanitor/
EnterMapPortal/Open(drafted, L28 读 clickedThing.Map ✓)/Train 等。

**执行期安全性（B 组时序审计结论）**：
- Reserve 错图记账窗口 = 0 tick：下单→StartJob→SetupToils→首个 toil initAction（Goto 的
  StartPath）→包装打断，全程同步（Pawn_JobTracker.cs:336-378、Toils_Goto.cs:16-24）；
- 释放必然正确：`Pawn.ClearReservationsForJob` 遍历 Find.Maps 释放每张图的全部五类 manager
  （Pawn.cs:2788-2821）；
- FailOn 无提前击杀窗口：打断发生在首个 toil initAction 内，早于任何 FailOn 的首次 per-tick
  评估；playerForced job 统一 ignoreDesignations（双保险，Mine 的 designation FailOn 不误杀）；
- 传送后重启幂等：同一 Job 对象重跑（driver 局部状态归零重来，targetQueue 型续队列），
  重记 Reserve 时 pawn.Map 已是邻图（记账在正确图）；携带链（救人/搬尸）driver 自带
  "已携带则跳过拾取"Jump，幂等成立。

### A3. split-target 型（6 个——targetA 在邻图、targetB 搜在本图 → 跨图劈裂）

| Provider | 错乱点 | 失败模式 |
|---|---|---|

A3 的修复点在选项 action 的 **targetB 搜索侧**（改搜被点击者图，同 FindBedFor 模式），不在公共层；

### C. RimExodus 自身路径清点（无冗余）

玩家下令恰好两条互斥入口：① `Patch_DraftedMove_PawnGotoAction_CrossMap`（一切移动语义——原版
全部 goto 入口已验证收敛于 DraftedMove.PawnGotoAction：单选 action L43 / 控制器 L155 /
Selector.cs:816 / 快捷建筑）；② `Patch_Pawn_PathFollower_StartPath_CrossMap`（一切非移动
playerForced job）。互斥性：① 吞掉原生（跨图 Goto job 不产生）；桥接 TransitGoto 目标是本图
spot 不会再进 ②。NPC 侧（撤离链/追击/跟随/即席战斗登记）独立成链不与玩家链共享下发器，设计内分工。

## 三、后续方向（本轮未做，三档）

1. **右键直达（小）**：让 Mine 族选项对邻图目标出现并在下令时自动落 designation——
   `MineAIUtility.PotentialMineables`/`JobOnThing` 在点击重放窗口内改为目标侧枚举/虚拟传送括号
   （重放域限定，防 JobGiver_Work 自动扫描误接单）+ 下令时自动 AddDesignation（邻图）。
   两处小 patch，不支持拖框批量标记。
2. **完整 designator 跨图（中，VMF 规模）**：在 1 基础上 patch 设计器链（Designator.Map getter /
   CanDesignateCell / DesignationDragger / DesignatorManagerUpdate，VMF Patches_Designator.cs
   全套参照）——采矿设计器可直接在邻图渲染带拖框标记/取消，与本图 UX 完全一致。
3. **标记渲染（可与 1/2 独立做，小）**：`SeamlessTileRenderer` 新增 DrawNeighborDesignations
   （仿 DrawNeighborPawns 模式：遍历邻图 designationManager，Cell 型 instanced 批量、Thing 型
   逐条，+offset 平移、MetaOverlays 高度、立即绘制不进 CommandBuffer）——邻图已有标记（如切图
   去标的）本视图可见。

**自动执行范围（用户定夺 2026-08）**：仅玩家点击下令——本图 pawn 不自动接邻图标记的活。
若将来要"标记后自动跨图干活"，需 VMF 式 JobGiver_Work 跨图扫描（搜索集合并入邻图 + 虚拟传送
验证 + 搬运入库路由），大工程，另行立项。

## 四、敌人跨图索敌断链（2026-08 已修复，此处存档根因）

索敌成功但 job 生成失败的三断点（按证据强度）：
1. **主断点（已修）**：`JobGiver_AIFightEnemy.TryGiveJob`——Wait_Combat 捷径要求"掩体旁
   （CalculateOverallBlockChance 混算坐标）或 <5 格（位置差 ~200+ 格恒假）"，fallback 的
   CastPositionFinder 射击位搜索在错误坐标系全灭 → null → 敌人不还击。修复 =
   TryGiveJob Postfix（可射的跨图目标 → 原版构造的 Wait_Combat，开火链交给已跨图化的
   CheckForAutoAttack）。
2. **伴生（已修）**：`ShouldLoseTarget` 对跨图目标每 tick 判丢（CanReach 安静 false + 混算距离
   > keepRadius），400 tick 宽限失效。修复 = Prefix 以"当前可射"作保持判据。
3. **观察项（未修）**：CastPositionFinder 跨图走位候选（走位质量提升项非功能缺口）。
近战敌人不适用远程索敌兜底（跨图无远程手段，走既有追击链/战斗踩点设计）。

### 第二轮断链（2026-08 已修复，此处存档根因）

索敌成功、推进 job（GotoNearestHostile 跨图版的 Goto(目标 thing)）也成功下发，但桥接识别失效：

4. **主断点（已修）**：`ThinkNode_Duty.TryIssueJobPackage`（反编译 ThinkNode_Duty.cs:24-29）把
   think tree 产出的 job 的 `dutyTag` **无条件覆写**为 `duty.tag`（AssaultColony 等 duty 无
   tag → null），旧判据 `job.dutyTag == NpcApproachTag` 在 StartJob 前即失效——**推进 job 从未
   被桥接**。日志特征：`Cross-map approach` 后无任何 `Bridge issued`/`Cross-map move rejected`
   （`TryBridgeJob` 根本没被调用），敌人在本图坐标上走向目标本地格的镜像数字格（方向都不对）。
   修复 = StartPath 桥接识别改结构判据（非 playerForced 的 Goto 且 targetA Thing 在邻图——
   原生 giver 的 CanReach 对跨图 NPC 安静 false，这样的 job 只可能来自我们的推进 patch）+ 删除
   NpcApproachTag。教训：**job.dutyTag 不能作为 think-tree job 的自标识通道**（TransitTag 幸存
   只因其 Goto 走 StartJob 直发不经 think tree）。
5. **伴生（已修）**：MarkPursuers 只认 Attack 系 job / mindState.enemyTarget，GotoNearestHostile
   推进期两者皆无（原版此阶段不设 enemyTarget）→ 目标跨图返回瞬间推进中敌人零追击。修复 =
   意图判据补「非 playerForced Goto 的 targetA=跨图者」。
6. **伴生（已修，防修好 4 后必现的"过缝秒退"）**：Bridge 落地 NPC 战斗体与 Pursue 落地同构
   （TryTransferPawn 剥离原 lord），不收编则续跑 job 过期后 JobGiver_ExitMap 直接离场。修复 =
   `NotifyPawnTransferred` Bridge 分支对 IsNpcCombatant 先 TryAttachAssaultLord、失败登记游荡宽限。
