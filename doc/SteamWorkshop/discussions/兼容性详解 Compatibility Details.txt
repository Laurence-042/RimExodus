----------------------------------------------------------
核心修改点 / Core Modifications
----------------------------------------------------------

本 Mod 导致兼容性降低的核心修改点主要是以下几点：
The core modifications that may reduce compatibility are mainly the following:

1. 添加额外的地图生成步骤来将地图切成六边形（在那 12 个五边形地块上则切成五边形），并使生成的地图在接缝上与先前的地图地形融合。
Adds extra map generation steps to cut maps into hexagons (pentagons on the 12 pentagonal world tiles), and blends terrain at the seams with previously generated maps.

2. Patch 了一些射击行为（投掷手榴弹也包含在内），允许跨地图射击（可关闭，关闭后不会有跨图战斗）。
Patches certain shooting behaviors (including thrown grenades) to allow firing across maps. (Can be disabled; when disabled, there is no cross-map combat.)

3. 创建了新的地图生成器管线：生成没有 POI 的地图（普通地块——派系基地、机械师遗迹、强盗营地、污染源地点等以及一切使用地点（site）机制的 Mod 内容不在此列）时使用分帧地图生成，避免地图生成期间卡死无法操作（可关闭，关闭后所有地图都走原版地图生成器管线）。
Creates a new map generation pipeline: maps without POIs (plain tiles — faction settlements, ancient mechanic complexes, bandit camps, pollution sites, and any mod-added content using the site/POI mechanism are not included) are generated frame-by-frame, so the game stays responsive during generation. (Can be disabled; when disabled, all maps use the vanilla generation pipeline.)

4. 在 pawn 所在地图格上生成一个隐形的、不会被袭击的、与 pawn 对应的影子远行队，用来在派系基地中与贸易商交互时提供完整远行队上下文。
Spawns an invisible, raid-immune "shadow caravan" matching your pawns on their current tile, providing full caravan context when interacting with traders at settlements.

本 Mod 做无缝的机制本质上是使用类似 Vehicle Map Framework 的技术，在当前地图周围渲染可以互动的邻居地块的地图，并允许 pawn 在接缝上通过隐形的传送点互相传送。
Under the hood, the seamless mechanism uses technology similar to Vehicle Map Framework: neighboring tile maps are rendered around the current map and remain interactive, and pawns cross the seams via invisible teleport spots.

从这些修改点就能大致判断其是否与某个 Mod 不兼容，以下是一些示例：
From these modifications you can roughly judge compatibility with any given mod. Some examples:

----------------------------------------------------------
做了额外适配后兼容 / Compatible After Extra Adaptation
----------------------------------------------------------

Combat Extended：CE 的战斗行为与原版不走同一条路，跨图射击需要单独适配，现已完成——普通枪械、手雷、迫击炮、瞬发射线、制导弹、CIWS、压制射击与能力发射路径均可攻击相邻地图，角色与自动/手动炮塔会跨图索敌；射程、视线、掩体、烟雾、光照、散布、弹道、碰撞与爆炸仍按 CE 规则在真实地图上计算。同一张地图内的战斗完全走 CE 原生逻辑；CE 世界炮击继续使用其原生流程。
Combat Extended: CE's combat follows a different code path from vanilla, so cross-map shooting needed a dedicated adaptation — now done. Ordinary firearms, grenades, mortars, instant rays, guided projectiles, CIWS, suppression fire, and ability-launched projectiles can engage targets on adjacent maps, while pawns and automatic/manual turrets acquire cross-map targets. Range, line of sight, cover, smoke, lighting, dispersion, ballistics, collision, and explosions still use CE rules on the actual maps. Combat within a single map goes entirely through CE's native logic; CE world shelling keeps its original flow.

Vanilla Landmarks Expanded：除了改地图大小的地标外，其他地标都正常走 Odyssey 提供的机制，应该都适配。
Except for landmarks that change map size, all landmarks use the mechanism provided by Odyssey and should be compatible.

Geological Landforms：它虽然用正常的地图生成步骤生成地图，但额外 patch 了原版地图生成器管线，所以最初不兼容。考虑到用户较多、体验确实好，做了额外适配，河流地貌也已适配——河流会跨过地块边界连续流动，不再需要在 GL 设置里手动关闭。已知边界：合流（River Confluence）/ 河源（River Source）类地貌的河道起点与下游端的接缝处可能残留小幅错位。适配只对新生成的地图生效；旧档里已生成过的地图不变。
Geological Landforms: it generates maps through normal generation steps but additionally patches the vanilla map generation pipeline, so it was initially incompatible. Given its large user base and the real improvement it brings, extra adaptation was done — river landforms included: rivers now flow continuously across tile borders and no longer need to be disabled manually in GL's settings. Known edge: river confluence / river source landforms may still show slight misalignment at the seam near their upstream/downstream ends. The adaptation only affects newly generated maps; already-generated maps in old saves are unaffected.

MapPreview：本来就需要添加额外地图生成步骤的 Mod 主动适配，本 Mod 已正常适配。
This mod requires active adaptation from mods that add extra gen steps; RimExodus has adapted to it.

Vehicle Framework / Vehicle Map Framework：多格载具的寻路机制与单格 pawn 有差异，需要额外适配跨图移动行为。
Multi-cell vehicle pathing differs from single-cell pawn pathing, so cross-map movement needed extra adaptation.

Perspective Shift：其主控 pawn 的移动不是原生的移动命令，需要额外适配其移动方式。
Its player-controlled pawn doesn't use vanilla move commands, so its movement needed extra adaptation.

Giddy-Up 2 - Continued：骑乘状态与跨图传送是两套独立机制，骑手跨缝时需要额外适配。现在坐骑会随骑手一同过缝，并由 Giddy-Up 自己的即时骑乘逻辑在落地图重建骑乘关系。
Mounted pawns and cross-map transfer are separate mechanisms, so riders crossing a seam needed extra adaptation. Mounts now cross together with their riders, and Giddy-Up's own instant-mount logic rebuilds the mount on arrival.

Vanilla Gravship Expanded：其世界炮击弹丸自带"离开发射图 → 世界地图 → 目标图"流程，与无缝接缝的弹道交接有冲突，已单独适配保留原生流程，远程火炮向其他地块开火时不再卡在发射图边缘。
Its world-artillery projectiles have their own "leave the firing map → world map → target map" flow, which conflicted with seamless seam projectile handoff; a dedicated adaptation preserves the native flow, and long-range artillery firing at other tiles no longer gets stuck at the firing map's edge.

Vanilla Expanded Framework 的地图物体刷出（ObjectSpawns，含 Vanilla Vehicles Expanded 的载具残骸、Dark Ages / Mythic Ages 的巢穴等一切基于此机制的内容）：刷出位置现已被限制在实际可玩的六边形区域内（不再落到边界外看得见够不着的 void 区），分帧生成的地块图上也会正常刷出。
Vanilla Expanded Framework's map object spawning (ObjectSpawns — including Vanilla Vehicles Expanded wrecks, Dark Ages / Mythic Ages nests, and anything else built on this mechanism): spawn positions are now restricted to the actually playable hexagon area (no more landing in the unreachable void beyond the border), and frame-sliced tile maps receive these spawns too.

天生兼容 / Naturally Compatible
----------------------------------------------------------

闪毁（Glitter World Destroyer）等 Mod 加的任务点：本质上仍走可进入地点（site）的机制，进入逻辑也没有特殊之处，所以天生走生成 POI 时的原生地图生成器，不会有兼容问题。
Quest sites added by such mods still use the enterable-site mechanism with nothing special in their entry logic, so they naturally go through the vanilla generator used for POIs — no compatibility issues.

金鸢尾兰等 Mod 加的外交选项：本 Mod 的派系基地贸易商对话选项复用远行队选项，所以外交选项会正常出现；且因为确实有影子远行队，外交流程能完整走完并收到花糕。
Diplomacy options from such mods appear normally, because the trader dialog reuses caravan options; and since a shadow caravan really exists, the diplomacy flow completes fully — flower cake included.

----------------------------------------------------------
天生单图兼容 / Naturally Compatible Within a Single Map
----------------------------------------------------------

各种 Fog of War Mod：迷雾只在聚焦地图上渲染，简化邻接地图渲染不会被影响。
Fog only renders on the focused map; the simplified neighbor rendering is unaffected.

各种小地图 Mod：只显示聚焦地图的小地图，邻接地图技术上不在当前地图内，自然不会被显示。
Minimaps only show the focused map; neighbor maps technically aren't inside it, so they simply aren't shown.

----------------------------------------------------------
不兼容 / Incompatible
----------------------------------------------------------

RimSkyBlock 之类的空岛 Mod：简单来说，没有非常硬性的不兼容，但可能有各种不符合预期的渲染、天气表现。严格来说，RimSkyBlock本身有一个保护机制来避免清除RimExodus的关键设施，使RimExodus的无缝加载、移动在空岛上仍能起效。但同时也会导致其留下空心六边形的地基框架，而且其空岛移动机制也会破坏RimExodus的“地图和世界地块一一对应”的假设，导致出现各种预期之外的问题。RimExodus不承诺可以解决这些问题，所以将其视为不兼容。因为如果考虑地图脱离地块移动的场景，很多简单高效的逻辑都不得不做得臃肿低效。不过考虑到并非硬不兼容，所以没有将其和 As above, So below 2 一样在mod元信息里标注为不兼容。
Sky-island mods such as RimSkyBlock: in short, there is no hard incompatibility, but you may see various unexpected rendering and weather behavior. Strictly speaking, RimSkyBlock itself has a protection mechanism that avoids removing RimExodus's key infrastructure, so RimExodus's seamless loading and movement still function on sky islands. However, this also leaves hollow hexagonal foundation frames behind, and its sky-island movement mechanism breaks RimExodus's assumption of a one-to-one mapping between maps and world tiles, causing all kinds of unexpected problems. RimExodus does not promise to fix these, so it is treated as incompatible — supporting maps that detach from their world tile would force a lot of simple, efficient logic to become bloated and slow. That said, since it isn't a hard incompatibility, it is not flagged in this mod's metadata as incompatible like As above, So below 2.

As above, So below 2：它需要生成一个巨大的地图并切分为表示各个高度层级的区域，会把本 Mod 的六边形裁坏；且本 Mod 没有可行方案在适应其切分行为的同时保证地图过渡生成平滑。但因为 MultiFloors 使用完整的口袋地图作为层级，不动基础地图的生成，所以是适配的。
It generates one huge map and splits it into altitude-layer regions, which breaks this mod's hexagons; and there is no feasible way to accommodate its splitting while keeping seam generation smooth. MultiFloors, however, is compatible: it uses full pocket maps as its layers and doesn't touch base map generation.

----------------------------------------------------------
简单判断规则 / Quick Rules of Thumb
----------------------------------------------------------

1. 如果一个 Mod 只是影响生成中的地图内容，那么应该适配；但如果它还 patch 了原版地图生成器本身，则不做特殊适配时需要关掉本 Mod 的分帧地图生成开关才能兼容。
If a mod only affects map content during generation, it should be compatible. But if it also patches the vanilla map generator itself, you'll need to turn off this mod's incremental generation option (unless specially adapted).

2. 如果一个 Mod 大幅修改已生成的地图或重新解释地图机制，而不只是在生成中影响地图内容，那么不适配。
If a mod heavily modifies generated maps or reinterprets map mechanics (rather than just affecting content during generation), it is not compatible.

3. 如果一个 Mod 只是添加 POI，那么天然适配。
If a mod only adds POIs, it is naturally compatible.
