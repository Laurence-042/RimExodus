# 兼容层注册审计（2026-10-30）

## 结论与范围

审计覆盖 RE 的 `Source/Compat/`、Mod 构造器与手动原版补丁，以及 REF 的公共模块、MapPreview 与 CE 注册入口。此次故障暴露了注册边界和验证覆盖的真实缺口：自动扫描、手动绑定、延迟执行必须分别核对。现有“原版补丁自动注册、可选 Mod 软反射注册”的基本分工可以保留，但只验证构建或签名不足以确认启动成功。

REF 原实现逐个把所有类型交给 `CreateClassProcessor`，连无 HarmonyPatch 标记、只有 Prefix/Finalizer 同名方法的手动辅助类也被处理。RE 使用 `Harmony.PatchAll`，本轮已用实际 Harmony 执行整套扫描验证，其手动辅助类没有发生同类误收。REF 已限定自动集合为显式 HarmonyPatch 类型，并将 CombatPatch 类型排除到独立战斗安装入口。

本轮对第三方适配器的检查主要是源码与注册路径审计；测试明确区分实际游戏方法绑定、模拟 API 的故障注入和第三方 Mod 实机功能，不能把这些结果互相替代。

## 已修复问题

| 问题 | 修复及验证 |
| --- | --- |
| REF 自动扫描误收 MapPreview 手动钩子，导致整个框架初始化失败 | 公共与战斗自动集合都要求 HarmonyPatch 标记；实际公共安装循环绑定 29 个游戏方法 |
| RE MapPreview 在第一次访问时永久缓存空反射结果，Lunar 延迟加载后仍被判断为缺失 | 缺失查询随程序集加载事件失效；事件线程只置脏，查询时解析；成功后缓存 bool 委托，签名或 getter 异常只告警一次并禁用此判定。模拟 API 验证缺失、晚加载、全局/线程标志区分、签名变化与 getter 抛错 |
| REF MapPreview 手动注册没有重复调用保护，类型查询在 try 之外 | 查询纳入保护；成功幂等，类型未加载时允许后续显式注册重试，确定失败后不重复刷错；模拟目标验证 Prefix/Finalizer 各只绑定一次 |
| RE/REF CE 的延迟炮塔与 CIWS 注册中，反射参数求值可能在 TryPatch 之前抛错 | 在真正执行延迟回调的位置分别保护两组注册；禁用状态不继续执行。对两个实际适配器注入歧义方法，验证异常不逃逸、不污染其他绑定 |
| RE 六处原版手动绑定中，多处查找或 Harmony.Patch 异常会中断构造器 | 集中到 `SeamlessPatchBinding.TryBind`，查找也在保护内；显式重载、核对具体回调所有权、逐项日志，失败后继续其他绑定。六处实际游戏目标及缺失/查找异常路径均验证 |
| RE 启动补丁计数早于手动原版补丁与 CE 延迟绑定 | 报告移到长事件收尾；后续 GL 生成入口补注册仍单独记录，不伪称启动报告覆盖未来事件 |
| GL 上下文解析失败被吞掉；VGE 静态反射解析无保护和字段类型校验 | GL 缺少必要成员时一次告警，保持不可用；VGE 在静态构造器内保护并校验实例 PlanetTile 字段，失败只关闭该检测 |
| 部分注册成功的日志容易被当作全适配成功 | VF 少于 5 个钩子明确告警；CE 汇总只表示注册流程结束，能力以逐项日志为准；GL 不再把部分失败描述为全部恢复原生 |

## 验证结果与限制

新增入口：`just test-compat`。使用标准 SDK 构建 REF→RE 后，在独立控制台进程运行：

- legacy：23 项检查，实际绑定 171 个游戏方法，另有 1 个 MapPreview 模拟目标。
- REF：25 项检查，实际安装 REF 公共/战斗与 RE 自动/手动集合，绑定 194 个游戏方法，另有 1 个模拟目标；验证 legacy 战斗回调不重复安装。
- MapPreview 签名变化独立进程：9 项检查。
- REF 既有 `just test-ref`：180 项检查通过，其中公共安装绑定 29 个游戏方法。
- 1.6 旧 PatchAll 验证器已尝试，仍因原路径缺少 Assembly-CSharp/UnityEngine 而失败；这不是新的补丁绑定结论，也不能沿用旧计数充当本次通过。

离线测试只安装方法补丁，不运行地图、外部 Mod 初始化、游戏 UI、GPU 或存读档。未使用真实 CE/GL/VF 等组合对全部反射成员重新验收；真实版本变更仍可能导致逐钩子告警或功能降级。尤其是成组能力的部分成功、MapPreview 注册时序与两后端切换，需要游戏启动日志和功能矩阵确认。

施工依据为 `_references` 已有材料：原版反编译 AssemblyVersion `1.6.9438.38202`（用于原手动补丁签名），MapPreview 源项目标记 `1.12.26`、Lunar 入口及 GeneratePreview 源码，VGE Projectile_Artillery 源码；1.7 绑定使用当前构建配置的实际游戏程序集。模拟 API 仅验证失效策略，不代表目标 Mod 的 1.7 支持认证。

## 后续维护规则

自动注册只收明确声明的补丁类；手动兼容函数即使名为 Prefix/Postfix 也必须留在手动路径。延迟注册的 try/catch 必须包住回调实际执行和参数解析，而不能只包住入队。支持重复调用的入口必须防重复挂钩；仅启动一次的入口不要无条件加入重试循环。

兼容结果至少区分“未安装”“类型尚未加载”“成员不匹配”“部分钩子已绑定”“绑定全部成功但功能待实测”。缺少可靠外部参考时保留验证边界，不按猜测改第三方行为。后续 REF/legacy 统一切换完成前保留两套 CE 执行器，用共同回归防止修复只落在其中一侧。
