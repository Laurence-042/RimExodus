# 地图滚动休眠（软休眠模型）

> 状态：已实现，游戏内回归进行中（2026-08）。
> 本文是地图滚动生命周期的权威文档：休眠 / 唤醒 / 删除三态与自动调度策略。

## 一、设计定夺（用户决议 2026-08）

**软休眠模型**：休眠图的 **Map 对象保留在 `Find.Maps` 中不卸载**，照常随档全量序列化
（存档零额外机制——建筑/物品/地形完好，"不丢东西"由模型本身保证）。休眠只意味着：

1. **不 tick**（冻结模拟：组件、天气、植物、动物、火、电力全部停）；
2. **不作为邻接地图显示**（渲染不画其背景、跨图菜单/传送点对其关闭，视觉上回到 void 清色帧）；
3. **无地图访问入口**（顶部殖民者栏的地图分组框不显示——原版 `CheckRecacheEntries` 遍历
   Find.Maps **每图一组**、无 pawn 也画空分组框（可点击切图），需 `Patch_ColonistBar_CheckRecacheEntries`
   Postfix 从 cachedEntries 移除休眠图 entry + 重编 group（重编必须用构造器重建 entry——Entry 的
   reorderAction 闭包捕获构造时 group，直改字段会使拖动跨组排序写错组）；Sleep/Wake 收尾调
   `MarkColonistsDirty` 立即生效。注意：休眠图上的殖民者尸体 entry 也随之隐藏（图不可访问，
   与"点不进去"一致）。世界地图"查看地图"gizmo 保留为显式唤醒入口）。
   **可选空组过滤（2026-08 增，默认关 = 原生行为）**：PlaySettings 全局控制条 toggle
   （`Patch_PlaySettings_ColonistBarToggle`，与接缝带开关同族）控制 `hideEmptyColonistBarGroups`
   ——开启时同 patch 追加移除"非玩家家且无玩家 pawn"的活跃图整组（口径与 AllIncidentTargets
   过滤②一致；玩家家含空家保留 = 原版"空家仍显示"语义）。toggle 前后比较字段值并
   `MarkColonistsDirty` 立即生效（ToggleableIcon 走 ref 无回调）。

- **唤醒** = 下次进入休眠地图时（同步、轻量：恢复 tick 注册 + 恢复邻接显示 + 恢复入口，
  无重新生成、无分帧）。
- **删除** = 彻底删除（地块图：`RemoveTileMap` 销毁 Map + WorldObject；原生家族：
  `RemoveNativeFamilyMap` 延迟执行原版删除偏好），下次进入时重新生成。
- **距离策略**（源 = 所有玩家阵营 pawn 所在图 **∪ 玩家阵营远行队所在 tile**，世界网格 BFS 拓扑距离。
  2026-08 修复"全员远行 → 源空 → BFS 距离表全空 → 全部管辖图按无穷远误删"的结构性炸弹：远行队
  计入源（用户原则"距离对全部 pawn 成立"——远行队里的 pawn 也在世界网格上占 tile）+ 空源守卫
  （无任何玩家 pawn 的异常态本轮不睡不删）。每轮现算、无维护状态——源每刻在动，预算好的距离表
  写完即过期。pawn 变动即时触发：跨缝传送完成 / 远行队组队离图（`Notify_CaravanFormed` Postfix）/
  远行队进图三类事件调 `SeamlessPawnLocationTracker.NotifyChanged()`（2026-08-29 收拢进统一底座，
  原 `RequestSweepSoon` 已删——影子远行队与地图休眠共享触发与更新机制，见 2.14；只置脏旗标，
  下一 GameComponentTick 位置刷新段执行——不在事件回调里直接睡/删图/拆影子，Sleep 摘全局
  tick 表落在 thing tick 遍历中途不安全）；周期兜底
  （间隔设置化 2026-08：`dormancySweepIntervalTicks` 默认 600，UI 以秒展示 1-60、
  运行时 clamp ≥60，每轮现读设置拖动即时生效）：
  - 图上有玩家 pawn → 永不休眠、永不删除（保护判据 = 仅玩家 pawn）；
    相邻图因玩家踏入自动距离 0，天然满足"相邻图不休眠，否则玩家可以跨图躲追击"；
  - **玩家家园（`IsProtectedHome` = 原版 `Map.IsPlayerHome`）→ 永不休眠、永不删除**（2026-08
    用户定夺，修复"全员离家 ≥2 跳家园被睡、入口消失"的缺口。覆盖开局家园/定居/逆重飞船降落
    产生的原生 Settlement 与建了引力引擎的图（含地块图营地）——家园特权判定全项目唯一行为
    消费点 = governor 保活分支）；
  - 距离 ≥ sleepHops（默认 2）→ 休眠；建筑和物品不会丢（只是不 tick）。
    **2026-08 距离放宽**：sleepHops 下限从 2 降为 1、deleteHops 允许与 sleepHops 相等
    （原为严格 +1）——性能不佳的玩家可 1/1 = "离开即休眠并销毁"；脚下安全仍由三条保活
    （CurrentMap / 玩家 pawn / IsProtectedHome）保证。原"下限 2 = 玩家跨图躲追击防线"论述
    随放宽降级为默认值的推荐理由（相邻图因玩家踏入自动距离 0，防线实际由 pawn 在场保活承担）；
  - 距离 ≥ deleteHops（默认 3，≥sleepHops）且可删（`CanRollingDelete` = 受管辖且非家园）→ 删除：
    **地块图**销毁 Map + WorldObject（"从未出现过"，下次进入走生成链重建）；
    **原生家族**（Settlement/Site/CaravansBattlefield/DestroyedSettlement，见 2.11）**延迟执行
    原版删除偏好**——删图时 WorldObject 是否连带销毁按原版 `ShouldRemoveMapNow` 的
    alsoRemoveWorldObject 判定（Settlement 删图留对象、CaravansBattlefield/DestroyedSettlement
    连对象删、Site 按 parts 语义）；
  - `Find.CurrentMap` 无条件保活（玩家正看着的图冻结会卡 UI）。
- **NPC 对端休眠语义**（撤离链/追击/跟随）：不唤醒、按"未加载"处理——撤离者踩 tier0 传送点
  原生离场（链终止）、追击/跟随许可作废跟丢。防 NPC 级联唤醒跑穿世界。
  玩家自己的跨图意图仍会唤醒（边界预加载带 + CurrentMap setter）。
- **自动 + Dev 手动**：`SeamlessDormancyGovernor`（GameComponent）周期调度；
  Dev 菜单提供手动 Sleep/Wake/Report/ForceDelete。

> 历史备注：设计文档曾规划"卸 Map、留 WorldObject"的硬休眠语义（`SeamStripData` 挂
> WorldObject 即其预埋）。2026-08 用户定夺改用软休眠（Map 不卸载）——预埋的 WorldObject
> 回落路径保留（`TryGetNeighborSeamStrip` 路径②），将来若做硬卸载仍零改动可用。

## 二、机制细节

### 2.1 停 tick 的两条腿（原版查证结论）

- **Map 方法拦截**：`TickManager.DoSingleTick` 直接遍历 `Find.Maps` 调 `map.MapPreTick()/MapPostTick()`
  （TickManager.cs:357-451），`Game.UpdatePlay` 遍历调 `map.MapUpdate()`。三方法均 public 非虚
  → `Patches_Dormancy` 三 Prefix 早退（与 `Patches_IncrementalMapGen` 同款模式）。
  MapComponentTick 在 MapPostTick 内、MapComponentUpdate 在 MapUpdate 内——跳过即全停。
- **全局 Thing tick 表**：原版 TickList 按 TickerType 分桶、**完全不按地图分组**——只跳过 Map
  方法停不掉图上 Thing。休眠必须 `Find.TickManager.RemoveAllFromMap(map)`（原版 API，
  MapDeiniter.Deinit 同款，按 `x.Map == map` 全摘）；唤醒时遍历 `map.spawnedThings` 逐个
  `RegisterAllTickabilityFor(thing)`（读档路径 `Spawn(respawningAfterLoad:true)` 即走此 API，
  语义等价"这张图像刚读档一样恢复"）。
- **时序安全**：governor 的 Sleep/Wake 发生在 GameComponentTick（DoSingleTick 的 MapPostTick
  循环之后）与 UI 事件（CurrentMap setter / StartJob Prefix），不会落在 thing tick 遍历中途；
  RegisterAllTickabilityFor 与原版"tick 中途 spawn"场景同源安全。

### 2.2 口径变化（全 mod 的"对端已加载"语义）

`SeamlessTileGraph` 三处加 `IsDormant` 过滤：`TryGetNeighborLinkByWorldTile` /
`PopulateNeighbors`（连带 `AreNeighbors`、`GetAllNeighbors`）/ `TryGetMapByWorldTile`。
休眠图虽在 Find.Maps，但邻接/已加载口径视为"未加载"。一处生效全局：

- 渲染器 cachedNeighbors 排除休眠图 → 零邻居清色分支接管背景；
- `CompSeamlessTileEnterSpot.ComputeAndCacheArrival` 走 link 查询 → `hasArrival=false`
  → 跨图菜单/传送自动关闭；
- 撤离链 `TryFindEvacuationExit` tier0 → 休眠对端 = 未加载 → 撤离者原生离场（Q4 决议零代码）；
- 传送许可 `HandleBoundTransfer/HandleEvacuation` 对端校验 → 休眠即跟丢/原生离场。

**例外——`TryGetNeighborSeamStrip` 刻意不过滤休眠**：它是数据查询而非邻接交互
（新图生成时接缝混合的参考数据），快照数据不因休眠失效（软休眠不销毁 Map，原生图快照挂
图组件仍在；地块图快照挂 WorldObject 两路同源——载体差异由 `SeamlessMapData` 屏蔽）。
消费方若需感知休眠图的存在（生成守卫防重复 WorldObject），直接查 `worldObjects.MapParentAt`。

### 2.3 唤醒入口（三处）

1. **`Game.CurrentMap` setter Prefix**（`Patches_Dormancy`）：一切"进入地图"路径
   （世界地图"查看地图"gizmo、殖民者栏组框点击、CameraJumper、跨图选中）都汇聚于
   此 setter——单点覆盖：目标为休眠图 → 先同步 Wake 再切图。
2. **边界预加载带**（`SeamlessBorderPreloader.CheckPawnGoto`）：玩家 goto 边界带且目标
   邻居休眠 → 同步唤醒（原本"已加载跳过/未生成入队"二分支中间插入休眠分支）。
3. **governor 兜底**：距离回落到活跃圈（< sleepHops）的休眠图唤醒——
   **对手动休眠锁定的图跳过**（见 2.12）。

### 2.4 生成守卫（防重复 WorldObject——会断点，勿删）

`SeamlessTileManager.GenerateTileMap`：`TryGetMapByWorldTile` 被休眠口径过滤后查不到休眠图，
但休眠图的 Map 和 WorldObject 都还在——入口处用 `worldObjects.MapParentAt` 查到休眠 parent 时
**Wake + 补登记邻居并返回**，绝不 `MakeWorldObject` 新建（否则同 tile 双 parent、邻居表分裂、
存档脏数据）。附带防御分支：WorldObject 在但 Map 不在（软休眠下理论不可达；历史
RemoveTileMap bug 曾残留隐形 WorldObject）→ 销毁残留后继续生成。

### 2.5 天气域与休眠的交互（2026-09 形态 B + 2026-09-02 注册制定稿，取代旧"字段替换共享实例"模型与一切"重算时推断激活"）

**现行模型（用户定夺，形态 B + 注册制）**：天气域 = 同群系连通区域中**有图**的成员集合。域内
**每张图保留自己的** WeatherManager/WeatherDecider/SkyManager 原生实例，共享的不是实例而是
**决策与事件**：
- **决策集中**：只有激活图的 `WeatherDeciderTick` 运行——被动成员被 `Patches_WeatherDomain` 以
  `Priority.First` 短路（连第三方 prefix 一并吞，预期行为：被动图没有决策过程；观察天气变化者的正确钩子
  TransitionTo/curWeather 对每图原生成立）。激活图的 `ForcedWeather` getter 原生读自己图的
  条件——旧"域内并集" patch 随之删除。激活后不回切（条件结束 getter 自然回 null）。
  **激活 = 注册制（2026-09-02 第三案，用户模型 v3，勿回退为重算推断）**：激活控制器是一份持久
  记录（`activeTiles` 集合，每域一条，随档保存），**不是重算派生值**。每张地图生成完成时**报到**
  （BindMap）：区域已有记录 → 新图被动 + 从激活图同步天气；区域无记录 → 登记区域、新图自己
  当选（**区域第一张图天然当选，无任何选择规则**）。记录只在三种事件变更，其余一律不动：
  ①报到；②**激活图停摆**（休眠[Sleep 钩子]/降频 0% 凝固[Throttle 钩子] = 等价休眠 → 还活着
  成员最小编号接任，交接 duration/禁雨窗口；全停摆不动，首个唤醒者接任；删除 → 重算清失效
  记录 + 无源兜底[最小编号 + 全新随机窗口]）；③**强制天气注册**（`RegisterCondition` Postfix
  识别 `ForcedWeather() != null` → 条件持有图接任[交接]）。读档重建 = 记录编号与重算区域做
  字面 in 判断。
  **历史三案教训（皆由"推断激活"产生，注册制下结构性不可能）**：①新图最小编号抢已有域激活
  且零交接（`Join: wt=14757 is the ACTIVE map` + `Gate: 41397 PASSIVE` 定案）；②新域首成时
  新图把随机 StartInitialWeather 复制给老图（10534 晴天冲掉 103177 暴雨，`normalized 1 member
  from self` 定案）；③三源解析/首成特判补丁链——推断本身是病灶，勿复活。
- **执行各图**：每图自己的 `WeatherManagerTick`/`SkyManagerUpdate` 照常跑——物理效果（雨湿地/
  积雪/毒性沉降）、闪电事件（eventMakers 各图独立掷骰）、环境音（map==CurrentMap 门）、
  CurSkyGlow（太阳能/植物光照按本图算）全部 per-map 原生正确。旧模型三类观察项就此根治：
  ①"物理效果只落钉死创图/宿主图"；②"CurSkyGlow 共享单值按聚焦图算"；③"创图删除后效果落
  幽灵图"。幂等守卫与 SkyManager 宿主跟随两个 patch 一并删除（每图 tick 自己的实例，无重复
  推进、视觉门天然成立）。
- **换天广播**：任一成员 `TransitionTo` → 同 tick 对域内全部成员（含休眠图，纯字段写无害）各
  TransitionTo 一次（`Priority.Last`——第三方取消型 prefix 先于我们执行，取消时广播不发生，
  全域一致）。`DisableRainFor` 同款转发。重入标志防递归广播（正确性单点）。

**持久化**：`activeTiles` = 记录本体（存档键 weatherDomainActiveTiles 沿用），运行时由三种事件
写入、随档保存；读档 FinalizeInit 重算成员结构后按 in 判断落位。各图 manager/decider 状态由
原版 per-map 序列化自然保存（广播保证本就同步）——旧模型"N 份相同快照选一份"的重绑语义废除。

**诊断埋点（2026-09）**：Rebuild（成员/激活落位来源 record-reporting-fallback/失效记录清除/新窗口）、
Join（报到：登记当选或被动同步）、Broadcast（换天转发目标列表与跳过原因）、
Gate 翻转（ACTIVE/PASSIVE，仅判定变化时一拍）、Activate（接任交接 duration/禁雨窗口）、
Suspend（停摆接任/全停摆冻结）、Resume 校准、DisableRain 转发、Save/Load activeTiles——全部走
`logWeather` 模块开关（分模块日志系统见 AGENTS.md 对应条目；天气 bug 定案记录见 doc/TODO.md）。

**与休眠/降频的交互**：休眠/降频图的 WeatherManagerTick 停/慢 → 本图 `curWeatherAge` 落后于
激活图（换天广播会归零自愈，两次换天间的漂移在 `Wake`/`Unthrottle` 经 `OnMapResumed` 从激活图
同步 cur/last/age 校准；激活图失效时由唤醒图接任——事件②补充检测点）。激活图休眠/0% 凝固 →
停摆通知接任（域继续演化）；激活图被删 → 重算兜底 + 全新随机窗口；全停摆 → 决策冻结，首个
唤醒者接任。

**历史（2026-08 旧模型，已废除勿回退参考）**：曾用"成员图三字段替换为宿主（域内最小 tileId
图）实例"的共享模型，配套幂等守卫（修 N 图重复推进 N 倍速）+ SkyManager 宿主跟随（修聚焦非
宿主图天空视觉冻结）+ ForcedWeather 域内并集（修 per-map 强制条件两态错乱）三 patch。2026-09
兼容性审计定性三类架构性缺陷（物理效果/闪电/环境音只落钉死图；CurSkyGlow 单值；幽灵创图），
重构为现行模型后三 patch 删除、缺陷根治。审计与形态 A/B 分叉论证见 AGENTS.md"天气域"条。

### 2.6 incident 目标过滤

`Storyteller.AllIncidentTargets` Postfix 剔除休眠图（返回的是原版静态缓存列表，调用方即用
即弃，原地 RemoveAll 安全）——防 storyteller 把袭击/事件打到冻结图上（pawn 同步 spawn 后
不 tick 站着不动，直到玩家回来）。`RandomPlayerHomeMap` 等消费面大的 getter **不 patch**
（误伤风险大于收益，见观察项）。

### 2.7 全局清扫迁移

三个静态清扫（`SeamlessSelectionTracker.PurgeInvalid` / `SeamlessTransferGrants.TickSweep` /
`SeamlessCrossMapOrders.PurgeInvalid`）从"仅家园图 MapComponentTick"迁至
`SeamlessDormancyGovernor.GameComponentTick`——家园无玩家 pawn 时可随软休眠冻结，
图组件 tick 不再可靠；GameComponent 恒 tick 与地图活跃状态解耦。

### 2.8 不序列化休眠状态

休眠集合（`SeamlessDormancyManager.dormantMaps`）是纯运行时性能状态。读档后所有图自动恢复
活跃（tick 注册由 FinalizeLoading 的重 spawn 完成），governor 首轮扫描（nextSweepTick=0
立即触发）重新收敛远图。因此不存在"读档时 CurrentMap 处于休眠"的窗口问题，也无需任何
存档迁移。

### 2.9 删除与 127 上限

删除统一入口 `RemoveRollingMap`（开头 `SeamlessDormancyManager.Forget(map)` 防集合持已
Dispose Map 引用阻碍 GC）：地块图 → `RemoveTileMap`（销毁 Map + WorldObject）；原生家族 →
`RemoveNativeFamilyMap`（见 2.11）。图量控制：活跃+休眠图 ≤ 以玩家为球心的 deleteHops 跳球
（默认 3 跳 ≤ 1+6+12+18=37 图），远离 `Game.AddMap` 的 127（sbyte）上限。

几何进程缓存随图删除释放（2026-09 泄漏收口）：`SeamlessTileManager.MapRemoved`
（一切删图路径的公共回调点——滚动删除/主动 `WorldObject.Destroy` 连带删图/迁都/Dev 均经
`Game.DeinitAndRemoveMap`，其在 `map.info.parent` 仍可读时回调，Game.cs:766-770）调
`SeamlessPolygonGeometry.ReleaseTileCaches(GetMapWorldTile(map))`——释放
`seamBandCache`/`polygonCache` 中该 tile 的条目（每条 `SeamBandInfo` 把全图格装进 7 个集合，
250 图推算 ≈4 MB/tile，不随图删释放则长会话探索数百 tile 无界累积）；口袋/空间图

### 2.13 分级休眠中间档：无玩家空图降频 tick（2026-08）

休眠模型从二值扩为三档：**活跃（全速）→ 降频（`SeamlessTickThrottle`）→ 休眠**。
降频接管"活跃圈内（BFS dist < sleepHops）但图上无玩家 pawn"的空图——即此前"醒着空转"
的那批图（典型：玩家跑图时周围 6 邻图常驻活跃）。设置 `dormancyThrottlePercent`
（默认 50；100 = 原生行为 = 功能关闭）。

**执行层跳 tick，注册表不动**（与 Sleep 的 RemoveAllFromMap 全摘是本质区别）：
- **thing 级**：`Patch_Thing_DoTick_Throttle`（`Patches_TickThrottle.cs`）Prefix 挂
  `Thing.DoTick`——原版三桶（Normal/Rare/Long）唯一的共同出口（`TickList.Tick` 逐 thing 调它），
  单点覆盖。热路径极简：集合空早退 → `thing.Map` 查集合 → 快速区白名单 → 相位取模。
  **Rare/Long 桶按调用序号门控（2026-08-27 两轮修正，勿删）**：这两桶的 DoTick 只在
  `(TicksGame % 250/2000)==hash` 的 tick 被调用——第一版相位门控（对 TicksGame 取模）与它
  gcd 混叠，同 hash 分野的 thing 永不命中 = 整个冻死；第二版整体豁免又被实测否决
  （0% + fastZone 0 下 calls 不降：野外图数万植物全是 Rare 桶 ~15k calls/window，违背
  "0% = 全图凝固"）。定稿 = 对 `t / bucketInterval`（调用序号，每次调用严格 +1）取模——
  无混叠，每个 thing 恒好每 N 次调用放行 1 次，0% 全冻结。
- **图级**：`Patches_Dormancy` 的 MapPreTick/MapPostTick Prefix 扩三态——降频图按**同一相位
  谓词**放行（Pre/Post/ThingTick 必须同拍，防 haulables/powerNet 与 thing 状态错位）。
  `MapUpdate`（每帧）**照常放行**——降频图仍作为邻图可见/可渲染，动画插值冻结属预期；
  tick 相位谓词不适用于每帧方法（会造成渲染抖动），勿并入。
- **相位**：每 N tick 放行 1 tick，`N = ceil(100/percent)`（50→2、25→4）；percent=0 →
  永不放行 = "可见的凝固"（等价休眠但保留显示与 tick 注册，此时 Throttle 时顺手结束该图
  声音 sustainer 防幽灵音——MapPostTick 被跳、天气 ambientSustainer 无人推进）。相位偏移用
  `map.uniqueID` stagger，防多张降频图同拍集中放行造成周期性尖峰。

**接缝快速区（空间分区，`throttleSeamFastRadius` 默认 15，0 = 关）**：降频图内距接缝边
≤ 半径的格（`ComputeVoidBand` 构建，与预加载带/禁建带同源几何）内 thing **全速** tick——
跨缝战斗的 turret/投射物/追兵不吃降频；区外按相位跳。**图级系统（powerNet/天气/野生生成，
走 MapPostTick）不分区**——整图同相位（功率网/天气是图全局语义，硬拆风险高；已知限制）。
快速区在 Throttle 时构建一次；Sweep 每轮幂等重入，半径设置变更时自动重建。

**状态归属与收敛**：`throttledMaps` 运行时集合（不序列化，读档后 governor 首轮 Sweep 重新
收敛——与休眠状态同口径）；`SeamlessDormancyGovernor.Sweep` 的活跃圈分支是唯一常态入口
（d ≥ sleepHops 走 Sleep、保活分支/`!enabled`/100% 都 Unthrottle）。**即时解除入口**（不等
下轮 Sweep，防玩家落图后 ~600 ticks 内走走停停）：CurrentMap 切图 Prefix / 跨缝传送
`AfterTransfer` / 远行队进图 `Patches_CaravanEnterMap` / 边界预加载带 `TryWakeByWorldTile`
（降频分支）。Sleep/Wake/Forget 全部联动清降频（三档互斥）。

**语义（重要，写进设置 tooltip）**：跳 N-1 跑 1 = "远处世界变慢"而非"省着跑"——
`TicksGame` 差值型逻辑（腐烂/计时）在放行 tick 自我校正速率，每 tick 累加型逻辑慢 N 倍。
Pawn 一并降频（用户定夺 2026-08）。1.6 原版视野外降频（`GenTicks.GetCameraUpdateRate`：
非当前图 thing UpdateRateTicks=15 + `TickInterval(delta)` 按累计 delta 缩放）是同族官方先例
——但该机制只节流 TickInterval 部分、Tick() 主体每 tick 照跑，所以整图降频仍需本层门控
（外层粒度 ≥ 内层，被跳的 tick 不累计 delta，速率型逻辑仍正确）。

**pawn 移动速率补偿（2026-08-27 实测修复）**：pawn 移动是**纯累加器**（
`Pawn_PathFollower.nextCellCostLeft -= CostToPayThisTick()`，每 tick 减、减穿换格，**无
TicksGame 差值补偿**）——整跳 DoTick 后放行 tick 也只缴 1 份成本 = 移动慢 N 倍（"降频图
动物变慢"实测症状；原版视野外降频不慢移动纯因它从不跳 Tick()，PatherTick 在每 tick 无条件
跑的 Pawn.Tick() 里）。修 = `Patch_PatherFollower_CostToPayThisTick_Throttle`（Postfix 挂
`CostToPayThisTick`，protected pawn 字段经缓存 FieldRef 读取）：放行 tick 缴 N 倍移动成本
（`SeamlessTickThrottle.MoveCostMultiplier`——快速区/非降频图恒 1 倍，防 N 倍速），平均格
推进速率回到满速。副作用（接受）：`cachedMovePercentage` 仅在放行 tick 刷新，邻图背景渲染中
pawn 动画按 N tick 一拍阶梯推进（50% 档基本不可感知）。

**热路径收口 + 0% 凝固摘 thing tick 表（2026-09-06，玩家实测定位，勿回退）**：实测判据 =
6 邻图全 0% 降频（things 全 skipped、pre/post 全 0）时，tick wall 仍比无邻图 +1~1.5ms/tick、
全部落在剖析器 unaccounted 桶——根因是**0% 凝固图 thing 的 DoTick 前缀链空转**：DoTick 的
Harmony Prefix+Postfix 调度与 `ShouldThingTick` 判定对每个被跳过的 thing 照跑（6 图约 620
次调用/tick × ~1.5µs；skipped 调用不计入 things 桶，故成 unaccounted）。修复两件：

- **热路径收口**：设置（percent/fastRadius/相位 N）由 governor `GameComponentTick` 每 tick
  刷新一次进 static 缓存（`RefreshSettingsCache`，滑条即时性损失 ≤1 tick）；
  `ShouldThingTick`/`MoveCostMultiplier` 从"每 thing 每 tick 两次设置读+Clamp +
  throttledMaps.Contains + fastRegions.TryGetValue 双查询"收敛为"单次 TryGetValue + static
  int 读"（原两集合合并为单 `Dictionary<Map, MapThrottleState>`）。
- **0% 摘表**：`Throttle` 进入 NeverTick 时把**快速区外**的 thing 逐个 `DeRegisterAllTickabilityFor`
  摘出全局 tick 表。这些物体的"跳过判定"结果恒为否，摘表是**纯等价变换**（连空转判定都省掉）；
  **快速区内 thing 刻意保留注册与判定**——0% 仍全速（跨缝战斗保护，turret/投射物/追兵不吃降频；
  2026-09 首版曾全摘误伤快速区，实测 fastRadius 0 未暴露）。显示/邻接口径不动（仍走活跃图
  路径、MapUpdate 每帧照常放行）——区别于 Sleep 的三件事全套。**摘/注册簿记三铁律
  （`TickList.RegisterThing` 无去重，双注册 = 活物双 tick）**：①摘表来源唯一标记
  `tickSuspendedMaps`；②恢复注册唯一实现 `RestoreThingTicks`（**先 RemoveAllFromMap 整图
  归零再全注册 = 幂等**——0% 摘表只摘了区外、区内 thing 一直注册着，直接补注册会双注册；
  含影子陈旧条目的 `t.Map == map` 过滤兜底）；③Sleep 调 Unthrottle 必须传 `restoreTicks:false`
  （图即将整表全摘，恢复无意义且会与 Wake 的重注册双注册）+ Unthrottle 恢复前查 `IsDormant`
  （图已休眠则注册归 Wake 独责）。Throttle 幂等重入条件从"仅 radius 未变"扩为"radius 与
  摘表态均未变"（0%↔50% 设置变更经 Sweep 重入时先恢复注册再按新相位重建）。

配套剖析器升级：unaccounted 拆桶为 world / gameComponents / other 三段（两个新计时 patch：
`Patch_World_WorldTick_Profiler` / `Patch_GameComponentUtility_GameComponentTick_Profiler`，
BOUND OK 基线 95→97——第三方 GameComponent 遍历全部地图的放大从此可归因）；状态标签
`throttled-frozen`——**该图快速区外 thing 的 calls 归零是预期**（DoTick 不再被调用；
fastRadius > 0 时残余 calls 全部来自快速区），勿误读为门控失效。残余待重测：当前图各桶
普涨 15-40%（同 calls 数耗时涨，疑 GC/CPU 缓存效应，7 图常驻内存所致），待摘表落地后重测归因。


### 2.14 统一 pawn 所在地追踪底座 + spawnedThings 完整性清扫（2026-08-29，玩家报告"pawn 同时在两个地点"的根治件）

**架构收拢（用户定夺）**：影子远行队与地图滚动休眠本质都是对 **"pawn 现在在哪张图/tile"这一事实的派生计算**（前者派生"据点图常驻远行队名单"，后者派生"BFS 距离与睡/删决策"）——两者共享同一个触发系统与同一个底层更新机制（`Source/Lifecycle/SeamlessPawnLocationTracker.cs`），只在派生逻辑处分别实现：

- **触发系统**：事件源全集（跨缝传送完成 / 远行队组队离图 / 远行队进图 → `NotifyChanged()`；删图 `Forget` → `NotifyMapRemoving(map)`）只认底座入口（原 `RequestSweepSoon` 已删）；事件回调只置脏旗标，绝不直接执行刷新（Sleep 摘全局 tick 表 / 拆影子改写 holdingOwner，不能落在 thing tick 遍历中途）。
- **更新机制**：governor `GameComponentTick` 内固定顺序的"位置刷新段"——①影子 `Maintain(dirty)`（事件即时名单同步 / 60t 轮询额外清扫注入副作用）→ ②休眠 `Sweep`（事件即时或自持间隔；**睡/删决策永远看到影子同步后的名单与清扫后的列表**）。
- **差异实现**：影子 = 期望集/成员同步/清扫 + 60t 轮询；休眠 = BFS 距离/保活/睡删 + 600t 轮询。

**根治对象——注入期 DeSpawn 的 spawnedThings 陈旧条目**（影子注入把据点图成员 holdingOwner 改指影子容器后，该 pawn 在据点图上任何 DeSpawn[跨缝走出 / 原版 SplitOff 抱起 / 死亡]中 `map.spawnedThings.Remove` 因 `ThingOwner.Contains` 指针判定 `item.holdingOwner == this` 失配而**静默失败**，innerList 残留删不掉的陈旧条目；零 Error 日志、读档自愈故难复现）。三个 innerList 直读消费者：

- **Wake 双 tick**：唤醒重注册遍历 spawnedThings——`TickList.RegisterThing` 无去重，陈旧条目把活在别图的 pawn 再注册一次（需求/衰老 2 倍速；Sleep 的 `RemoveAllFromMap` 按 Map 过滤摘不掉，一经发生即永久）。
- **删图索引漂移**：`MapDeiniter` 删图时对后续图逐条 `DecrementMapIndex` 补偿 Find.Maps 索引位移——陈旧条目给活人多减一次 → `pawn.Map` 指向错图（玩家报告"被计数在另一个 tile"：点殖民者栏头像相机跳错图、下令失灵；"重组远行队走到该 tile 进图"= 完整登记重写 = 玩家自救有效的原因）。

0. **事前闸门（2026-09-02 穿梭机登机消失案补，`Patch_ShadowCaravan_ReleaseOnDespawn`）：`Pawn.DeSpawn` Prefix 调 `ReleaseIfShadowMember`**——原版不变量 = pawn DeSpawn 前 holdingOwner 必须是本图 spawnedThings 或 null（原版 `Thing.SplitOff`/`Pawn.Kill` 的"DeSpawn 后 `holdingOwner?.Remove(this)`"先例）；Prefix 时 pawn 仍 Spawned → 释放归还本图容器，DeSpawn 本体的 `map.spawnedThings.Remove` 正常成功并清空 holdingOwner → 下述陈旧条目对一切 DeSpawn 路径（跨缝走出/SplitOff 抱起/死亡）**事前不发生**。追加动机 = holdingOwner 悬指影子期间任何"离图进容器"的原版路径都被 "already in another container" 拒绝：`JobDriver_EnterTransporter`（穿梭机登机，TryAdd 返回值被原版忽略 = pawn 离图又进不了舱，实测"登机即消失"、存读档即永久丢失）、`JobDriver_EnterCryptosleepCasket`（TryAcceptThing 同款）、`JobDriver_EnterPortal`（DeSpawn→Spawn 新图，Spawn 侧 TryAdd 同要求持有者为空）。纯容器簿记、thing tick 中途安全（不拆影子——拆除由下轮 Refresh 在 GameComponentTick 评估）；与 `Caravan.AddPawn` 释放 patch（2026-08-27 组队冲突案）幂等互备，二者保留互为双保险。

### 2.15 前哨保留：封存与重放（2026-09，M1+M2 一次落地）

**动机**：滚动删除对"玩家建造过但暂时离开的图"一视同仁地销毁——前哨/营地离开 3 跳即消失，建造心血丢失。本机制让**有居住区（Home area）的图到删除距离时不删，改为封存**：记录在案、拆图卸内存，再访时重生成 + 重放恢复。

**设计路线否决记录（四轮对话定案，勿重提）**：①整图序列化快照（blob 恢复）——跨引用重绑定/pawn 重复/loadID 管理三座手术 + 存档体积膨胀 + 冻结照片无法支持"离开期演化"，全部否决；②增量序列化——无原版机制，等于自研序列化器，否决；③age 判别器增量重放（只重放"生成后落图"的建筑）——玩家修改未占领遗迹墙体 / 本 mod 生成链调整挪动遗迹时会双份堆叠或漏恢复，否决。**定案 = 居住区字面区域 + 权威置换**：区域内记录是唯一事实（清除一切可拆物后恢复记录内容），区域外完全相信重生成。

**判定（语义唯一出处 = `Source/Lifecycle/SeamlessMapModificationTracker.cs`）**：居住区格数（`map.areaManager.Home?.TrueCount`，O(1)）与阈值（设置 `dormancyPreserveHomeAreaThreshold`，默认 20，0 = 任何非空居住区）比较——达阈 Auto / 非空小于阈 BelowThreshold（弹窗）/ 空 None（普通删除）。**用且仅用居住区、零膨胀**（用户定夺）：居住区随建造自动扩展、房间闭合自动填充，同时是玩家的显式控制手段（"画居住区 = 画保留区"）；自行膨胀会破坏精细控制者的预期。v1 范围仅地块图（营地自动覆盖），原生家族不纳入（Settlement 删图留对象/再访重生成驻军与整图恢复冲突，将来单独设计）。

**封存（governor 删除分支 → `ArchiveTileMap`）**：`ZoneMapRecord.Capture`（遍历居住区格，采建筑/屋顶/地板/物品四层**稀疏**记录——地板仅 Floor/基架不录土壤，"自然层相信重生成"；comp 级状态明确不保真）→ 挂 `MapParent_SeamlessTile.preserveRecord` → `DeinitAndRemoveMap` 拆图（pawn 善后与删除一致 = 进世界池，记录零 pawn 无重复问题）→ **WO 刻意保留**（与 `RemoveTileMap` 三差异：不销毁 WO / 不清邻居链 / 不释放 tile mesh）——邻居链跨档有效、封存期间邻图生成可经 `TryGetNeighborSeamStrip` 的 WO 回落读条带参考、世界图第四态。

### 2.16 活跃威胁保活：图上有活跃敌人时不降频（2026-09，用户定夺）

**语义（用户定夺，两层）**：①图上存在活跃敌人 → 该图豁免降频/休眠/滚动删除（保活第四条），敌人清零后回落正常距离判定；②判定 = 纯"活跃敌人"口径**零排除分支**——驻军、炮塔一律不排除（一致性优先；已知后果 = 敌对据点/Site 图因常驻驻军恒保活、活跃圈内不降频，定夺行为非缺陷）；虫激怒取**窄判**（与原版威胁/撤退判定同语义——守巢/激进守巢的虫不算，只有真正发起进攻的才算）。

**谓词（唯一出处 `SeamlessMapGovernance.HasActiveThreat`）**：原版 `GenHostility.AnyHostileActiveThreatToPlayer(map)` 一行（走 `attackTargetsCache` 事件增量缓存、非全图 pawn 遍历；官方先例 = 原版撤离门 CaravanExitMapUtility / CompShuttle；内置倒地/逃跑/休眠/雾中排除与虫巢窄判豁免）+ 蹒跚怪补充 `mapPawns.SpawnedShamblers` 存活（动物版猎群 faction==null 走 GenHostility 的 shambler 专用分支判非敌对、进不了缓存桶；无 Anomaly 恒空天然安全）。

**机制形态 = 发现-清零双频段轮询（自愈式；设计讨论中否决了全事件触发方案——死亡没有事件点、环境激怒零交互，轮询查实况天然全覆盖。复查间隔刻意独立于休眠扫描间隔——2026-09 定夺，曾误合并被用户撤销：复查平时零执行、有敌人时较高频跑以保证敌人行为正常回落，休眠扫描平时就要一直低频跑，节奏本质不同；设置 UI 两个滑条相邻摆放但机制独立）**：
- **发现** = Sweep 每轮对非休眠未追踪图跑谓词（≤一个扫描间隔延迟；已追踪图跳过谓词省成本）。顺带自愈"袭击 incident 选中降频图、敌人冻在 0% 生成点"的既有半 bug。
- **清零** = governor GameComponentTick 独立轮询段（`threatKeepalivePollIntervalTicks` 默认 120、可配、名单空零成本）复查 `null/Disposed/IsDormant/!HasActiveThreat` → 注销。**回落不立即 Throttle**——交下轮 Sweep 按距离收敛（0% 图重新摘表走既有幂等路径）。
- **追踪中 = 保活第四条**（Sweep 保活条件 + 原因链第四档 "active threat"）→ continue 豁免删除/休眠/降频全部下游；玩家跑远图不删，敌人清零后正常。
- **休眠图刻意不注册不唤醒**（休眠冻结防级联语义保留；袭击打不进休眠图；玩家手动睡追踪中的图 → 轮询 IsDormant 分支注销追踪让位手动锁，保活分支的手动锁守卫挡 Wake）。

**告警**：`Alert_ThreatKeepalive`（AlertPriority.Medium = 枚举最低档"需要治疗"族；原版 AllLeafSubclasses 自动发现零注册；`AlertReport.Active` 刻意不做点击跳转——跳图 = 切 CurrentMap 太激进）——追踪名单非空时右下角提示"因活跃敌人保持全速的地图"，展开列 tile 经纬度 + 地图名。数据源 = governor 快照（`ThreatKeepaliveSnapshot`），每 24 帧重算零遍历。
