# 地图滚动休眠（软休眠模型）

> 状态：已实现，游戏内回归进行中（2026-08）。
> 本文是地图滚动生命周期的权威文档：休眠 / 唤醒 / 删除三态与自动调度策略。

## 一、设计定夺（用户决议 2026-08）

**软休眠模型**：休眠图的 **Map 对象保留在 `Find.Maps` 中不卸载**，照常随档全量序列化
（存档零额外机制——建筑/物品/地形完好，"不丢东西"由模型本身保证）。休眠只意味着：

1. **不 tick**（冻结模拟：组件、天气、植物、动物、火、电力全部停）；
2. **不作为邻接地图显示**（渲染不画其背景、跨图菜单/传送点对其关闭，视觉上回到 void 清色帧）；
3. **无地图访问入口**（顶部殖民者栏的地图分组框不显示——原版 `CheckRecacheEntries` 遍历
   Find.Maps **每图一组**、无 pawn 也画空分组框（可点击切图），需 `Patch_ColonistBar_CheckRecacheEntries`
   Postfix 从 cachedEntries 移除休眠图 entry + 重编 group（重编必须用构造器重建 entry——Entry 的
   reorderAction 闭包捕获构造时 group，直改字段会使拖动跨组排序写错组）；Sleep/Wake 收尾调
   `MarkColonistsDirty` 立即生效。注意：休眠图上的殖民者尸体 entry 也随之隐藏（图不可访问，
   与"点不进去"一致）。世界地图"查看地图"gizmo 保留为显式唤醒入口）。

- **唤醒** = 下次进入休眠地图时（同步、轻量：恢复 tick 注册 + 恢复邻接显示 + 恢复入口，
  无重新生成、无分帧）。
- **删除** = 彻底删除（地块图：`RemoveTileMap` 销毁 Map + WorldObject；原生家族：
  `RemoveNativeFamilyMap` 延迟执行原版删除偏好），下次进入时重新生成。
- **距离策略**（源 = 所有玩家阵营 pawn 所在图 **∪ 玩家阵营远行队所在 tile**，世界网格 BFS 拓扑距离。
  2026-08 修复"全员远行 → 源空 → BFS 距离表全空 → 全部管辖图按无穷远误删"的结构性炸弹：远行队
  计入源（用户原则"距离对全部 pawn 成立"——远行队里的 pawn 也在世界网格上占 tile）+ 空源守卫
  （无任何玩家 pawn 的异常态本轮不睡不删）。每轮现算、无维护状态——源每刻在动，预算好的距离表
  写完即过期。pawn 变动即时触发：跨缝传送完成 / 远行队组队离图（`Notify_CaravanFormed` Postfix）/
  远行队进图三类事件调 `RequestSweepSoon`（置零计数器，下一 GameComponentTick 执行——不在事件
  回调里直接睡/删图，Sleep 摘全局 tick 表落在 thing tick 遍历中途不安全）；600 ticks 周期兜底）：
  - 图上有玩家 pawn → 永不休眠、永不删除（保护判据 = 仅玩家 pawn）；
    相邻图因玩家踏入自动距离 0，天然满足"相邻图不休眠，否则玩家可以跨图躲追击"；
  - **玩家家园（`IsProtectedHome` = 原版 `Map.IsPlayerHome`）→ 永不休眠、永不删除**（2026-08
    用户定夺，修复"全员离家 ≥2 跳家园被睡、入口消失"的缺口。覆盖开局家园/定居/逆重飞船降落
    产生的原生 Settlement 与建了引力引擎的图（含地块图营地）——家园特权判定全项目唯一行为
    消费点 = governor 保活分支）；
  - 距离 ≥ 2（sleepHops）→ 休眠；建筑和物品不会丢（只是不 tick）；
  - 距离 ≥ 3（deleteHops）且可删（`CanRollingDelete` = 受管辖且非家园）→ 删除：
    **地块图**销毁 Map + WorldObject（"从未出现过"，下次进入走生成链重建）；
    **原生家族**（Settlement/Site/CaravansBattlefield/DestroyedSettlement，见 2.11）**延迟执行
    原版删除偏好**——删图时 WorldObject 是否连带销毁按原版 `ShouldRemoveMapNow` 的
    alsoRemoveWorldObject 判定（Settlement 删图留对象、CaravansBattlefield/DestroyedSettlement
    连对象删、Site 按 parts 语义）；
  - `Find.CurrentMap` 无条件保活（玩家正看着的图冻结会卡 UI）。
- **NPC 对端休眠语义**（撤离链/追击/跟随）：不唤醒、按"未加载"处理——撤离者踩 tier0 传送点
  原生离场（链终止）、追击/跟随许可作废跟丢。防 NPC 级联唤醒跑穿世界。
  玩家自己的跨图意图仍会唤醒（边界预加载带 + CurrentMap setter）。
- **自动 + Dev 手动**：`SeamlessDormancyGovernor`（GameComponent）周期调度；
  Dev 菜单提供手动 Sleep/Wake/Report/ForceDelete。

> 历史备注：设计文档曾规划"卸 Map、留 WorldObject"的硬休眠语义（`SeamStripData` 挂
> WorldObject 即其预埋）。2026-08 用户定夺改用软休眠（Map 不卸载）——预埋的 WorldObject
> 回落路径保留（`TryGetNeighborSeamStrip` 路径②），将来若做硬卸载仍零改动可用。

## 二、机制细节

### 2.1 停 tick 的两条腿（原版查证结论）

- **Map 方法拦截**：`TickManager.DoSingleTick` 直接遍历 `Find.Maps` 调 `map.MapPreTick()/MapPostTick()`
  （TickManager.cs:357-451），`Game.UpdatePlay` 遍历调 `map.MapUpdate()`。三方法均 public 非虚
  → `Patches_Dormancy` 三 Prefix 早退（与 `Patches_IncrementalMapGen` 同款模式）。
  MapComponentTick 在 MapPostTick 内、MapComponentUpdate 在 MapUpdate 内——跳过即全停。
- **全局 Thing tick 表**：原版 TickList 按 TickerType 分桶、**完全不按地图分组**——只跳过 Map
  方法停不掉图上 Thing。休眠必须 `Find.TickManager.RemoveAllFromMap(map)`（原版 API，
  MapDeiniter.Deinit 同款，按 `x.Map == map` 全摘）；唤醒时遍历 `map.spawnedThings` 逐个
  `RegisterAllTickabilityFor(thing)`（读档路径 `Spawn(respawningAfterLoad:true)` 即走此 API，
  语义等价"这张图像刚读档一样恢复"）。
- **时序安全**：governor 的 Sleep/Wake 发生在 GameComponentTick（DoSingleTick 的 MapPostTick
  循环之后）与 UI 事件（CurrentMap setter / StartJob Prefix），不会落在 thing tick 遍历中途；
  RegisterAllTickabilityFor 与原版"tick 中途 spawn"场景同源安全。

### 2.2 口径变化（全 mod 的"对端已加载"语义）

`SeamlessTileGraph` 三处加 `IsDormant` 过滤：`TryGetNeighborLinkByWorldTile` /
`PopulateNeighbors`（连带 `AreNeighbors`、`GetAllNeighbors`）/ `TryGetMapByWorldTile`。
休眠图虽在 Find.Maps，但邻接/已加载口径视为"未加载"。一处生效全局：

- 渲染器 cachedNeighbors 排除休眠图 → 零邻居清色分支接管背景；
- `CompSeamlessTileEnterSpot.ComputeAndCacheArrival` 走 link 查询 → `hasArrival=false`
  → 跨图菜单/传送自动关闭；
- 撤离链 `TryFindEvacuationExit` tier0 → 休眠对端 = 未加载 → 撤离者原生离场（Q4 决议零代码）；
- 传送许可 `HandleBoundTransfer/HandleEvacuation` 对端校验 → 休眠即跟丢/原生离场。

**例外——`TryGetNeighborSeamStrip` 刻意不过滤休眠**：它是数据查询而非邻接交互
（新图生成时接缝混合的参考数据），快照数据不因休眠失效（软休眠不销毁 Map，原生图快照挂
图组件仍在；地块图快照挂 WorldObject 两路同源——载体差异由 `SeamlessMapData` 屏蔽）。
消费方若需感知休眠图的存在（生成守卫防重复 WorldObject），直接查 `worldObjects.MapParentAt`。

### 2.3 唤醒入口（三处）

1. **`Game.CurrentMap` setter Prefix**（`Patches_Dormancy`）：一切"进入地图"路径
   （世界地图"查看地图"gizmo、殖民者栏组框点击、CameraJumper、跨图选中）都汇聚于
   此 setter——单点覆盖：目标为休眠图 → 先同步 Wake 再切图。
2. **边界预加载带**（`SeamlessBorderPreloader.CheckPawnGoto`）：玩家 goto 边界带且目标
   邻居休眠 → 同步唤醒（原本"已加载跳过/未生成入队"二分支中间插入休眠分支）。
3. **governor 兜底**：距离回落到活跃圈（< sleepHops）的休眠图唤醒。

### 2.4 生成守卫（防重复 WorldObject——会断点，勿删）

`SeamlessTileManager.GenerateTileMap`：`TryGetMapByWorldTile` 被休眠口径过滤后查不到休眠图，
但休眠图的 Map 和 WorldObject 都还在——入口处用 `worldObjects.MapParentAt` 查到休眠 parent 时
**Wake + 补登记邻居并返回**，绝不 `MakeWorldObject` 新建（否则同 tile 双 parent、邻居表分裂、
存档脏数据）。附带防御分支：WorldObject 在但 Map 不在（软休眠下理论不可达；历史
RemoveTileMap bug 曾残留隐形 WorldObject）→ 销毁残留后继续生成。

### 2.5 天气域与休眠的交互（2026-08 机理勘误）

**勘误**：曾以为"宿主图 tick 是域内天气推进的唯一驱动"，据此加了"宿主必须活跃"过滤并预言
"宿主休眠 = 冻结 / 换宿主 = 跳变"——**两者都不成立，过滤已撤销**。真实机理：三件套
（WeatherManager/WeatherDecider/SkyManager）均非 MapComponent，tick/update 由每张图的
MapPostTick/MapUpdate **走自己字段**调用；域内所有图的字段指向同一实例（字段替换共享），
任一活跃成员都在推进它；实例由成员字段引用保持存活（宿主图休眠/销毁都不影响）。因此：
- 宿主图休眠 → 活跃成员照常推进共享实例 → **不冻结**；
- 换宿主（RebindAll 重选）→ 成员字段读的还是同一实例 → **不跳变**；
- "宿主"的唯一实义：存档时哪张图存这套实例的状态副本（各成员都存同一份，读档后 RebindAll
  择一恢复共享）+ 新成员 BindMap 读谁的字段（域内字段全指同一实例，读谁都一样）。

**真 bug（既有，随勘误一并发现并修复）**：共享实例被域内每张活跃图各推进一次——
`WeatherManagerTick` 直接 `curWeatherAge++` 无自守卫，N 张活跃图 = 换天气频率 N 倍速；
`SkyManagerUpdate` 同理视觉快进。修复 = `Patches_WeatherCluster` 实例级幂等守卫（同 tick/
同帧内该实例第二次调用跳过；不引入域/宿主概念、不误伤非共享图、ConditionalWeakTable 弱键
防泄漏）。WeatherDeciderTick 内部仅条件比较无计数推进，天然幂等，无需守卫。
既有语义缺口（接受，观察）：天气 Worker 的物理效果（雨湿地/雪积累）作用于实例的创建图
（`WeatherTick(map,…)` 的 map = 实例字段），成员图只有视觉一致、无物理效果。

### 2.6 incident 目标过滤

`Storyteller.AllIncidentTargets` Postfix 剔除休眠图（返回的是原版静态缓存列表，调用方即用
即弃，原地 RemoveAll 安全）——防 storyteller 把袭击/事件打到冻结图上（pawn 同步 spawn 后
不 tick 站着不动，直到玩家回来）。`RandomPlayerHomeMap` 等消费面大的 getter **不 patch**
（误伤风险大于收益，见观察项）。

### 2.7 全局清扫迁移

三个静态清扫（`SeamlessSelectionTracker.PurgeInvalid` / `SeamlessTransferGrants.TickSweep` /
`SeamlessCrossMapOrders.PurgeInvalid`）从"仅家园图 MapComponentTick"迁至
`SeamlessDormancyGovernor.GameComponentTick`——家园无玩家 pawn 时可随软休眠冻结，
图组件 tick 不再可靠；GameComponent 恒 tick 与地图活跃状态解耦。

### 2.8 不序列化休眠状态

休眠集合（`SeamlessDormancyManager.dormantMaps`）是纯运行时性能状态。读档后所有图自动恢复
活跃（tick 注册由 FinalizeLoading 的重 spawn 完成），governor 首轮扫描（nextSweepTick=0
立即触发）重新收敛远图。因此不存在"读档时 CurrentMap 处于休眠"的窗口问题，也无需任何
存档迁移。

### 2.9 删除与 127 上限

删除统一入口 `RemoveRollingMap`（开头 `SeamlessDormancyManager.Forget(map)` 防集合持已
Dispose Map 引用阻碍 GC）：地块图 → `RemoveTileMap`（销毁 Map + WorldObject）；原生家族 →
`RemoveNativeFamilyMap`（见 2.11）。图量控制：活跃+休眠图 ≤ 以玩家为球心的 deleteHops 跳球
（默认 3 跳 ≤ 1+6+12+18=37 图），远离 `Game.AddMap` 的 127（sbyte）上限。

### 2.10 营地地图接入生成链（2026-08）

"设立营地"原走 `GetOrGenerateMapUtility.GetOrGenerateMap(..., WorldObjectDefOf.Camp)`——原版
`Camp` parent 的 `ShouldRemoveMapNow` 在地图无 pawn 阻挡时返回 true，而 `MapParent.TickInterval`
每 tick `CheckRemoveMapNow` → 全员跨缝走进邻图的瞬间营地被原版自动解散（删 Map + WorldObject +
原地留 AbandonedCamp 标记），完全绕过本策略（实测"1 跳邻图上的营地被删除"即此，日志无
Dormancy DELETE 行）。已查证 Camp WorldObject 的唯一创建路径 = 玩家"设立营地"
（SettleInEmptyTileUtility.SetupCamp → GetOrGenerateMap）。

修复 = `Patches_CampTileMap`（整方法 Prefix 接管 `GetOrGenerateMap`，仅 `def == Camp` 且 tile
无图无 parent 时）：建 `RimExodus_SeamlessTileMap` parent（**worldTile 必须生成前设置**——
391/392/1490 genStep 以 `GetMapWorldTile >= 0` 为门，晚设则整条无缝链被跳过）+ 同步
`MapGenerator.GenerateMap`（尺寸用 `initialMapSize` 弃 Camp 的 overrideMapSize=200；Base_Player
链与家园/地块同链；SetupCamp 的 LongEventHandler 里同步生成本就是原版行为，GenerateMap 自带
static 重置与 FinalizeInit）+ onComplete 子集集成（天气 BindMap / 传送点幂等补铺 /
AutoConnectWorldNeighbors）。

语义变化（用户原则下接受）：营地不再自动解散、不再留 AbandonedCamp 标记，改为 ≥2 跳休眠 /
≥3 跳删除（遗留物随图删，与所有地块图一致）；失去 Camp def 的 TimedDetectionRaids 与
Map_TempIncident 标签（与地块图对等）；"立即重组远行队"路径的 `CheckRemoveMapNow` 变 no-op
（基类默认 false）。防御放行（退回原版行为）：tile 已有图（含休眠图）/ 已有 parent /
`mapBeingGenerated != null`（防与分帧增量生成交错——已知观察项①同族）/ def 取不到。
其余"人走即删"原版 def 已由 2.11 的原生家族接管统一覆盖。

### 2.11 原生家族滚动接管 + 治理判定归一层（2026-08）

**原生家族** = 原版"全员离开即删图"语义的原生 parent：`Settlement`（含其他派系据点与玩家
定居/gravship 降落家园）、`Site`（含远行队埋伏 AmbushEdge/AmbushCenter、遗迹 AncientComplex
等一切 site part）、`Camp`（def 缺失回退路径；常规路径已被 2.10 接管为地块图）、
`CaravansBattlefield`、`DestroyedSettlement`（第 6 个覆写类 `SpaceMapParent` 属空间层，
排除——其 tileId 不在表面 WorldGrid）。关键事实：我们的 4 个裁切 genStep 已 XML 注入
`Base_Player/Base_Faction/Encounter`（Settlement 走 Base_Faction、Site 走 Encounter）——
**原生家族的图生成时就已被六边形裁切+铺传送点**，与地块图同链。

两层接管：

1. **拦截被动删除**（`Patches_NativeMapFamily`）：`MapParent.CheckRemoveMapNow`（public 非虚，
   覆盖全部子类覆写与"立即重组远行队"/`MoveColonyUtility` 直调）Prefix——原生家族 +
   `dormancyEnabled` → 跳过原版"人走即删"，删除时机移交 governor。主动销毁
   （`WorldObject.Destroy` → PostRemove，如任务结算）不经此路径，不受影响。口袋图与空间层图
   天然不在拦截面。
2. **governor 扩权**：管辖范围纳入原生家族（≥2 跳休眠、≥3 跳 `RemoveNativeFamilyMap`
   延迟执行原版删除偏好：先跑未被 patch 的 `ShouldRemoveMapNow` 取 alsoRemoveWorldObject
   ——Settlement 删图留对象（世界图据点仍在、再访重生成驻军，与原版重访语义一致）、
   CaravansBattlefield/DestroyedSettlement 连对象删、Site 按 parts 语义（ConditionCauser/
   RaidSource 存活时保留对象）；原版判定 false（建筑/pawn 阻挡）→ 本轮不删、保持休眠
   待状态清除后下轮再评估。"延迟语义 = 只改删除时机、不改谁决定"）。

**原生图接线钩子**（`SeamlessTileManager.SetupNativeParentMap`，MapGenerated 后延迟 1 tick）：
原生 parent 图统一做——天气域 BindMap + 传送点幂等补铺 + **AutoConnectWorldNeighbors**
（2026-08 补的关键缺口：原生路径（远行队进入据点/埋伏图）生成的图此前无人接线，无法跨缝
互走）+ 传送点缓存刷新；新增**表面层守卫**（`map.Tile.LayerDef != Surface` 早退——修复
空间层图会把轨道 tileId 打进表面 WorldGrid 的潜伏 bug）。可选级联预加载（preloadAllNeighborsOnStart）
仅玩家家园，家族不级联。**Settlement 无缝接入（2026-08 已落地，用户定夺，勿回退）**：
走近自动生成范围 = 仅 `Settlement`——`GenerateTileMap` 的占位分支对 Settlement 走原生
`GetOrGenerateMapUtility.GetOrGenerateMap`（复用既有 WorldObject 不换 def，Base_Faction/Base_Player
链含裁切 genStep；尺寸 = 源图 mapSize 保接缝几何一致；入口 mapBeingGenerated 守卫防与分帧增量
生成交错），生成后即时 `EnsureNeighborRegistered`（源图↔据点图双向邻居表+两端传送点）+ 贸易商
指定，其余接线由本钩子（延迟 1 tick）幂等补齐；`TryPreloadNeighbor` 忙时（增量生成进行中）对
Settlement 目标改为下一 tick 重排队（避免玩家的走近下令被静默丢弃）。好感度可交易（非
permanentEnemy 且非敌对，口径 = 原版 CaravanArrivalAction_Trade）的据点另按用户 7 条件从驻军选
"MarketValue 最高、玩家走得到"者为贸易商（`SeamlessSettlementTrader`：一次性指定不补选——失效
则本图存续期内无对话入口，图删除重生成后重选；登记于随图序列化的 MapComponent，读档不丢；不写
pawn.trader/wantsToTradeWithColony 原版字段，防 provider 双入口）。玩家右键其对话——
"远行者，你想要做什么？"面板（交易 + 据 `settlement.GetGizmos()` 枚举项，天然适配给据点加特殊
交互的 mod；排除"查看地图/组建远行队教学"项；"进攻"在 GetCaravanGizmos 不在其中）；交易 =
Settlement 本体作 ITrader 的原版远行队交易语义（据点 stock/baseTraderKinds/补货/恩惠货币），
