本轮已按用户授权实施局部视区和 IsoRim 私有剔除修复，用户已实测确认有效。依据 `_references/IsoRim-1.7.installed` 源码、参考 DLL、用户截图及用户运行游戏采集的日志；未证明 IsoRim 随包源码与 DLL 逐方法一致。Mod 来源/版本见统一参考目录 `IsoRim-1.7-reference-notes.txt`。原版最终渲染链已按用户授权，从安装目录补取到 `_references/RimWorldDecompiled_1.7/Rendering-1.7.4990`，具体来源、版本与哈希见其中 `PROVENANCE.md`。

## 邻图随镜头缺块：修复已实施，用户验收通过

REF 通用作用域的视区 Postfix 改为 `Priority.Last`，保证通常优先级的相机 Postfix 不再覆盖源图局部视区；窗口外保留相机结果。独立的 `IsoRimCullingCompat` 在原版回调窗口内，把 `BoxVisible` 的局部包围盒和 `MeshVisible` 的模型矩阵投影到显示坐标，再执行原有剔除；不改全局视锥、真实相机和地图归属。其依据来自公开的 `MapRenderPlan.CurrentNativeView` 与 `MapTransform.BoundsToDisplay`，不绑定 RE/Delta-V 或地图类别。API 契约见同级 REF 的 `doc/地图模块.md`。

新增 33 项离线回归覆盖两种 Harmony 注册顺序、窗口外/identity 行为、重复切换、平移/旋转/非均匀缩放、缺失或漂移签名。实际参考 IsoRim DLL 的两个入口绑定成功；使用第三次日志相机平面时，同一块局部包围盒修复前被拒绝，投影后通过，退出窗口后恢复原行为。该检查没有启动游戏或 GPU，不代表画面已经验收。

实测时重启游戏，保持高兼容性邻图渲染和“正常显示全部地图”，对同一邻图从近到远缩放并平移、旋转，再切为聚焦图比较。检查启动日志的 `IsoRim compat: bound BoxVisible and MeshVisible` 成功行及 REF/RE 实例化/绑定报告。预期不再出现随镜头推进的大片灰色缺块边界；矩形土层长条、首次访问前私有层未重建仍是独立未修问题。下文按采集时间保留调查证据，早期未定结论不代表当前修复状态。

最新症状修正：用户说明并非像素闪烁，而是邻图大面积灰色；拉远时阴影先出现，随后地形/物品逐渐出现，正常与缺失区域之间有随镜头移动的锯齿边界。当前结论是已证实 REF 局部视区补丁有注册顺序依赖，实机提交集合与错误使用聚焦图视区吻合；IsoRim 的私有视锥缺少源图投影是另一个独立问题。下文保留早期采集的证据边界，最新定责依据见第三次采集。

用户对照确认：镜头平移或旋转时边缘会闪烁、跳变；同一段边缘切为直接聚焦后消失或明显改善。这与下文的土层长条、首次显示问题分别调查。固定的格子台阶不足以解释这种差异，应优先排查 REF 邻图绘制是否破坏了原本的渲染契约，不能直接归为 IsoRim 专用适配或抗锯齿不足。

源码核对得到的边界：

- RE 的 terrain/void 归属按格生成；原版地形按格生成网格与过渡三角形。它解释静态台阶，不解释上述邻图/聚焦差异。
- REF 的覆盖层裁切按所引用顶点判断大面积平面，使用浮点插值，没有按格取整。普通地形 section 通常不达到面积阈值；尚无证据证明截图中的闪烁发生于被裁切网格。
- 高兼容性路径保留原队列，共用原版渲染与深度，不调用自绘制路径的深度分组。不能将后者的队列改写当作当前原因。
- 普通地形 shader 不写深度；因此“两个地面重叠必然 Z-fighting”也不是已证实解释。额外深度平面、遮罩、透明排序及坐标相关 shader 参数仍需实际提交数据区分。
- IsoRim 的 Sky 在特定透视/天空或距离雾配置下会为聚焦地面图补深度平面，但现有截图没有证明该条件生效；第二次采集没有该平面提交。最终排序的补充核对见下文。

用户在本轮构建后反馈“完美”，确认所报灰色缺块与移动锯齿边界修复有效；此验收不扩展到尚未适配的矩形土层侧面与首次显示重建。

### 限时诊断（1.7）

RE 设置 → 高级与诊断 → **采集邻图渲染诊断（60 秒）**，要求已载入地图并开启高兼容性原版邻图渲染。操作步骤：关闭设置，在邻图有问题的同一段地形边缘平移/旋转数秒；保持相近缩放，聚焦该邻图再重复；最后返回原图再观察。可暂停游戏以减少模拟变化。不要同时更改 IsoRim 的渲染选项，否则无法区分切图与设置差异。

文件保存在游戏数据目录的 `REF-RenderDiagnostics/render-*.log.gz`（gzip 压缩文本，可直接提交该文件）；设置页显示最近文件路径，Player.log 的 `[REF:RenderTrace]` 也记录开始/结束与路径。每秒取一帧，开始及聚焦变化额外连续取三帧；60 秒、120 样本帧、约 32 MiB 压缩内容或 512 MiB 原文上限后停止。每图每帧有独立的约四百万字符明细额度，避免前一图挤掉后一图，超过额度仍保留分类计数并标注省略。切渲染路径、退出地图或换档也会停止。采样会带来短暂 CPU 开销；完整格式见同级 REF 的 `doc/渲染诊断.md`。

采集记录地图 ID、聚焦/邻图角色、局部视区与投影、相机矩阵、网格身份/版本/包围盒、裁切前后网格、材质/shader、队列/pass/layer、变换前后矩阵，以及声明的全局参数、材质值与提交覆盖参数。作用域外的命令标为 `unscoped`，**不假定属于当前图**。同一网格身份在切图前后的对照，可定位被删/重建/改队列或参数不同的提交。

日志观察点是 REF 自己的 Enqueue Prefix 内、裁切/冻结的前后；不是其他补丁结束后的最终队列，也不是 GPU 抓帧。纹理只记录对象身份，不读取其内容；相机矩阵是 BeginFrame 时点；网格包围盒可能含人为 padding。日志不能单独证明像素深度冲突或最终抗锯齿行为。诊断默认关闭，不改绘制，不绑定 IsoRim 类型；确认原因后再决定通用修复还是专用适配。

### 2026-10-30 原版最终渲染链补充核对

用户明确授权后，从游戏目录补取 `1.7.4990 rev1069` 的排序、绘制器、管线定义及 shader；版本与此次 Player.log 一致。下列结论以 `Rendering-1.7.4990` 快照为准，不混用父目录旧版反编译。

**排序：** `MapRenderFeature.CaptureFrame` 先执行 `TransparentDepthOrder.Compute`，再由 `DrawItemFactory.TryMake`、`FinalDrawItem.Reset` 生成排序键，最终在 `MeshBatchRenderer.RecordPass` 排序并与持久提交合并。队列 `>2500` 才计算网格中心的相机深度等级；同队列先比较等级，再比较提交序号。队列 `<=2500` 不计算该等级，同队列按管线 ID、提交序号排列。是否属于这两个排序分支取决于队列，不取决于 shader 是否开启 alpha blend。

第二次日志中的 TerrainHard 队列为 2070/2220，TerrainFadeRough 为 2190–2370，全部低于 2500。因此，**这批地形不会因为相机距离变化而在透明深度排序中翻转**。不同来源同队列的重叠几何仍可能受提交先后影响；这不是“所有合成排序问题都已排除”。地形 shader 的 UV 直接取 `inPosition.xz`，没有使用平移后的 world XZ，也没有证据支持“邻图平移令地形噪声纹理改用另一套坐标”。

**颜色、深度和模板缓冲：** `ShaderProgramDefinition` 默认开启深度测试和深度写入；XML 覆盖后，实际状态如下。`MeshPipelineCache` 将深度比较固定为反向 Z 的 `GreaterOrEqual`。

| 绘制对象 | 写颜色 | 测深度 / 写深度 | 作用 |
| --- | --- | --- | --- |
| TerrainHard | 是 | 是 / 否 | 不透明地面，仍会受之前提交的模型深度遮挡 |
| TerrainFadeRough | 是，alpha blend | 是 / 否 | 地形过渡；不因 alpha blend 自动参与距离排序 |
| ShadowMask | 否 | 否 / 否 | Always/Replace 写模板位 4，队列 3165 |
| SunShadow / SunShadowFade | 是，乘目标颜色 | 是 / 否 | 读取/更新模板位后画阴影，队列 3170/3175 |
| IsoRimSolid / IsoRimSolidTex | 是 | 是 / 是 | 本轮队列 2000/2001/2002，在地形之前写模型深度 |

`ShadowMask` 片元输出虽为零颜色，但管线 `colorWrite=false`，所以**不能把它解释成直接涂黑、覆盖地面的 void 遮片**。它仍可能通过共享模板影响后续阴影；这要与直接改变地形可见性分开验证。反过来，地形关闭深度写入并不能排除模型与地形的深度冲突，因为地形仍读取模型已写入的深度。

主场景 pass 首段统一清颜色、深度和模板，后续 scene-grab 分段加载已有结果；没有按源地图清深度。场景目标为单采样。IsoRim 的 AntiAlias 是整屏后处理，不能仅凭“邻图有锯齿”就推断 REF 漏跑了一个每图抗锯齿步骤；现有采集窗口也没有覆盖全部相机阶段提交，尚未证明该后处理本次实际执行情况。

**当前责任判断仍未定。** 目前可以收窄错误裁切、已匹配地形的参数/平移变化、地形距离排序、ShadowMask 直接涂黑等解释，但还没有出问题像素的实际覆盖与深度证据。下一步有区分价值的对照应固定相机和问题边缘：先在保留源图局部调用语义和原投影的条件下，仅保留该来源提交，检查是否仍闪烁；随后单独验证早于地形的深度写入是否参与问题。若仅保留该来源就恢复，继续定位跨来源重叠/深度/模板；若仍异常，再对照同一来源聚焦时的完整提交与私有状态。临时关闭地形深度测试只能定位遮挡参与情况，不能作为修复，否则会把地面画到模型上。

上述单来源对照已在用户确认后提供临时入口，待实测；尚未据此实施渲染修复。重复当前层级的提交日志收益有限；需要最终绘制/像素证据或单因素对照，不能以未发现 CPU 差异证明 REF 完全正确，也不能凭“聚焦后改善”直接认定 REF 的通用缺陷。

### 单来源对照操作（待实测）

1. 暂停模拟，保持高兼容性邻图渲染开启，找到有问题的邻图边缘。开始 60 秒采集，先保持“正常显示全部地图”，观察几秒。
2. 在同一页的“单图绘制对照”菜单中选中有问题的邻图 ID，关闭设置，在相同视角和缩放下重复轻微平移。其他已知地图来源的绘制会隐藏，选定图的位置、投影、回调和参数保持原状。
3. 选回“正常显示全部地图”，再次观察同一边缘。需要确认地图 ID 时可先聚焦目标图，用菜单中的“当前聚焦”识别 ID，再回原图开始对照；不要用另一张邻图的结果代替问题来源。
4. 可在保持同一来源选择的情况下切换聚焦，补充对比。结束时点击停止；超时也会自动恢复正常显示。报告“仅显示目标时是否还闪烁，恢复全部时是否复现”，并保留日志。

REF v3 日志记录每个样本的 `isolatedSource`、切换事件和每条提交的 `submitted/clipped/isolated` 结果。过滤只发生在已知地图作用域内的提交出口；全局绘制、私有持久提交和绕过此入口的 GPU 绘制保留。因此“隔离后仍闪烁”不能彻底排除未知来源干扰；“隔离后消失、恢复后复现”则能把调查收窄到被移除的已知来源贡献。对照不改深度测试，不清每图深度，不切换实际 CurrentMap，也不暂停其他图的回调或 tick，不写存档。

**关键空间证据：** frame 8263 聚焦图 0，来源 1 的显示平移为 `(138,0,161)`。REF 计划中图 0 局部视区为 `(38,57)–(249,249)`，图 1 为 `(0,0)–(211,207)`。但两图实际地形网格中心范围都为 X=42.5…244、Z=59.5…244。frame 8442 聚焦图 1 时，两图计划中的各自局部视区保持上述范围，而两图实际地形网格中心又一起变为 X/Z=8.5…212.5。来源地图不同，提交范围却跟着真实聚焦图的局部坐标变化；仅检查成功提交网格的矩阵一致，会遗漏这个问题。

来源 1 在邻图/聚焦状态分别有 293/326 个地形网格身份，交集仅 87。把“聚焦时存在、邻图时未提交”的网格按邻图计划平移后，**190 个网格的整个带 padding 包围盒都在日志相机的屏幕及 Vulkan 深度范围内**。例如网格 `28178607:v1:s0` 的局部中心 `(8.5,0,76.5)`，应显示于 `(146.5,0,237.5)`，NDC 为 `(-0.4773,0.1839,0.5589)`；若遗漏显示平移，NDC 变为 `(-0.3248,2.2201,1.2004)`，会被判到屏幕外。该计算用的是 BeginFrame 相机和已有网格 bounds，不是 GPU 抓帧，但证明“这些网格按计划本应在视区内、却未到达 REF 的提交观察点”，不应优先用像素深度争夺解释它们。

**REF 通用缺陷：** `MapRenderScope.ViewPatch.Postfix` 以默认优先级返回 `Plan.LocalView`。IsoRim `Patches.CurrentViewRect_Postfix` 同为默认优先级，会把结果重新设为 `Floors.WidenView(View3D.GroundRect())`。后者基于真实相机的聚焦图坐标。REF 先注册、相机补丁后注册时，本来已转换的局部视区会被覆盖。原版 `MapDrawer.ViewRect` 再把错误视区裁到源图矩形范围，无法补回遗漏的平移。

已用当前生产 REF 的真实 Postfix 与真实 Harmony，配合模拟相机 Postfix 在纯离线 getter 上复现（不是运行 IsoRim）：

| REF 优先级 | 注册顺序 | 作用域内最终视区 |
| --- | --- | --- |
| 当前默认 | REF → 相机 | `(38,57,249,249)`，错误地回到显示坐标 |
| 当前默认 | 相机 → REF | `(0,0,211,207)` |
| Last（仅测试覆盖） | 任意上述顺序 | `(0,0,211,207)` |

四种情况下作用域外均保留相机 Mod 的视区。复现程序位于 `tmp/isorim-viewrect-order-20261030`，未更改生产补丁。此处证明的是顺序缺陷本身；实机还应补验最终 getter 返回值与实际补丁顺序，不能把模拟相机测试冒称为已加载 IsoRim 的实机验证。

**独立的专用兼容：** IsoRim `Cull.SetCamera` 保存真实聚焦相机的一套平面，`SectionVisible/BoxVisible` 和 `MeshVisible` 使用源图局部包围盒/模型矩阵，未乘 REF 的显示变换。因此即便局部矩形修正了，它仍可能把可见邻图块剔除。应该在判定前将包围盒投影到显示系，或将视锥平面转换到源图局部系；不能等到 Enqueue 才平移，也不能全局禁用所有图的剔除当作正式修复。

该机制也解释症状的方向：拉远会扩大错误坐标系中的窗口，越来越多块被放行；切到目标图后坐标系重合，问题改善；section 以块为单位绘制，窗口与这些块相交可形成移动的台阶边界。阴影与地形不是同一个放行条件：原版未绘制整块时仍调用 `DrawDynamicSections(view)`，SunShadow/EdgeShadow 属于动态层，使用扩展阴影视区，可在普通地形之前出现。参考中 `GetSunShadowsViewRect` 还存在仅按帧缓存、未按地图/输入视区区分的假设，应另审计，但本轮不能据此宣称它就是当前主因。

据此实施的修复：先在 REF 通用作用域内保证局部视区不被通常优先级的相机 Postfix 覆盖，保留作用域外相机 Mod 的计算结果，并补两种注册顺序回归；再独立接入 IsoRim 私有剔除的坐标变换。没有修改 terrain shader、抗锯齿、深度或重放每图相机更新。实现与验收边界见本文开头。

## 土层长条（独立问题）

`Source/Layers.cs:1816` 的 `SectionLayer_IsoRimEdge` 使用 `IsoRim/Edge/Strata` 纹理，在矩形四边生成向下约六格深的土层侧面。边界来自 `x=0/Size.x`、`z=0/Size.z`，不读取 RE 多边形或邻接；`Face` 根据全局相机方向选择侧面，逐格生成四边形。注释明确描述破碎底边的外观。`Visible` 受 `mapEdge3D` 和 `Map.DrawMapClippers` 控制；`Patches.DrawClippers_Prefix` 开启此选项时还会抑制原版平面遮片。

截图中横穿地形间空白区、带土层颜色的长条，与此链高度吻合。旧方形边不再是 RE 可见地块边，所以可能悬在 void 上。这个解释只针对土层长条，不作为地形轮廓闪烁的归因。

REF 当前裁切大面积平面覆盖层，不裁切这种立面，符合当前 API 范围。但消费方缺少表达“矩形边不是真实世界边缘”的共同契约。把所有 3D 网格按地面多边形硬裁，会切坏跨边界伸出的墙、树和屋顶，不能作为通用修复。

## 跨图后才出现

已确认两条独立风险链，实测还需区分当前主因：

1. `View3D.RegenerateAllMaps`（1151）在切换 3D/模型状态后，只立即重建 `Shown(map)` 的图，其余进入 `stale`；`RebuildStaleShownMaps`（1169）仍按同一谓词重建。`Shown`（1188）只有 `map == Find.CurrentMap`。RE 同时显示邻图，但 IsoRim 相机更新阶段只知道真实聚焦图，因此邻图可能保留旧的/空的 3D 层，聚焦后才重建。普通 section dirty 更新不消费 IsoRim 私有 stale 集合。此链尤其符合“启动/切换 3D 后，进过一次就能持续显示”。
2. `Cull.SetCamera`（Culling.cs:43）仅存一套全局视锥；`SectionOverlaps`（300）、`SectionVisible`（392）使用 section 局部包围盒，只有 IsoRim 自己的楼层位移。REF 平移绘制命令发生得更晚，救不回已被 CPU 剔除的 section。切图后局部坐标成为相机参考系，问题可能暂时消失。此链更可能随平移、缩放和旋转反复出现。

REF 提供正确的邻图局部 CurrentViewRect，并不代表 IsoRim 私有相机矩阵也已转换。不能仅据此断言 REF 没生成地图，也不能把补一次 RegenerateEverythingNow 当成完整修复。

## 专用机制分工与剩余边界

| 问题 | 假设冲突 | 建议分工 |
| --- | --- | --- |
| 方形土层长条 | IsoRim 把矩形边当真实外缘；RE 使用多边形接缝 | REF 提供有效边界/真实外边缘语义，适配方抑制内部接缝和旧方形侧面；需要新土层时由了解其几何的绘制方生成 |
| 首次进入才重建 | IsoRim 假定只显示 CurrentMap | REF 暴露本帧可见图和显示状态通知，IsoRim 或窄兼容层让 Shown/私有重建调度消费 |
| 邻图视锥剔除 | 私有视锥为单一坐标系，网格投影晚于剔除 | 已由 REF 独立兼容层提前转换包围盒/模型矩阵，保留原有剔除算法；用户已确认修复有效 |

上表仅涉及长条和显示/剔除的专用兼容，不能据此排除闪烁锯齿是 REF 通用缺陷的可能。对这些专用机制，REF 提供可复用事实，IsoRim 私有机制由了解它的适配层消费。不建议把 IsoRim 类名/字段塞进通用提交逻辑，也不能逐邻图重放 CameraDriver.Update，避免重复输入、第一人称状态和全屏效果。

最小实测区分：关闭 IsoRim 地图土层边缘选项观察长条；同一存档切换 3D，比较未访问邻图和访问后返回的状态；旋转/平移观察是否反复丢块。后续可记录 stale 命中及邻图剔除数量，确认主因后再决定实现范围。
