## 改动 1：修复卸载地块后刷新剩余邻居的传送点缓存

**文件**：`Source/SeamlessTileManager.cs`

**问题**：`CleanupNeighborLinks`（L567-585）清理双向邻居表后，剩余邻居上指向被卸载地块的 spot 仍保留陈旧的 `hasArrival=true` + `cachedArrivalCell`。

**修复**：在 `CleanupNeighborLinks` 中，foreach 清理邻居表时同步收集"受影响的剩余邻居 Map"（去重），foreach 结束后对每个 Map 调 `RefreshEnterSpotArrivals`（已是 public static，L452）。
- 收集：遍历 `linksToRemove`，对每个 `link.neighbor`，若 `link.neighbor.Map != null` 加入 `HashSet<Map>`。
- 刷新：foreach 后，对 HashSet 每个 map 调 `RefreshEnterSpotArrivals(map)`。
- `RefreshEnterSpotArrivals` 会让每个 spot 重算 `ComputeAndCacheArrival`，`TryGetNeighborLinkByWorldTile` 查不到已卸载地块 → `hasArrival=false`，缓存自然失效。
- 取 Map 用 `link.neighbor.Map`（MapParent 基类属性，锚点和口袋都适用）。

## 改动 2：TryGetOwnerNeighbor 性能优化（缓存多边形顶点）

**文件**：`Source/SeamlessPolygonGeometry.cs`

**问题**：`TryGetOwnerNeighbor`（SeamlessTileRegistry.cs L47-67）每次调用对"当前地块 + 每个邻居"都重新 `BuildPolygonVertices`，内部走世界网格查询 + 切平面基计算，结果在单局游戏内不变，重复计算浪费。

**修复**：进程级缓存。
- 新增 `private static readonly Dictionary<(int worldTile, int mapSize), List<Vector2>> polygonCache = new();`
- 新增 `PopulatePolygonVerticesCached(int worldTile, int mapSize, List<Vector2> result)`：命中 → `result.Clear(); result.AddRange(cached); return;`；未命中 → 调现有 `PopulatePolygonVertices` 后存一份拷贝到缓存。
- `BuildPolygonVertices`（L25-30）改为调 `PopulatePolygonVerticesCached`。
- **无失效需求**：worldTile 几何在单局游戏内不变，开新档是新进程。所有 `BuildPolygonVertices` 调用方自动受益。
- **不动 GetAllNeighbors 的 new List**：点击路径、非高频，避免扩大改动面。

## 改动 4：补写"边界带不可建造"约束设计（只写文档，不实现代码）

这是阶段3 → 阶段4 衔接的安全前提。阶段3 论证"卡 void 不会发生"依赖此约束（传送点只在对侧可达时被 goto 激活，但玩家可用建筑改变寻路打破前提）。当前设计文档完全没写，属真实遗漏。

### 4a. 写入 `doc/无缝世界地块探索.md` 阶段4 节

在"### 4. 实现连续地形原型"节补充"边界带不可建造"子节，内容：

- **动机**：防止玩家在接缝重叠带及其内侧建造，用建筑改变寻路把 pawn 困在 void 一侧（传送点激活依赖"对侧可达"，建筑可打破此前提）。
- **范围**：每张地块多边形边内侧 N 格的环形带（N 待定，初步 = SeamOverlap(2) + 1 = 3 格，由独立 settings 字段控制，不复用 borderPreloadDistance=15）。
- **实现机制**（基于反编译调研的结论）：
  - **方案**：Harmony Prefix patch `GenConstruct.CanPlaceBlueprintAt`（`RimWorld/GenConstruct.cs:231`），这是所有玩家建造路径（手动 Designator_Build/Install、自动重建、Sketch、Prefab、BaseGen）的唯一汇聚点。
  - **判定**：遍历 `GenAdj.OccupiedRect(center, rot, entDef.Size)`，任一格落在禁建带 → 返回 `AcceptanceReport("RimExodus_BorderNoBuild".Translate())`，跳过原方法。
  - **数据源**：在 `SeamlessBorderLookup` 加 `IsInNoBuildBand(cell)` + 独立的 `noBuildBandCells` 速查表（带宽由新 settings 字段 `noBuildBorderDistance` 默认 3 控制，独立于 `borderPreloadDistance`）。
  - **godMode 放行**：与原生 `InNoBuildEdgeArea` 一致，开发模式可建。
  - **ignoreEdgeArea**：建议**不尊重**（世界几何约束，攻城者也不该跨地块缝建），但对 BaseGen/Siege 做兼容性测试。
  - **原生范式参照**：`InNoBuildEdgeArea`（`Verse/GenGrid.cs:14-25`，地图边缘 10 格禁建）+ `GenDraw.DrawNoBuildEdgeLines`（视觉提示，可选体验增强）。
- **否决的方案**：
  - 改 terrain affordance：无 affordance need 的建筑（墙、门）绕过检查，挡不住。
  - PlaceWorker：per-Def，无法"某区域禁所有建筑"。
  - Zone/Area：原生 Zone/Area 全部不参与建造可行性检查。
