# RimExodus 第二阶段增强：对称无缝地块（基于直接邻居表）

## 核心架构转变

**从"宿主特殊论"转向"地块对等论"**。当前架构有 4 处硬编码假设"宿主是特殊的"（`IsPocketMap return`、`sourceMap != map` 过滤），无法支持 B→C（口袋到口袋）。

本次建立**直接邻居表**：每张地块维护 6 向邻居引用 + 相对偏移。A→B、B→A、B→C 完全相同处理。无全局世界坐标（避免累积误差，原型整数偏移，未来六向扩展也不累积）。

**约束**（用户确认）：
- 单跳可见：A 只看 B，B 只看 A+C，B 只看 C。无全局世界坐标。
- 单跳寻路：不跨地图寻路，传送点桥接只做单跳。
- sourceMap 扁平化指向锚点 A（仅 skyManager 共享 + 原生合规用），不表达地块关系。

## 第一部分：直接邻居表基础设施

### 步骤 1.1：邻居表数据结构

**修改 `Source/MapParent_SeamlessTile.cs`**：
```
// 新增：6向直接邻居表。每槽存邻居引用 + 邻居相对本地块的偏移。
// direction: 0=北,1=东北,2=东南,3=南,4=西南,5=西北（原型 1/2→东, 4/5→西）
public struct NeighborLink { public MapParent_SeamlessTile neighbor; public IntVec3 offset; }
public NeighborLink[] neighbors = new NeighborLink[6];  // null neighbor = 该方向无邻居
public bool autoFocused;  // 步骤4自动聚焦一次性标志
```
- `hostOffset` 字段**保留但语义不变**（仍是"相对生成源地块的偏移"，用于 sourceMap 扁平化下的坐标转换）。
- `ExposeData`：`neighbors` 用 `Scribe_Collections` 存（注意 NeighborLink 含 MapParent 引用，需 `Scribe_References`）；`autoFocused` 用 `Scribe_Values`。
- 新增辅助方法 `GetNeighborInDirection(int dir)`、`SetNeighbor(int dir, MapParent neighbor, IntVec3 offset)`。

### 步骤 1.2：sourceMap 扁平化 + 生成时双向登记邻居

**修改 `Source/SeamlessTileManager.cs` 的 `GenerateTileMap(direction, mapSize, overlapBand)`**：
- 调用者 `map` = 生成源地块（可能是 A 或 B 或任意图块）。
- 新地块的 `sourceMap` = **锚点地图**（家园 A，即 `worldOffset==Zero` 的那张，或通过 `SeamlessTileGraph.AnchorMap` 查），不是调用者 map。避免原生嵌套副作用。
- `hostOffset` = `ComputeHostOffset(...)`（新地块相对源地块 `map` 的偏移，现有逻辑不变）。
- skyManager/weatherManager 共享自锚点 A（`interiorMap.skyManager = anchorMap.skyManager`）。
- **双向登记邻居表**：
  - `mapParent.SetNeighbor(direction, newParent /*新地块*/, hostOffset)` — 源地块的该方向邻居 = 新地块，偏移 = hostOffset。
  - `newParent.SetNeighbor(OppositeDirection(direction), mapAsParent /*源地块*/, -hostOffset)` — 新地块的反方向邻居 = 源地块，偏移 = -hostOffset。
  - 注意：源地块 `map` 若是锚点 A，它不是 `MapParent_SeamlessTile`（A 是普通 Map）。需让 A 也能存邻居表 → 见步骤 1.3。

### 步骤 1.3：锚点地图（家园 A）的邻居表

锚点 A 是普通 `Map`（非口袋），不是 `MapParent_SeamlessTile`。但它也需要邻居表（A 北邻 = B）。
- **方案**：A 的邻居表存在其 `SeamlessTileManager` MapComponent 上（A 上本来就有这个组件）。给 `SeamlessTileManager` 也加一份 `NeighborLink[6]` + 同样的 Get/Set 辅助方法。
- 新增 `Source/SeamlessTileGraph.cs`（静态工具，或轻量 GameComponent）：提供 `GetNeighborLink(Map map, int dir)` 统一入口——若 map 是锚点/普通地图，查其 `SeamlessTileManager.neighbors`；若是口袋地图，查其 `MapParent_SeamlessTile.neighbors`。`GetAllNeighbors(Map)` 返回所有非空邻居 + 偏移，供渲染/交互统一遍历。

### 步骤 1.4：解除 IsPocketMap 禁令 + 防递归

**修改 `Source/SeamlessTileManager.cs`**：
- 移除 `MapComponentTick`（第42行）和 `MapGenerated`（第69行）的 `if (map.IsPocketMap) return;`。
- **防递归新机制**：`MapGenerated` 里检查 `if (GetNeighborInDirection(0) != null) return;`（北邻已存在就不重复生成）。只允许锚点 A（`SeamlessTileGraph.IsAnchorMap(map)`）触发开档自动生成北侧。
- 口袋地块（B）上的自动生成：由"pawn 接近边界"事件驱动（本次可先用 Dev 命令手动触发验证，自动边界检测可作为增强）。生成前查邻居表该方向是否已有邻居。
- `pendingAutoGenerateTicks` 延迟机制保留，对所有地块生效（但自动触发入口只对锚点 A 开）。

### 步骤 1.5：Registry/Utility 基于邻居表重构

**修改 `Source/SeamlessTileRegistry.cs`**：
- `GetFootprintsOnHost(Map)` → `GetNeighborFootprints(Map currentMap)`：遍历 `SeamlessTileGraph.GetAllNeighbors(currentMap)`，每个邻居的 footprint = 邻居本地矩形 + 该邻居相对偏移。不再依赖 `sourceMap`。
- `TryGetOwnerPocketMap` → 用最近中心所有权规则，候选 = 当前地图自身 + 所有邻居（footprint 覆盖该格的）。返回归属地图 + 局部坐标。
- `IsPocketMapAnchoredTo` → `AreSeamlessNeighbors(Map a, Map b)`：查邻居表是否有直接邻居关系。

**修改 `Source/SeamlessMapUtility.cs`**：
- `ToHostCoord`/`ToLocalCoord` → 保留，但增加基于显式 offset 的 `ToMapCoord(cell, offset)`/`FromMapCoord(cell, offset)`。
- `TryResolveMapPosition` → 用泛化的最近中心所有权（候选含当前地图 + 所有邻居）。

## 第二部分：传送点（铺满接缝 + 多点寻路 + 性能）

### 步骤 2.1：铺满接缝

**修改 `Source/SeamlessTileManager.cs` 的 `PlaceEnterSpots(parent, interiorMap, direction, overlapBand)`**：
- 沿接缝方向遍历每个可通行格，每格放一对传送点。
- 偏移用 `parent.hostOffset`（新地块相对源地块的偏移，现有逻辑）。
- 北侧（direction=0）：z 固定重叠带中央行，x 遍历 `[2, sizeX-3]`，每格校验两端 Walkable。
- 配对不变：本端/对端 `CounterpartSpot` 双向绑定。
- 调研确认：`Standable/pathCost=0`，满铺不影响寻路网格成本。

### 步骤 2.2：多点寻路桥接

**修改 `Source/SeamlessCrossMapOrders.cs` 的 `TryFindBridgeSpot`**：
- 改为 `TryFindNearestReachableBridgeSpot(Pawn pawn, Map toMap, out Thing exitSpot)`。
- 用 `fromMap.listerThings.ThingsOfDef(enterSpotDef)`（按 def 索引，避免全量遍历）。
- filter `comp.CounterpartSpot?.Map == toMap`，按 `DistanceToSquared` 升序排序，依次 `CanReach`，返回第一个可达。

### 步骤 2.3：触发扫描性能优化

**修改 `Source/SeamlessMapTransferTrigger.cs` 的 `CheckLocalEnterSpots`**：
- 改用 `map.listerThings.ThingsOfDef(enterSpotDef)`（O(1) def 索引）。
- 移除全量 `AllThings` 快照分配，内层只检查站在传送点格上的 pawn。

## 第三部分：自动聚焦 + 无感相机切换

**新增 `Source/SeamlessCameraFocus.cs`**：
- `TryAutoFocusOnArrival(Pawn pawn, Map arrivalMap)`：
  1. 判断 `pawn.IsColonist`。
  2. 判断 `arrivalMap.Parent is MapParent_SeamlessTile parent && !parent.autoFocused`。
  3. 记录切换前相机位置 `camPos`（当前地图坐标系）。
  4. 算目标位置：`arrivalMap` 中对应同一世界位置的坐标 = `camPos - 邻居相对偏移`（偏移 = arrivalMap 相对当前地图的偏移，从邻居表查）。
  5. `Current.Game.CurrentMap = arrivalMap;`（触发原生硬跳）。
  6. 立即 `Find.CameraDriver.JumpToCurrentMapLoc(targetPos);` 覆盖（硬跳，画面不动=无感）。
  7. `parent.autoFocused = true;`

**修改 `Source/SeamlessMapTransferTrigger.cs`**：`TryTransferPawn` 成功后、`ContinueCrossMapMove` 之前调 `TryAutoFocusOnArrival`。

**调研确认**：drafted 状态天然不丢（`DeSpawn/Spawn`/`mindState.Reset` 不动 `draftedInt`），drafted 移动 Job = 普通 `JobDefOf.Goto`，续程已用此 JobDef。聚焦在续程前完成，避免 `SelectInternal` 二次跳镜头。

## 编译与验证

- 每步 `dotnet build Source/RimExodus.csproj -c Debug`（0 错误 0 警告）。
- 游戏内验证：
  1. 开档 → A 自动生成北侧 B（邻居表双向登记，sourceMap 扁平化）。
  2. 聚焦 A → 看到 B 的 terrain + 建筑 + Pawn。
  3. 征召 pawn 跨图到 B → 仍 drafted、续程、无感聚焦。
  4. **B 上生成北侧 C**（Dev 命令，口袋上也能生成）→ 聚焦 B 看到 C。
  5. pawn 从 B 跨入 C（口袋到口袋）→ 对称转移/续程/聚焦。
  6. 聚焦 C → 看到 B（反向可见）。
  7. 切回 A → 第二个 pawn 跨图不再自动聚焦。
  8. 保存读档 → 邻居表、hostOffset、传送点配对、autoFocused 恢复。

## 关键风险与缓解

1. **邻居表存档**：NeighborLink 含 MapParent 引用，用 `Scribe_References`。存档时邻居可能尚未加载，需 PostLoadInit 阶段重新解析。
2. **sourceMap 扁平化副作用**：所有地块 sourceMap=A，A 的 ChildPocketMaps 含全部地块（财富/威胁计算）。原型阶段地块少，可接受。
3. **锚点 A 的邻居表存于 MapComponent**：A 不是 MapParent_SeamlessTile，邻居表存其 `SeamlessTileManager`。`SeamlessTileGraph` 统一入口屏蔽此差异。
4. **六向扩展**：邻居表 6 槽 + 方向偏移查表，未来改六边形只改偏移计算（ComputeHostOffset 的方向表）。整数偏移在矩形原型无精度问题；六向扩展时偏移可能带 `H/2`，但因为不累加（每条邻居关系独立存），单次精度无损。
