# 阶段3：多边形裁切实现计划

## 设计总纲

### 几何模型（内切圆顶点模型）
最简洁的构造：**多边形顶点 = 地图中心 + 0.5S × 顶点方向单位向量**。即顶点位于正方形地图的内切圆上（距中心 0.5S）。

- **顶点方向**：世界地块顶点投影到切平面、归一化后的单位向量。忠实于地块真实朝向。
- **顶点尺度**：固定 0.5S（地图半边长 = 内切圆半径）。几何意义：k=0.8 的平顶六边形左右顶点恰好顶在正方形左右边中点附近（1.6S/3≈0.533S≈0.5S），用 0.5S 是其自然近似。
- **多边形**：N 个顶点依次连线构成的凸多边形（N=5五边形/N=6六边形，代码统一遍历 N，不区分）。
- **后续操作全部基于这个多边形顶点连线**，不反复换算 apothem/边距离/circumradius：
  - 虚空区 = 地图内但多边形外（扫描线判定）。
  - 传送点 = 沿多边形每条边 Bresenham 划线。
  - 邻居 offset = round(边中点方向 × 邻居中心距)，邻居中心距从多边形边中点到中心的距离 × 2 得到。
- 所有逻辑统一遍历 N 个顶点/边，**不区分五边形/六边形**，不出现 N 具体数值的分支判定。
- **不使用** H/S/k 长宽比代数、circumradius 比例常数、apothem/cos 换算。

### 数据模型重构（direction → 动态方向）
当前 `direction`（0-5 固定编号）**完全移除**，改为基于世界地块真实顶点角度的动态方向：

- **世界地块几何读取**（Odyssey 版 WorldGrid API）：
  - `grid.GetMaxTileNeighborCountEver(tile)` → 顶点数 N
  - `grid.GetTileVertices(tile, outVerts)` → N 个顶点的世界球面坐标（环绕顺序）
  - `grid.GetTileNeighbors(tile, outNeighbors)` → 邻居列表，**邻居 j 对应顶点 j→j+1 的边**
  - `WorldRendererUtility.GetTangentsToPlanet(center, out north, out east)` → 切平面坐标系
- **顶点方向**：`(verts[i]-center)` 投影到切平面 `(Dot(·,east), Dot(·,north))`，归一化。
- **NeighborLink 结构变更**：`direction`(int) 移除，改存 `edgeAngle`(float 弧度) 和 `worldTile`(int)。offset 为 IntVec3（整数）。

### 虚空地形
新增 `RimExodus_Void` TerrainDef（参考 VMF `VMF_ImpassableFloor` + 官方 `Space`）：
- `passability=Impassable`（阻止寻路+跳跃落点，经 `JumpUtility.ValidJumpTarget→WalkableBy` 验证）
- `dontRender=true`（透明）、`fertility=0`（不生植物）
- `changeable=false`+`layerable=false`（不可覆盖）
- **不设 `forcePassableByFlyingPawns`**（保持默认 false，堵飞行 PathGrid 漏洞）
- 空 `affordances`（不可建造）
- `filthAcceptanceMask=None`、`holdSnowOrSand=false`、`avoidWander=true`

## 实现步骤（7 步）

### 步骤 1：新增 RimExodus_Void 地形 Def
**文件**：`1.6/Defs/TerrainDefs/VoidTerrain.xml`（新建）
定义 `RimExodus_Void` TerrainDef，字段如上总纲所述。

### 步骤 2：新增世界地块几何工具 `WorldTileGeometry.cs`
**文件**：`Source/WorldTileGeometry.cs`（新建）

职责：从世界地块读取真实几何，计算顶点方向。核心 API：

```
// 计算地块 tile 每个【顶点】的方向单位向量（x=东, z=北）。
// 返回 N 个方向，用于构造多边形顶点（center + 0.5S × dir）。
static List<Vector2> ComputeVertexDirections(int worldTile)
```

实现：
1. `grid.GetTileVertices(worldTile, verts)` 取 N 个顶点。
2. `center = grid.GetTileCenter(worldTile)`。
3. `GetTangentsToPlanet(center, out north, out east)`。
4. 对每个 i：`(verts[i]-center)` 投影 `(Dot(·,east), Dot(·,north))`，归一化。

边方向（邻居方向，传送点/offset 用）可由顶点方向推导：边 j 连接顶点 j 和 j+1，边中点方向 = normalize((dir_j + dir_{j+1})/2)。或直接从世界地块边中点投影（与顶点方向共用切平面）。

### 步骤 3：重构邻居表数据模型（direction → 动态方向）

### 步骤 4：重构偏移与裁切核心 `SeamlessTileManager.cs`
**文件**：`Source/SeamlessTileManager.cs`

**ComputeHostOffset 移除**，替换为基于多边形边中点的直接计算：

```
// 从 sourceWorldTile 到 newWorldTile，算新地块相对源地块的偏移。
// 1. 构造源地块多边形顶点：verts[i] = center + 0.5S × vertexDir_i。
// 2. 查 grid.GetTileNeighbors(sourceWorldTile) 找到 newWorldTile 是第 j 个邻居。
// 3. 边 j 的两端 = 顶点 j 和顶点 j+1，边中点 midJ = (verts[j]+verts[j+1])/2。
//    邻居中心方向 = normalize(midJ - center)，邻居中心距 = 2 × |midJ - center|。
// 4. offset = round(邻居中心方向 × 邻居中心距) = round(2 × (midJ - center))。
IntVec3 ComputeNeighborOffset(int sourceWorldTile, int newWorldTile, Map sourceMap)
```

注意：offset 直接 = `round(2 × (边中点 - 中心))`，无需 apothem/cos 换算。边中点已编码了方向和距离。

**GenerateTileMap 签名变更**：
- 新：`GenerateTileMap(int sourceWorldTile, int newWorldTile, IntVec3 mapSize)`
- 内部：`mapParent.worldTile = newWorldTile`；offset 由 `ComputeNeighborOffset` 算。
- overlapBand 概念移除。

**自动生成**：`TryAutoGenerateNorth` → `TryAutoGenerateFirstNeighbor`。

**RegisterNeighborBidirectional 变更**：
- 不用 `OppositeDirection`；反向登记在新地块查"指向源地块的边"（用 newWorldTile 反查其世界邻居中等于 sourceWorldTile 的边角度）。

### 步骤 5：重构 GenStep 铺设多边形虚空（凸多边形扫描线填充）★
**文件**：`Source/GenStep_SeamlessTile.cs`

核心逻辑：**用凸多边形扫描线填充高效铺设可通行区域与虚空**。

#### 5.1 构造多边形顶点（内切圆模型）
```
1. worldTile = map.Parent.worldTile。
2. vertexDirs = WorldTileGeometry.ComputeVertexDirections(worldTile)（N 个顶点方向）。
3. N = vertexDirs.Count，S = map.Size.x。
4. center = (S/2, S/2)。
5. 多边形顶点 verts[j] = center + 0.5S × vertexDirs[j]。
   （直接顶点方向 × 0.5S，无需算交点/apothem）
```

#### 5.2 凸多边形扫描线填充
利用凸性：每行（z 固定）与多边形边界**最多 2 交点**，定义填充区间。

```
for z in [0, S-1]:
  scanY = z + 0.5  // 格中心
  xs = []
  for each edge (v0, v1) in verts（环绕）:
    if (v0.z <= scanY) != (v1.z <= scanY):  // 边跨越该行
      t = (scanY - v0.z) / (v1.z - v0.z)
      x = v0.x + t * (v1.x - v0.x)
      xs.add(x)
  sort(xs)
  if xs.count >= 2:
    xLeft = xs[0], xRight = xs[xs.count-1]
    for x in [0, S-1]:
      cellX = x + 0.5
      铺 (xLeft <= cellX <= xRight) ? grass : void
  else: 全行铺 void
```

#### 5.3 锚点地图 A 的处理
家园 A 是原生 Map，不经过 `GenStep_SeamlessTile`。需 MapComponent 补铺虚空：
- `SeamlessTileManager.MapGenerated` 或首次生成邻居前，按 A 的 worldTile 用 5.1+5.2 扫描线算法补铺（覆盖原版地形）。
- 用标志防重复。
- A 的 worldTile 从 `map.Tile` 获取。

### 步骤 6：重构传送点划线放置 `SeamlessTileManager.cs`
**文件**：`Source/SeamlessTileManager.cs`

**EnumerateSeamCells 重写**（Bresenham 划线，沿多边形边）：
对每条边 j（对应邻居 j），沿多边形边（顶点 j → 顶点 j+1）枚举传送点候选格：

```
// 多边形边 j 连接顶点 j 和顶点 j+1。
// 用 Bresenham 从 verts[j] 到 verts[j+1] 画线，线经过的每个格放候选。
IEnumerable<IntVec3> EnumerateSeamCellsForEdge(int edgeIdx, List<Vector2> polyVerts, int S)
```

实现：
1. 边 j 两端 = 多边形顶点 j 和顶点 j+1。
2. Bresenham 从一端到另一端画线，线经过的每个格放候选。
3. **四格交点补偿**：线恰好经过四格交点时，在交点任一侧补一个（防斜向空缺）。

**PlaceEnterSpots 调整**：
- 对每个邻居（每条边），调 `EnumerateSeamCellsForEdge` 枚举候选格。
- sourceCell 算 localCell = sourceCell - offset（offset 来自邻居表）。
- 校验 localCell.InBounds + Walkable（虚空不 Walkable，传送点只铺可通行侧）。
- 生成传送点对（逻辑不变）。
- 传送点铺在边界当前地块这一侧，确保站上去触发转移。

## 关键风险与验证点

1. **锚点地图 A 的 worldTile 获取**：A 是原生 Map，需确认 `map.Tile` 可用。
2. **A 的虚空铺设法**：原生 GenStep 不走 RimExodus，需 MapComponent 补铺（一次性，防重复 SetTerrain）。
3. **WorldRendererUtility.GetTangentsToPlanet 可用性**：确认 1.6 存在且语义正确（north/east）。
4. **offset 凑整对称性**：A→B 与 B→A offset 须 = -(A→B offset)。两边各自从自己的多边形边中点算，理论上对称，但凑整可能 ±1 误差。需验证或登记时强制对称。
5. **存档不兼容**：direction 移除，旧存档无法加载（原型阶段可接受）。
6. **虚空环带宽度**：顶点距 0.5S 时多边形到地图角的虚空距离需检查是否足够抵御跳跃（PawnFlyer 3.9 格半径）。角部虚空区 ≈ 0.5S·(√2-1) 需算（S=250 时约 52 格，充足）。
7. **凸多边形顶点退化**：世界地块细分边界处顶点角度可能不均匀，但 0.5S 统一尺度后多边形仍为凸（顶点方向忠实）。扫描线仍适用。
8. **编译验证**：每步后 `dotnet build Source/RimExodus.csproj -c Debug`，0 错误 0 警告。
