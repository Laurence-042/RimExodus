# RimExodus 第二阶段三问题修复计划

## 问题 1：选中跨图 Pawn 后相机应保持相对偏移而非聚焦 Pawn

**根因**：原生 `Selector.SelectInternal`（`references/.../RimWorld/Selector.cs:379-384`）选中跨图 Thing 时，先 `Current.Game.CurrentMap = map`（行 381），再 `Find.CameraDriver.JumpToCurrentMapLoc(thing.PositionHeld)`（行 384）硬跳到 pawn 上。当前 mod 未 patch 此处（见 `doc/第二阶段` 已知限制 1）。

**方案**：新增 `Patches_Selector.cs` 中对 `Selector.SelectInternal` 的 Postfix（复用 `SeamlessCameraFocus` 已有的无感算法）。因为 `SelectInternal` 行 384 跳完 pawn 后我们无法"撤销"，但可以在 Postfix 里重新覆盖相机位置。

- **关键时机问题**：无感算法需要在切图之前记录相机位置（`camPos = Find.CameraDriver.MapPosition`），但 Postfix 在原方法执行完之后才运行（此时已切图）。所以需要 **Prefix + Postfix 配合**：
  - Prefix：检测即将选中的 `obj` 是 Thing 且 `thing.MapHeld != Find.CurrentMap` 且两者是直接邻居（`SeamlessTileGraph.AreNeighbors`）→ 记录切图前 `camPos` 和 `offset` 到静态字段。原方法照常执行（不 return false）。
  - Postfix：若 Prefix 记录了数据（说明刚发生跨图切换），用 `Find.CameraDriver.JumpToCurrentMapLoc(camPos - offset)` 覆盖行 384 的聚焦。
- **复用无感算法**：把 `SeamlessCameraFocus` 行 48-59 的 `camPos → offset → JumpToCurrentMapLoc(camPos - offset)` 逻辑抽成内部可复用方法，或直接在 Postfix 里内联（offset 用 `SeamlessTileGraph.GetAllNeighbors(currentMap)` 查，逻辑同 `SeamlessCameraFocus.FindNeighborOffset`，可把后者提为 internal/public 共用）。
- **边界**：若选中目标不是直接邻居（offset 查不到），不记录、不覆盖，保持原生聚焦行为。
- **现有文件改动**：
  - `Source/Patches_Selector.cs`：新增 `SelectInternal` 的 Prefix+Postfix（与现有 `SelectableObjectsUnderMouse` patch 共存于同一文件）。
  - `Source/SeamlessCameraFocus.cs`：把 `FindNeighborOffset` 改为 `internal`（或提取公共静态方法）供 Selector patch 复用。

## 问题 2：传送点载体从 Building 改为 Ethereal（ThingWithComps）

**根因**：当前 `SeamlessEnterSpot.xml` 是 `Building` category，可被攻击/占领/拆除，且 `isEdifice` 默认 true 会与岩山墙冲突；`PlaceEnterSpots` 第 263/270 行的 `Walkable` 过滤主动跳过岩山/深水格。

**方案（用户已选 Ethereal）**：
- **改 `1.6/Defs/ThingDefs/SeamlessEnterSpot.xml`**：
  - `thingClass` 从 `Building` 改为 `ThingWithComps`。
  - `category` 从 `Building` 改为 `Ethereal`。
  - 保留 `passability=Standable`、`pathCost=0`、`altitudeLayer=FloorEmplacement`、`size=(1,1)`、`comps`。
  - 加 `destroyable=false`、`useHitPoints=false`、`selectable=false`（隐藏，避免玩家误选）。
  - 删除 `graphicData`（或保留但设为透明/极简，因为 selectable=false 后不需可见图标——原型阶段建议保留一个极淡的标记方便调试，或删掉）。
  - 验证结论：Ethereal 进 `listerThings`，`ThingsOfDef` 照常工作（`ListerThings.cs:298 EverListable` 对非 Mote/非 Projectile 返回 true）；不进 edificeGrid、不被攻击（不实现 IAttackTarget）、不被占领（无 building.claimable）、不阻挡寻路（passability=Standable）。
- **改 `Source/SeamlessTileManager.cs` PlaceEnterSpots**：
  - 放宽放置过滤：第 263 行 `!sourceCell.Walkable(map)` 和第 270 行 `!localCell.Walkable(interiorMap)` —— 这两个过滤会跳过岩山/深水。改为去掉 `Walkable` 检查（Ethereal 不占 edifice，可与任何地形共存）。
  - **但保留到达端可站立校验**：`SeamlessMapTransfer.TryTransferPawn` 第 51 行 `arrivalCell.Walkable(arrivalMap)` 仍要求 pawn 落地格可通行。所以源端可放任意地形，但若对端不可站立，传送会失败（这是合理的——pawn 无法落到深水/岩山里）。因此建议：**两端都放宽放置，但成对放置时若对端 Walkable 为 false 则跳过该对**（避免放一个永远无法使用的传送点对）。即：去掉源端 Walkable 过滤，保留对端 Walkable 作为"传送可行性"过滤（而非"放置可行性"过滤）。
  - 改失败回退：第 293-294 行 `Destroy()` 改为 `DeSpawn()`。因为 `destroyable=false` 后 `Thing.Destroy`（`Thing.cs:1045`）会拒绝执行，导致部分生成失败时悬空残留。`DeSpawn` 不检查 destroyable。
- **消费者零改动**：`SeamlessMapTransferTrigger.cs`、`SeamlessCrossMapOrders.cs`、`SeamlessMapTransfer.cs` 都用 `ThingsOfDef` + `TryGetComp` + `Position`/`Map`/`Spawned`，与 category 无关，Ethereal 完全兼容。
- **`CompSeamlessTileEnterSpot.cs` 无需改动**。

## 问题 3：传送反弹 bug（pawn 级锁 + 离开接缝带才解锁）

**根因**：传送点满铺接缝，pawn 被传到 B_x 后，续程 Goto 沿接缝前进，离开 B_x 即解锁（`PurgeInvalidArrivalLocks` 第 149 行判定 `pawn.Position != arrivalSpot.Position`），踩上相邻 B_{x+1}（无锁）又被传回。锁的是"特定 spot"而非"pawn 整体"。

**方案（用户已选：pawn 级锁 + 离开接缝带解锁）**：把锁的语义从"锁特定 spot"升级为"锁 pawn 的跨图到达状态"，pawn 只要还在本图接缝带上就保持锁，离开整条接缝带才解锁。

- **改 `Source/SeamlessMapTransferTrigger.cs`**：
  - `arrivalLocks` 字段类型从 `Dictionary<Pawn, Thing>` 改为 `Dictionary<Pawn, bool>`（或 `HashSet<Pawn>`，表示"该 pawn 处于跨图到达锁状态"）。
  - `RecordArrival(pawn, arrivalSpot)`：参数简化为只记 pawn（不再记 spot），设 `arrivalLocks[pawn] = true`。移除对 `pawn.Position == arrivalSpot.Position` 的校验（转移后必然成立）。
  - `IsArrivalLocked(pawn, thing)` → 改名 `IsArrivalLocked(Pawn pawn)`：返回 `arrivalLocks.ContainsKey(pawn)`。不再比较特定 spot——pawn 在冷却/锁状态时，踩**任何**接缝 spot 都被锁住。
  - `CheckLocalEnterSpots` 第 94-95 行调用处：`IsArrivalLocked(pawn, thing)` 改为 `IsArrivalLocked(pawn)`。
  - `PurgeInvalidArrivalLocks`：清除条件从"pawn 离开特定 spot"改为"pawn 不再站在本图任何接缝传送点上"。实现：遍历 `arrivalLocks` 中每个 pawn，检查其当前 `pawn.Position` 是否在 `map.listerThings.ThingsOfDef(enterSpotDef)` 的任一 spot 位置上；若不在任何接缝 spot 上，则该 pawn 已离开接缝带，移除锁。
    - **性能**：已锁 pawn 通常 1-3 个（刚跨图的），每 tick 检查它们是否还在接缝带，O(lockedPawns × seamSpots)。可优化为缓存接缝 spot 的坐标集合，但原型阶段直接遍历即可（接缝 spot 数 ≈ 接缝长度 ≈ 96，lockedPawns ≈ 1-3，每 tick ≈ 300 次比较，可忽略）。
    - **注意**：`PurgeInvalidArrivalLocks` 当前每 tick 调用（第 39 行），需在内部用 `DefDatabase.GetNamedSilentFail` 取 enterSpotDef（或缓存为字段）。若 enterSpotDef 为 null 直接 return。
    - 同步清除 pawn 失效条件：pawn destroyed/dead/despawned/不在本图 → 移除锁（保留现有第 147-149 行的失效判定，去掉 spot 相关判定）。
  - `ExposeData` 第 27 行：`Scribe_Collections.Look` 的 value LookMode 从 `LookMode.Reference` 改为 `LookMode.Value`（bool）。

## 风险与边界

- **问题1**：Postfix 覆盖相机发生在行 384 之后，原方法可能还触发了 `SoundDefOf.MapSelected.PlayOneShotOnCamera()`（行 382）和 `SelectionDrawer.Notify_Selected`（行 392）——这些不影响相机位置，无需处理。唯一需确认：`JumpToCurrentMapLoc` 在 Postfix 调用时是否已稳定（它是同步设 rootPos，无异步，安全）。
- **问题2**：Ethereal 的 `selectable=false` 后，`SeamlessGenUI.ThingsUnderMouse`/`SelectableObjects`（`Patches_Selector.cs:40-47` 的 TargetingParameters `mustBeSelectable=true`）不会再选中传送点——这是期望的（传送点本就不该被玩家选中）。但需确认这不影响 `CompSeamlessTileEnterSpot` 的 `ThingsOfDef` 查询（不影响，selectable 只管鼠标选中，不管 listerThings 索引）。
- **问题3**：若 pawn 被传到对端后续程 Goto 因某种原因失败（pawn 卡在接缝 spot 上不动），锁会一直保持——这是安全的（锁着只是不再触发传送，pawn 不会被卡死，玩家可手动指令）。`ContinueCrossMapMove` 在转移成功后立即调用，正常情况 pawn 会立刻开始移动离开接缝。
